- grpaphics to control size of objects, ui elements, sprites, etc.

## Hadamard Product - Multiply Vector by another Vector / An element wise multiplication between Vectors

So it has three namings like you saw.

Also called a **`Hadamard Product`**; also techically written like this with a circle as an operation:
$$
\vec{v}_{1} \circ \vec{v}_{2}
$$

In a game dev, you will se nobody using that symbol, or that naming, they will use `star`(`*`) and call it `element-wise multiplication`
$$
\vec{v}_{1} * \vec{v}_{2}
$$


Example for 2D

$$
\vec{a} \circ \vec{b} = (a.x * b.x , a.y * b.y)
$$


Example for 3D

$$
\vec{a} \circ \vec{b} = (a.x * b.x , a.y * b.y, a.z * b.z)
$$


### Hadamard product is less common operation and it might not be what you want to do anyway

For example in unity there are operators `+` and `-` that are used for addition and subtraction of Vectors, but there is operator also `*` and it should be used only to multiply Vector by sclar value.

In Three.js, they have `multiply` and `multiplyScalar` methods so it is more explicit


## Multiplication by Scalar Value vs Hadamard Product of Two Vectors

by Scalar Value
- scales magnitude only
- direction-line is perserved
- sense (heading) is perserved; if you didn't scale with negative scalar

# Example: Having vector `A`; scale it to create new vector B; normalize them; compare normalized vector `A` with normalized vector `B`

```ts
A = (x,y)
// scaling
B = 2 * A = (2 * x , 2 * y) 

normalized(A) === normalized(B)

// same because at the end they both have same magnitude and direction and sense
```

Vector scaling lets you

2 ways
- scaling by sclar
	- using single number
