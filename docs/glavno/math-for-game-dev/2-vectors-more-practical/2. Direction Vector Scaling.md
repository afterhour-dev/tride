## Normalization is scaling Vector by inveres of its length/magnitude

To be honest we explained it there very well; and also why is performance wise better to use inversion once, and just reuse inversion to scale every element, rather than division multiple times; : [[1. Normalized Directioan Vectors#Normalization is **Vector Scaling** by inverse of its magnitude]]

Normalization is dividing `Direaction Vector` by its `length/magnitude`, but what we could do is to **multiply vector by inverse of magnitude**:

```ts
UnitVector = DirectinVector * (1 / magnitude)

// instead of doing:         UnitVector = DirectionVector / magnitude
```

Actually, what we did is scaling of vector. And this is done element wise. And what we are doing is scaling by scalar value, since inverse of magnitude is scalar. 

## Scaling is element-wise multiplying Vector by Scalar 

Result is new vector 
- with different magnitude
- same direction line (action line)
- same or different sense (heading) depending of the scalar value is negative or positive

it is used so much in game development:
- Object position + normalized direction ⨯ scalar speed; can allow object to move fast/slow, while preserving original heading (sense)
- keeping the speed separate from direction allows you to increase/decrease as game-play requires

Might be seen in:
- character movement
- graphics to control size of objects, UI elements, sprites, etc.

## Hadamard Product - Multiply Vector by another Vector - An element wise multiplication between Vectors

So it has multiple names like you saw.
- Hadamard product
- Element-wise multiplication between vectors
 
 Also technically written like this with a circle as an operation:
$$
\vec{v}_{1} \circ \vec{v}_{2}
$$

In a game dev, you will see nobody using that symbol, or that naming, they will use `star (*)` and call it `element-wise multiplication`
$$
\vec{v}_{1} * \vec{v}_{2}
$$


Example for 2D

$$
\vec{a} \circ \vec{b} = (a.x * b.x , a.y * b.y)
$$


Example for 3D

$$
\vec{a} \circ \vec{b} = (a.x * b.x , a.y * b.y, a.z * b.z)
$$


### Hadamard product is less common operation and it might not be what you want to do anyway

For example in unity there are operators `+` and `-` that are used for addition and subtraction of Vectors, but there is operator also `*` and it should be used only to multiply Vector by scalar value.

In Three.js, they have `multiply` and `multiplyScalar` methods so it is more explicit.


## Multiplication by Scalar Value vs Hadamard Product of Two Vectors

by Scalar Value
- scales magnitude only
- direction-line is preserved
- sense (heading) is preserved; if you didn't scale with negative scalar

# Example: Having vector `A`; scale it to create new vector `B`; normalize them; compare normalized vector `A` with normalized vector `B`

```ts
A = (x,y)
// scaling
B = 2 * A = (2 * x , 2 * y) 

normalized(A) === normalized(B)

// same because at the end they both have same magnitude and direction and sense

// but you can confirm it

magnitudeA = sqrt(x*x + y*y)

magnitudeB = sqrt(2x * 2x + 2y * 2y)

normalizedA = (x,y) / magnitudeA = (x/magnitudaA, y/magnitudeA);

normalizedB = (2x, 2y) / magnitudeB = (2x/magnitudeB, 2y/magnitudeB)

// let's say    x = 3  y = 4

magntudeA = sqrt(3 * 3 + 4 * 4) = 5
magntudeB = sqrt(2*3 * 2*3 +  2*4 * 2*4) = 10

normalizedA = (3,4) * (1/5) = (3/5, 4/5) = (0.6, 0.8)
normalizedB = (2*3,2*4) * (1/10) = (6/10, 8/10) = (0.6, 0.8)

normalizedA === normalizedB
```

# Recap

Vector scaling lets you
- to adjust things like object sizes
- do deformations (in shaders)
- perform movement calculations

2 ways
- scaling by sclar
	- using single number
	- scales magnitude, preserves direction line (action line)
	- sense (heading) would not be preserved if scaling by negative number
- scaling by components (Element Wise/Hadamard Product)
	- scaling along each axis differently
	- potentially not uniform (if vector we are scaling by doesn't have equal elements); means magnitude and direction potentially wouldn't be preserved
