# what LERP is exactly

So let's examine what LERP is exactly. Let's take a normal number line like we've been looking at before, and we'll make two points, a and b, some distance apart from each other.

It doesn't matter really where they are or what their exact coordinates are for the purposes of just explaining what the LERB function does. Now, if I wanted to find the halfway point between A and B, it's not super difficult. Without using any math whatsoever, you can roughly glance at the screen and you know exactly where it is, it's right in the middle between those two points. 

![[2026-10-05_09-28.png]]

Using actual math we'll break out our linear algebra and it's one half of `A` plus one half of `B`. 

And we wanted slightly different values like one quarter of the way between `A` and `B`.

Again visually this is a trivial problem to solve. 
And using linear algebra that's three quarters of `A` plus one quarter of `B`.

And of course the reverse is true. 

If you want a value that's three quarters of the way between `A` and `B`, then that's one quarter of `A` plus three quarters of `B`.

![[2026-10-05_09-30.png]]

What you've done is, in essence, you've drawn a line between those two points, those two values, and you are basically just sliding from value `A` to value `B`.

![[2026-10-05_10-09.png]]

You're linearly interpolating between the two points.
Interpolation being a method for estimating unknown values between two known values.
Or in other words, figuring out the value of an intermediate value between two endpoints.
And the linear part is somewhat self explanatory.
The interpolation from one value to the other is being done on a straight line. 

So what ends up happening here is that you'll quickly realize this generalizes to a formula.

![[2026-10-05_10-11.png]]

You've got `b` times `t` plus `a` times (`1` minus `t`)

```c
b * t + a - a * t
```
, or more simply.
![[2026-10-05_10-12.png]]

In fact we can view this through the lens of linear algebra, so let's take `A` as a position vector and we'll take the direction from `A` to `B` as another vector, we'll call it `BA`. So `BA` is equal to `B` minus `A`, and so linear interpolation is simply `A` plus `t` times `BA`.

![[2026-10-05_10-15.png]]

And you'll see that using that parameter `t` as it ranges between `0` and `1` you get a smooth blend of the two values, starting with `A` or `t` equals `0` and ending with `B` or `t` equals `1`.

# Inverse Lerp or Linear Step

Now sometimes it's necessary to do the inverse. 

That is, given a value somewhere on this number line, how far as a percentage between 0 and 1 is some point P between A and B?

![[2026-10-05_12-06.png]]

This is what's called an `inverse LERP`
Although you could conceivably call it a `linear step` because there are other step functions that we'll run into in later sections on shaping functions, and calling it `linear step` makes more sense in that context.

But for now, let's just stick with the common name, `inverse LERP`. 

This is the inverse LERP function as shown right here in the Unity docs.

![[2026-10-05_12-02.png]]

This isn't a standard function though, you won't find it everywhere. So if it's not available in your game development environment, it's easy enough to implement anyway. 

As I explained earlier, sometimes it's called linear step as well, and in fact, this name makes way more sense than inverse LERP.

So given a number line and two points `A` and `B` and a point `P` somewhere on this number line, what value of `t` do you need so that LERP of `A`, `B`, and `t` is equal to `P`?

![[2026-10-05_12-05.png]]

Computing this manually is actually really simple. The definition is normally something like this.

![[2026-10-05_12-12.png]]

So you've got float inverse LERP, you've got a min value, you've got a max value, and you've got the value that you're interested in.

And then you calculate your value as the (value minus the min value) divided by the (max value minus the min value).

Then you clamp that into the range zero to one, and then you return it.


So we'll take a quick look at this implementation. 
- The first line basically figures out the percentage value `t`
- and then there is the second line which has a clamp function. Now if you're not familiar with clamp, it does what you might expect from the name. It clamps a value to a specific range, in this case zero and one.

> if you forgot what clamp does it is this:
```typescript
const clamp = (num) => Math.min(Math.max(num, 0), 1);

console.log(clamp01(0.5)); // Output: 0.5 (Inside range)
console.log(clamp01(-2.5)); // Output: 0 (Clamped to min)
console.log(clamp01(1.8)); // Output: 1 (Clamped to max)
```

- Meaning that if the value was less than zero before, the function clamps it to zero.
- And if the value passed in is greater than one, it gets clamped to one. 
- The function will never return a value less than zero or greater than one.

So this is to basically force the returned value to be in the range 0 to 1. Otherwise LERP is **extrapolating** at that point, **not interpolating**.

Let's do a quick example. 
So given `A` equals `0`, `B` equals `10`, and `P` equals `5`, what value of `t` works so that `P` equals LERP of `A`, `B`, and `t`?

And we know immediately from just looking at this that `P` is exactly halfway, and so in theory we should end up with `t` = `0.5`. 
So let's do the calculation itself and figure out whether or not it gives the same answer.

![[2026-10-05_12-36.png]]

This is of course clamped to the range 0 and 1, but it's already between 0 and 1 so nothing happens.

So now you have a mechanism for telling as a percentage how far between two reference points something is.

And this could be used: 
- to track your progress between two reference points in the level
- using a start and end distance to scale an object's properties. 
- In graphics, you could use the distance to the camera to decide on level of detail
- inside game logic, you could decide to wake up entities or enemies or whatever you want based on distance.

![[2026-10-05_12-39.png]]

The uses here are pretty much endless. 

# remap

Lastly, let's take a quick look at `remap` because this function works really well with `LERP` and `inverse LERP` and is often presented alongside them.

Again, this may or may not be available in your game environment. If it isn't, it's a trivial function to implement.

![[2026-10-05_12-47.png]]

What this does is it takes a value that's within a range and remaps it to another value in another range, which is a bit of a handful to understand so let's visualize that.

Here's the number line and here are two points `A` and `B`, and we'll draw a second number line underneath. Same values, but instead of `A` and `B` we'll have a different range here, `C` and `D`.

![[2026-10-05_12-49.png]]

Now if you have a point between `A` and `B`, what remap does is it takes that point `P` between `A` and `B`, it figures out where between `C` and `D` it would fall and returns a new point `P'` (`P` prime).

![[2026-10-05_12-51.png]]

You can think of this as a sort of convenience function that combines multiple calls to `LERP` and `inverse LERP` for you.

So given points `A` and `B` and a point between them `P` and a new range `C` and `D`, you'll get some new point, `P'`.

![[2026-10-05_12-52.png]]

So `P'` is equal to a `remap` of A, B, C, D, P.

So what you're actually doing when you do a `remap` is you're doing an `inverse LERP` first and then you're doing a `LERP` again afterwards.

![[2026-10-05_13-02.png]]

So if `P'` is equal to a `remap` of `A`,`B`, `C`, `D`, and `P`,
- we'll make an intermediate value of `t`, so t is equal to the `inverse LERP` of `A`, `B`, and `P`. 
- Then we use `t` to generate a new value between `C` and `D`, so `P'` is equal to `LERP` of `C`, `D`, and `t`. 

And that's all remap does. Seriously, that's it.

It's a quick convenience function that when you want to remap a value from one range to another, it's really handy for that.

And this is again quite useful in a number of situations. 
Let's say that you've got an area effect, like let's say it's healing from a spell.
You could easily use remap in this case to trivially map distance from the center of the spell to health

![[2026-10-05_13-08.png]]

So we could say the healing factor is equal to a remap from zero to 10, that's the distance, and then we'll say 100 and distance or something to that effect. And all that means is that really close to this origin or center of the spell, you get, let's say, a 100 health and then it falls off to zero.

As I said, the implementation is really easy because, as we just saw, it's a combo of inverse `LERP` and `LERP` again.

So officially the function would look something like this.

![[2026-10-05_13-10.png]]

And in this case, `inMin` and `inMax` refer to `A` and `B` from our examples, while `outMin` and `outMax` refer to `C` and `D`. And `currentValue` refers to of course `P`.

Let's do a quick example to hammer this point home a bit.

So given a range, `A = 0`, `B = 10`, and we'll have a second range here, `C =  55` and `D =  95`
![[2026-10-05_13-23.png]]

Now let's try out remapping some points. So if `P` equals zero, then `P'`  is equal to a `remap` of `A`, `B`, `C`, and `D` and `0`.

So `t` equals `inverse LERP` of `A`, `B`, and 0.
`t` is equal to 0.
![[2026-10-05_13-25.png]]

That would mean that `P'` is equal to a `LERP` of `C`, `D`, and `t`. 
Which is a `LERP` of `55`, `95`, and `0`, which is equal to `55`.
![[2026-10-05_13-26.png]]

Let's try in the middle now. 

So `P` = `5`, And `P'` is equal to a `remap` of `A`, `B`, `C` and `D` and 5.
So `t` is equal to the `inverse LERP` of `A`, `B` and 5, and it should end up with `0.5`.

Then `P'` is equal to a `LERP` of `C`, `D` and `0.5`, and that's a `LERP` of `55`,  95,  `0.5`, which is of course `75`.

![[2026-10-05_13-29.png]]

So what's this useful for?

Well, it happens quite a bit in games where you have some value and based on time or on distance or whatever, it has a secondary effect.

Let's say that you're in a game and you have an explosion that goes off nearby, and you need to figure out how much damage each player takes.

You could easily do this with a remap function. 

So we'll say that the explosion damage is 500 health points right up until the 10 meter mark, and then it drops down to zero at 15 meters.

So given a distance `d`, how much damage should they receive?

Well, the damage is equal to a `remap` from `10 to 20`, and `500 to 0`, and `d`. And that's it.

Figuring out your damage is a one line call now. Really simple.

# Recap

So just a quick recap. We covered three functions, `LERP`, `inverse LERP`, and `remap`.

`LERP`, sometimes referred to as `mix`, takes two values and a scalar `t` value which ranges from `0` to `1` and returns a linear interpolation between the two reference values.

![[2026-10-05_13-34.png]]


`Inverse LERP` does the inverse of LERP, hence the name. It takes two values specifying the range, and a third value specifying a value in that range, and returns a scalar `t` value, which if it were used in the LERP function would yield that third value again.

![[2026-10-05_13-36.png]]

And `remap` takes an input range, an output range and a value and returns a new value in the output range.

![[2026-10-05_13-36_1.png]]

Hopefully that was all clear.
