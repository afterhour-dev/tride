# What is safe to use with LERP

You can use it safely. 

The 1st example is obviously positions. The relationship between points and space is completely linear. Cartesian space is linear.
It's a coordinate system that specifies each point in space by a set of numerical coordinates that are just distances along each axis.

This is linear and completely safe to use with LERT.

So given 2 points in space, `A` = `(0,0,0)` and `B` = `(10, 20, 30)`, you can always calculate some intermediate value. So `position` equals `LERP` of `A`, `B`, and `t` and that's fine.

There will be no issues there whatsoever.

Size is another property that you can safely interpolate without issues.

# Getting the most out of LERP

So now let's move on to the types of values that you may run into issues with when using LERP. 

Now to reiterate, LERP assumes a linear relationship between points in order to do the interpolation.

![[2026-10-06_12-04.png]]

If that assumption isn't valid, the results may end up subtly or not subtly breaking.

To start, let's talk about some things that are absolutely fine with LERP but could also be greatly improved on if you decide that normal LERP results aren't good enough.

I said that color values can be interpolated just fine, and they can be. But you can improve on the results by 1st transforming the colors into something other than RGB. There are other color spaces in the same way that you can represent points in 2 d in Cartesian coordinates, or you can represent them with polar coordinates.

![[2026-10-06_12-06.png]]

You can transform colors into other spaces, do your LERP there, and then transform back for potentially better results.

Look at the results of these 2 LERPs. So the top one is a LERP in standard RGB color space, while the bottom one uses a color space called OkLab. Notice how the RGB color space goes through a slightly reddish but purplish near the middle, which is kinda weird, but the OkLab gradient doesn't suffer from that.

![[2026-10-06_12-06_1.png]]

We'll be covering color interpolation in a later section.

But in the same vein, brightness can be better dealt with for perceptually better results by potentially using another color space.

Scale and zoom, as we mentioned, these can be used with LERP directly. But for perceptually better results, you may consider transforming the points into log space.
We'll be covering this again in a later section.

![[2026-10-06_12-08.png]]

And along with zoom, things like velocity and volume are again possibly better done in log space.This helps to create a more natural smoother transition.


# Challenging interpolations

Now let's get into the values that just outright break and shouldn't ever be used or at the very least be used with extreme caution.

![[2026-10-06_12-10.png]]

Let's start with unit vectors. They're easy to see why they can't be interpolated easily.

If you have 2 unit vectors and they're reasonably close to each other in direction, you can sort of interpolate between them and the results can range from decent to kind of broken, but possibly still okay.

When you interpolate between 2 vectors, the result can be kind of stunted or shorter, so you lose that unit vector property.
If you renormalize after the interpolation, you can bring things back to mostly okay, but this can still break under the right circumstances.

If you have 2 vectors at 180 degrees from each other, there is literally no way to lerp these and get the right answer. In fact, you end up with 1 of 3 possibilities. 
- You get the 1st vector
- get a 0 vector 
- or you get the 2nd vector.
But that's it. 

![[2026-10-06_12-22.png]]

So in some cases, interpolating vectors can completely break. This is an example of use with extreme caution. 

**It's still used quite a bit actually.** 
- In fact, shaders interpolate normals across the triangles using this exact method with the understanding that this can break and so you should tessellate your geometry accordingly.

Rotations, specifically:
- Euler angles
- rotation matrices 
**they can't be LERPed.**

This will just end up being a mess. In fact, in the section on rotations you can watch the interpolation of the Euler angles and rotation matrices and see that even with attempts to re normalize the basis vectors of the matrix you still get a broken rotation. 

![[fourth.gif]]

You might, with extremely small changes, be able to interpolate between Euler angles or matrices, but the circumstances would have to be very right in order for this to work.

As I said, you can still get away with interpolating these types of values even if it's not strictly correct to do so.

Sometimes the error on interpolation is small enough that it's still good enough to use. A lot of times in games, it's about whether or not it makes an impact on the end user, regardless of whether or not it's technically correct. And if they don't notice because the error is so small, then it may be totally fine to go ahead and LERP it.

![[2026-10-06_12-39.png]]

Basically, sometimes it's a problem and sometimes it isn't.
What I want you to be is aware of what you're trying to interpolate and to be able to reason about the nature of that value, about whether or not that value can be safely interpolated and if it can't, whether or not the error is small enough to ignore or not.
