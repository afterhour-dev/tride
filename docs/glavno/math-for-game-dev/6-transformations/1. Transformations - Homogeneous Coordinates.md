# How do you represent translation

We covered rotation and scale but we didn't translation; but we didn't for a good reason.

![[2026-09-25_14-25.png]]

You can't do translation of 2D point with a 2 by 2 matrix; you can do a rotation and scale but weirdly you need another dimension in order to do translation; you need 3 by 3 matrix.

![[2026-09-25_14-27.png]]

Let's look at why.

So we have point `P (1,1)` and it needs to be translated into `P'` (`P prime`), which is some fixed distance.

![[2026-09-25_14-38.png]]

No easy way to do this, at least as a matrix transform in two dimensions.

But you can manipulate things a bit by adding another dimension. We added this **fake third dimension** `z`.

Don't mind how is drown bellow, just imagine `z` is comming at you.

![[2026-09-25_14-40_1.png]]

We define our points sitting at: `( P, z = 1)` -> `(P,1)`; 
So all points are sitting in `z=1` plane. 

So we can shear space to the appropriate spot.

Let's say we want to transform our point `P`(1,1) by this: `δ` (delta) 
- δ = `(3,4)`
- so we define shear along `basis vector` like we did in previous lesson.

But on the place of `z` inside `basis matrix` for `basis vectors`, we put the **translations of `z`**, which are `(0, 0, 1)`.

You'll notice that matrix multiplication bolils down to adding the translation and point together.

![[skwingzintranslation.excalidraw|700]]

It's kind of a hack that makes matrix multiplication included translation by shearing in a higher dimension.

## If you want to transform 3D points you must use 4x4 matrix

To get a single matrix to do all of those in a single transform, you again add one more dimension and shear along that dimension.

You'll see that games end up using this everywhere, weather it is 3d vectors and they transform points in the world; they magicaly convert those to four dimensional vectors with 1 in the last component; the `W` component; Now you know why.

It's actually not that complex; basically little clever trick that makes possible representing transform in one single matrix.

# TRS Matrices - SRT order

Now you can define your scale, your rotation and tyour translation as matrices, and we know from earlier that you can multiply these together and form final matrix that combines all of mentioned operations; and you do that in a specific order.

![[2026-09-25_16-00.png]]

`T R S` is the order in which these matrices need to be multiplied.

## Is there any other way?

Without doing mentioned higher dimension shear hack? And answer is: There is.

If we are talking about 2D, the scale and the rotation can be represented by a single matrix; so we have a result of `RS`; and then you simple need to translate the position, **which we know already is simple vector addition**

so the final point is `P' = RS * (P + T)`

We are using long route because most game engines are using 4x4 matrices to represent combined transformations; and if you work in graphics, the entire transformation is 4 by 4 matrices.

![[2026-09-25_16-07.png]]

Three.js has `Matrix4` class and there are special functions on that class which allows you creating matrix from scale rotation  and translation (`compose` function).

Unity has similar class, `Matrix4x4` and there among other function there is one called `TRS` which creates translation,rotation scale matrix.
`T R S` is the order in which these matrices need to be multiplied, not a coincidence, the common pattern, because order of applying is from right to left, meaning scale , then rotation, then translation.

Unity also wraps the idea of transform object into separate `Transform` class, that is dedicated solely to holding a scale rotation and position. Benefit here is that you can create thing separately and create 4x4 matrix only when you need to.


# Transforming direction vector

What if we are transforming some kind of direction Vector?

Often people says that you "need to zero-out the last component W".

![[2026-09-25_17-46.png]]

Let's say you have vector V, which is a 2D value, and then you have (V, 1) where 1 is last, the z component; that is what allows the shearing part of the matrix transform to work.

And shear is translation; that's basically proportional to z.

So if you zero-out that component , shear gets zeroed out as well because it is proportional

So (v,0) and the rotation and scale portions of matrix work, but shear gets multiplied by 0.

and that's it , that is why some vectors gets one at the end, and other 0.

In reality that is not the whole story , but unless you are mathematician we can pretty much end things there.
