Like I said:  **`r`** and `θ` are also called `Polar Coordinates`

`(r, θ)`
- **r** — the **radial coordinate**: how far the point is from the origin (a straight-line distance, always ≥ 0)
- **θ** — the **angular coordinate**: the angle that line makes with the **positive `x`‑axis**, represented in radians

# Converting Vector from Cartesian coordinates representation to Polar coordinats representation

We have couple of ways of doing this.

Let's say we have direction vector represented with cartesian coordinates: 
- `V = (0.707, 0.707)`

We want to represent the vector with polar coordinates, which means we need to find radial and angular coordinates

## Dot Product way

**We can do this by utalizing dot product**: [[glavno/math-for-game-dev/2-vectors-more-practical/3. Dot Product]]
$$
\begin{gather}
\vec{v}_{1} \cdot \vec{v_{2}} = |\lvert a\rvert| & |\lvert b\rvert| & \cos{\theta} 
\end{gather}
$$

### Finding radial coordinate - magnitude (we don't need to do this in unit vectors like ours but let's confirm it)

This is easy, radial coordinate is also magnitude of vector so we need to find magnitude

```ts
||v|| = sqrt(0.707*0.707 + 0.707*0.707)
||v|| = 0.999848988 ≈ 1

// Magnitude is indeed one
// we confirmed it
r = ||v|| = 1
```

### Calculating dot product from cartesian components

![[findingthetaforangularcoord.excalidraw|700]]
So , dot product is 0.707

### Finding the angular coordinate - angle theta (θ)

So we are using equation for dot product. once again but it's part to the right of =

```js

dot product = ||v1|| * ||v2|| * cos(θ) 

// we have calculated dot product, and we know all the magnitudes
0.707 = 1 * 1 * cos(θ)

cos(θ) = 0.707 

// Now we can use `θ = acos(cos(θ))`   to get an angular coordinate

```

## Trigonometry way

Even easier. What we know:
- magnitude is hypotenuse
- adjacent side is `x` component/element of Cartesian representation

# `acos` & `asin` or `ArcusCosinus` and `ArcusSinus`

In previous example we calculated what `cos` of `θ` is (`cos(θ)`), but how to get actual angle value from it. An angular coordinate.

We need to invert cosinus calculation to get original angle.

There are few functions we can invert cosine or sine calculation to get original angle:
- ArcusCosinus
- ArcusSinus

// the way of doing it

# `cos` and `sin` peculiarity & `acos` and `asin` problems 

`sin` and `cos` have certain feature that transferred to `acos`  or `asin` brings potential problems.
## Different angles but same value for `cos`; Different angles but same value for `sin`

For example these next two different angles have same value for cos. Why? Looking at just `x` axis and a projection onto it from the vectors, we can notice the same angle in relation to `x` on the right side of the circle.   

But what is different is their `y` component, one is positive, other is negative.

You can see with bare eyes that their cos values are the same.

Same occurrence is terms of sin but looking at top and bottom side of the circle.

![[samesincoz.excalidraw|700]]
Nothing wrong with this but it can cause problems and we will see that next.

## `acos` only works for the top side of the circle & `asin` only works for the right side of the circle

This is continuation of previous peculiarity where we have different angles but same value of cos for them; well this peculiarity also transfers from `cos` to `acos`; and same peculiarity transfers from `sin` to `asin`. But in case of `asin` and `acos` it can become a real problem.

![[acosasinproblem.excalidraw|700]]

**As you can see because value of the `cos` is the same for different angles, `acos` just uses same value and that is why value is the same.** 

- **So the correct angle isn't calculated for the left side of the circle. It presents us symmetrical one on the right side**

Same goes for `sin` and `asin`.

- **So the correct angle isn't calculated for the bottom side of the circle. It presents us symmetrical one on the top side**
 
There is a solution for this problem and it is abandoning usage of `asin` and `acos`, and using something else instead.


# `atan2` - Fixing  `acos` and `asin` problems we mentioned


They realized mentioned peculiarity about `sin` and `cos`, in programming, 50 years ago, and introduced a new function: `atan2`.

![[2026-09-30_18-53.png]]

`atan2` arguments
- `y`
- `x` 
(Yes, in that order, first `y` and then `x`)
 
Which allows splitting circle into 4 quadrants, then map the result of `atan` call to the appropriate sections, giving you the angle theta without restrictions of `acos` or similar functions.

Let's go into browser console and test this.

so we have Cartesian `x` coordinate which is `0.707`, but also have Cartesian y coordinate `0.707`;  remember, our vector is (0.707, 0.707); and these are also cos and sin values  

So first argument is y and second is x, or first is sin and second is cos

```ts
Math.atan2(0.707,0.707)

> 0.7853981633974483  radians
```


or to calculate angle in degrees all together

```ts
Math.atan2(0.707,0.707) * 180/ Math.PI
> 45  degrees
```


Now let's invert the y component, making the same angle like here.
![[inveringcos.excalidraw|700]]

Don't forget that sinus or `y` component is first argument of `atan2`

And in this example it is negative number.

You will get the negative value for the angle.

```ts

Math.atan2(-0.707,0.707)
> -0.7853981633974483

Math.atan2(-0.707,0.707) * 180/ Math.PI
> -45
```

## Result of `atan2` is in range between -π and π

- it will be positive if vector is on upper side of the circle
- it will be negative if vector is in lover side of the circle

But if you want your angle to go from `0` to `2π` you can use if statement like this

```ts
// again telling you that y component is first argument
θ = atan2(-0.707, 0.707)

θ = -0.78539

θ = -PI/4

// so it is negative but if we want range betwen 0 and PI we cad do this

if(θ < 0) {
 θ += 2 * PI
}

// to confirm it

θ = θ + 2 *PI

θ = -PI/4 + 2 *PI

θ = 5.49778

θ = 7/4 * PI
```

## Converting from Polar coordinates to Cartesian coordinates

We already saw how to convert Cartesian to polar: [[glavno/math-for-game-dev/3-trigonometry/3. Vector to Angle#Represent Cartesioan coordinates (x,y) in Polar coordinates (r,θ)]]
Let's now learn the opposite.

Let's say we have
- `radial` coordinate with value of 1 (we are doing this on unit circle)
- `angular` coordinate θ of some value (doesn't really matter which value)

We want to get cartesian `(x,y)`

Well, since our circle is unit circle:
- x component is the same as `cos(θ)`
- y component is the same as `sin(θ)`

![[polartocartesian.excalidraw|700]]

So how we transform polar coordinates to cartesian:

```ts
x = r * cos(θ);
y = r * sin(θ);
```
