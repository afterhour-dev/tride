## Concept

Three fundamental interpolation functions in GLSL — the building blocks for transitioning between values, creating thresholds, and smoothing transitions.

### `step(edge, x)` — Hard Threshold

`step` returns **0.0** when `x` is below `edge`, and **1.0** when `x` is at or above `edge`. It's a binary on/off switch — nothing in between.

If you wrote it yourself:

```glsl
if (x < edge) return 0.0;
return 1.0;
```

Examples:
- `step(0.5, 0.0)` → `0.0`
- `step(0.5, 0.49)` → `0.0`
- `step(0.5, 0.51)` → `1.0`
- `step(0.5, 1.0)` → `1.0`

The name is intuitive: once `x` steps over the `edge` threshold, the output jumps up from 0 to 1. Useful for creating hard cutoffs, binary masks, or triggering regions.

### `mix(a, b, t)` — Linear Interpolation (LERP)

`mix` blends between two values `a` and `b` using `t` as a fraction. It's a linear interpolation — often called LERP.

Internally:

```glsl
return a + t * (b - a);
```

Examples:
- `mix(10.0, 20.0, 0.0)` → `10.0` — 0% between 10 and 20
- `mix(10.0, 20.0, 0.25)` → `12.5` — 25% between 10 and 20
- `mix(10.0, 20.0, 0.5)` → `15.0` — 50% between 10 and 20
- `mix(10.0, 20.0, 0.75)` → `17.5` — 75% between 10 and 20
- `mix(10.0, 20.0, 1.0)` → `20.0` — 100% between 10 and 20

`t` acts as a percentage or fraction multiplier. In HLSL (Microsoft's shader language), this same function is called `lerp` instead of `mix`.

### `smoothstep(edge1, edge2, x)` — Smooth Hermite Interpolation

`smoothstep` is like `step` but smooth — it eases in and out between 0 and 1 over a range defined by `edge1` and `edge2`. When `x` is below `edge1`, the result is 0; when `x` is above `edge2`, the result is 1; between them, it follows a Hermite curve.

Internally:

```glsl
t = clamp((x - edge1) / (edge2 - edge1), 0.0, 1.0);
return t * t * (3.0 - 2.0 * t);
```

The formula `t * t * (3.0 - 2.0 * t)` is a Hermite polynomial that produces S-curve easing — the transition starts and ends gradually, with faster change in the middle.

Examples:
- `smoothstep(10.0, 20.0, 10.0)` → `0.0`
- `smoothstep(10.0, 20.0, 12.5)` → `0.156`
- `smoothstep(10.0, 20.0, 15.0)` → `0.5`
- `smoothstep(10.0, 20.0, 20.0)` → `1.0`

### Combining Them

The most powerful pattern is using `smoothstep` as the `t` input to `mix`:

```glsl
color = mix(red, blue, smoothstep(0.0, 1.0, vUvs.x));
```

This gives you a smooth gradient blend between `red` and `blue` across the UV space, where:

1. `smoothstep` produces a smooth S-curve from 0 to 1 across the surface
2. `mix` uses that curve to blend between the two colors

The result is noticeably smoother than `mix(red, blue, vUvs.x)` (which is linear) — the edges linger longer, and the middle transition is more gradual.

## Code

in repo — `apps/21_9_step_mix_smoothstep`

```glsl
// Fragment shader — experimenting with step, mix, and smoothstep

varying vec2 vUvs;

void main() {
  vec3 color = vec3(0.);
  vec3 red   = vec3(1., 0., 0.);
  vec3 blue  = vec3(0., 0., 1.);

  // step — hard black/white cutoff at 50%
  color = vec3(step(0.5, vUvs.x));

  // step — cuttoff at 25% (75% white)
  color = vec3(step(0.25, vUvs.x));

  // mix — linear gradient from red to blue
  color = mix(red, blue, vUvs.x);

  // smoothstep — Hermite S-curve, subtle difference from linear
  color = vec3(smoothstep(0., 1., vUvs.x));

  // Combined — smooth gradient blend from red to blue
  color = mix(red, blue, smoothstep(0., 1., vUvs.x));

  gl_FragColor = vec4(color, 1.);
}
```

```glsl
// Vertex shader — passes UVs to fragment

varying vec2 vUvs;

void main() {
  vec4 localPosition = vec4(position, 1.);
  gl_Position = projectionMatrix * modelViewMatrix * localPosition;
  vUvs = uv;
}
```

The setup uses a `THREE.ShaderMaterial` on a `PlaneGeometry(1, 1)` with an orthographic camera framing the plane from `-0.1` to `1.1` in both axes — so the UV coordinates `(0, 0)` → `(1, 1)` fill most of the viewport.

## Gotchas

- **`step` is hard, not smooth** — it's easy to expect a gradient when you see a function name like "step". It gives a binary 0 or 1 with nothing between. Use `smoothstep` when you want a soft edge.
- **`mix` is linear** — the transition is mathematically straight. For organic or eased transitions, pass `smoothstep()` as the `t` parameter instead of raw UVs.
- **`smoothstep` requires `edge1 < edge2`** — if you reverse the edges, the function flips: values below the lower edge return 1, above the higher return 0. This is useful for inverted masking but can be surprising.
- **Subtle visual difference** — `smoothstep(0., 1., vUvs.x)` looks very close to `vUvs.x` as a grayscale gradient. The difference is in the curve's shape: smoothstep lingers at the edges (slow start, slow end) while a straight `vUvs.x` is constant velocity. You can spot the difference by looking for the "flattened" ends.
- **The app uses WebGL, not WebGPU** — the `three/webgpu` import path and `WebGPURenderer` are commented out. These functions work identically in both, but the code as-is uses WebGL.

## Revisit

- Combine `step` and `mix` to create multi-band color palettes — e.g. `mix(mix(colorA, colorB, step(0.33, x)), colorC, step(0.66, x))`.
- Practice using `smoothstep` with different edge ranges (not just 0 to 1) for soft threshold masks.
- Explore the connection between `smoothstep` and easing functions in animation (it's the same Hermite curve used in CSS `ease-in-out`).

approach is valid — these are fundamental GLSL functions shared by WebGL, WebGPU, Vulkan, and Metal. The concepts don't change between rendering APIs.
