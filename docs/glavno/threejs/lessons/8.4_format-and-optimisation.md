# Format and Optimisation

When preparing textures, three crucial elements determine performance and quality:

1. **Weight** — the file size the user must download
2. **Size** — the resolution of the texture
3. **Data** — what information the texture stores

## Concept

### Weight

The weight of a texture is the file size that must be downloaded by the user. When choosing a file format:

- `.jpg` — lossy compression, usually lighter file size
- `.png` — lossless compression, usually heavier file size

Use compression tools like [TinyPNG](https://tinypng.com/) to reduce file size, though some quality loss is expected.

### Size

Each pixel of a texture must be stored on the GPU, regardless of the image's file weight. GPUs have strong memory limitations, and mipmapping makes this even more significant because it increases the number of pixels to store.

Key points:
- Reduce texture size as much as possible
- Mipmapping (from the previous lesson) produces progressively smaller versions until 1×1
- Texture dimensions must be a **power of 2** for mipmapping to work correctly
  - 512 × 512
  - 1024 × 1024
  - 512 × 2048
- Failing to use power-of-2 dimensions causes poor performance and visual artifacts

### Data

Textures support different types of data, and choosing the right format matters:

- Transparency cannot be stored in `.jpg` — use `.png` for alpha channels
- Normal maps need exact values — use `.png` (lossless) to avoid compression artifacts
- Multiple data types can be combined into one texture using the R, G, B, and A channels separately

### Where to Find Textures

- [Poliigon](https://www.poliigon.com/)
- [3D Textures](https://3dtextures.me/)
- [Arroway Textures](https://www.arroway-textures.ch/)
- or create your own with [Adobe Substance 3D Designer](https://www.adobe.com/products/substance3d/apps/designer.html) — for procedural textures

> ⚠️ Always verify you have the right to use a texture if it's not for personal use.

## Code

in repo — `apps/8_format_and_optimisation`

```ts
import * as THREE from 'three/webgpu';

// Loading multiple textures with a LoadingManager
const loadingManager = new THREE.LoadingManager();
const textureLoader = new THREE.TextureLoader(loadingManager);

// Color map — using minecraft.png for NearestFilter demo
const colorMap = textureLoader.load('/textures/minecraft.png');

// Other texture maps (PBR workflow)
const normalMap = textureLoader.load('/textures/wooden_door/Door_Wood_001_normal.jpg');
const roughnessMap = textureLoader.load('/textures/wooden_door/Door_Wood_001_roughness.jpg');

// Disabling mipmaps and using NearestFilter for pixelated look
colorMap.minFilter = THREE.NearestFilter;
colorMap.generateMipmaps = false;
colorMap.magFilter = THREE.NearestFilter;

// Apply to material
const material = new THREE.MeshBasicMaterial({
  map: colorMap,
});

const mesh = new THREE.Mesh(new THREE.BoxGeometry(1, 1, 1), material);
```

## Gotchas

- Using non-power-of-2 textures with mipmapping causes performance issues and visual artifacts
- `.jpg` cannot store transparency — if you need alpha, you must use `.png`
- Normal maps stored as `.jpg` may have compression artifacts that affect lighting calculations
- Large textures (e.g., 4K wood door) are wasteful for objects far from the camera

## Revisit

- Experiment with different texture sizes to see the impact on memory and quality
- Try combining channel data (e.g., roughness in one channel, metallic in another) to reduce texture count
- Practice identifying when to use `.jpg` vs `.png` based on the data type
