# 11.2 Text Center

## Concept

This lesson covers **how to center TextGeometry** in the scene. When you create a text mesh, its origin sits at the bottom-left of the first character — not at the visual center. To fix this, we need to understand bounding boxes and how to translate geometry.

### What is a Bounding Box?

A **bounding box** is the smallest axis-aligned box that fully encloses a geometry. Three.js computes it from the geometry's vertices and stores it in `geometry.boundingBox` as a `Box3` object with `min` and `max` properties.

```ts
textGeometry.computeBoundingBox();
console.log(textGeometry.boundingBox);
// Box3 { min: Vector3(-1.23, 0, -0.02), max: Vector3(2.45, 0.5, 0.23) }
```

**Important:** `boundingBox` is `null` until you call `computeBoundingBox()`. Three.js doesn't compute it automatically because it's an extra step.

There's also a **bounding sphere** (`computeBoundingSphere()`), which is the smallest sphere enclosing the geometry. By default, Three.js uses the bounding sphere for **frustum culling** — determining whether an object is inside the camera's view and should be rendered.

### Centering the Hard Way: Bounding Box + Translate

The manual approach:
1. Call `computeBoundingBox()` to get the bounding box
2. Use `translate()` to shift the geometry so its center aligns with the origin

```ts
textGeometry.computeBoundingBox();

// Without accounting for bevel — slightly off
textGeometry.translate(
  -textGeometry.boundingBox.max.x * 0.5,
  -textGeometry.boundingBox.max.y * 0.5,
  -textGeometry.boundingBox.max.z * 0.5,
);
```

**The bevel problem:** TextGeometry adds a bevel (rounded edge) around the text. The bounding box includes the bevel, so if you center using only `max`, the text sits slightly off-center because the bevel adds extra space on the negative axes too. To fix this, you subtract the bevel offset:

```ts
const bevelSize = 0.02;
const bevelThickness = 0.03;

textGeometry.translate(
  -(textGeometry.boundingBox.max.x - bevelSize) * 0.5,
  -(textGeometry.boundingBox.max.y - bevelSize) * 0.5,
  -(textGeometry.boundingBox.max.z - bevelThickness) * 0.5,
);
```

> ⚠️ Even with the bevel correction, the manual approach can still be slightly off-center in the Y axis, especially with certain fonts. The `center()` method handles all of this automatically.

### Centering the Easy Way: `geometry.center()`

Three.js provides a built-in method that does all the math for you:

```ts
textGeometry.center();
```

That's it. It computes the bounding box, calculates the correct translation for each axis, and applies it. No need to worry about bevel offsets or manual calculations.

**Why translate geometry instead of moving the mesh?** Because `mesh.position` moves the entire object (including its local coordinate system), while `translate()` moves only the geometry vertices relative to the mesh's origin. When you want centered text at `(0, 0, 0)`, translating the geometry keeps the mesh at the origin and centers the visual result — which is usually what you want.

    size: 0.5,
    depth: 0.2,
    curveSegments: 5,
    bevelEnabled: true,
    bevelThickness,
    bevelSize,
    bevelOffset: 0,
    bevelSegments: 4,

  // --- Hard way (commented out) ---
  // textGeometry.computeBoundingBox();

  //   );
  // }

  textGeometry.center();

  const textMaterial = new THREE.MeshBasicMaterial();

## Gotchas

- **`boundingBox` is null until computed** — calling `textGeometry.boundingBox` before `computeBoundingBox()` gives you `null`. Always compute first if you're using the bounding box for centering or other calculations.

- **Bevel throws off manual centering** — the bounding box includes the bevel volume. If you center using only `boundingBox.max`, the text will appear shifted because the bevel adds space on the negative side too. You need to subtract `bevelSize` (X/Y) and `bevelThickness` (Z) from the max values.

- **`translate()` moves geometry, not the mesh** — `geometry.translate(x, y, z)` moves the vertices themselves. `mesh.position.x = 1` moves the entire mesh (including its children). For centering, you want the former.

- **`center()` vs manual** — `geometry.center()` is simpler and more reliable, especially with bevels. Use it unless you need fine-grained control over the centering offset.

- **Frustum culling uses bounding sphere, not box** — by default Three.js uses `boundingSphere` for frustum culling (determining what's on-screen). The bounding box is there for other purposes like centering. Don't confuse the two.
