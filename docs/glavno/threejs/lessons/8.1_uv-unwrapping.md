# UV Unwrapping

Exploring how textures are mapped onto 3D geometry through UV coordinates — the invisible 2D "skin" that tells the renderer which part of a texture image goes where on a 3D surface.

## Concept

### How Does a 2D Image Cover a 3D Shape?

When you apply a texture to a mesh, the texture doesn't magically know where to go. Every vertex on the geometry has a hidden set of **2D coordinates** that map it to a position on the texture image. These coordinates are called **UV coordinates** (sometimes called texture coordinates).

The letters **U** and **V** are used because **X**, **Y**, and **Z** are already taken by the 3D space. U is the horizontal axis on the texture, V is the vertical axis. Together, each vertex gets a `(U, V)` pair that says "this corner of the triangle maps to this spot on the image."

### The Candy Wrapper Analogy

Think of UV unwrapping like unwrapping a Christmas candy. The candy is a 3D shape wrapped in foil (the texture). To lay the foil flat on a table, you have to cut and unfold it. The way you unfold it determines how the pattern on the foil lines up — some parts might stretch, some might compress, and the seams might show.

That's exactly what UV unwrapping is: defining how a 3D surface "unfolds" into a flat 2D plane so the texture can be applied.

### UV Coordinates Are Always in a Square

UV coordinates are normalized to a **0–1 range** on both axes:

- `(0, 0)` is the bottom-left corner of the texture
- `(1, 1)` is the top-right corner
- `(0.5, 0.5)` is the center

This means UV space is always a unit square, regardless of the texture's actual pixel dimensions. A 1024×1024 texture and a 4096×4096 texture both use the same 0–1 UV space.

### Three.js Generates UVs for You

For built-in geometries (`BoxGeometry`, `SphereGeometry`, `TorusGeometry`, etc.), Three.js automatically creates UV coordinates. You don't have to think about them — they just work.

But the way Three.js unwraps each geometry is different, and that's why the same texture looks completely different on different shapes:

| Geometry | UV Behavior |
|---|---|
| **Box** | Each face gets its own clean 0–1 square. Texture appears once per face, no stretching. |
| **Sphere** | Texture wraps around like a globe map. Stretched at the equator, compressed at the poles (the "pinch" effect). |
| **Cone** | Top is dense (texture compressed into a point), bottom is stretched. One side shows strange patterns. |
| **Torus** | Texture repeats around the ring and through the tube — all stretched and repeating. |

You can see this in action in the app — use the **GEOMETRY** dropdown in the GUI to swap between shapes and observe how the same door texture maps differently.

### When You Need to Create UVs Yourself

If you create geometry from scratch (using `BufferGeometry` with custom vertices), you must provide the UV coordinates manually — Three.js won't generate them for you. The `uv` attribute is a `Float32BufferAttribute` with 2 floats per vertex.

If you model in 3D software like Blender, you do the UV unwrapping there. Blender's UV editor lets you cut seams, unfold the mesh, and arrange the UV islands — then exports the UV coordinates with the model.

### Inspecting UV Coordinates

In the app, switching geometries logs `geo.attributes` and `geo.attributes.uv` to the console. The `uv` attribute is a `Float32BufferAttribute` — open the console and expand it to see the raw UV data:

```ts
// When you switch geometry in the GUI:
console.log(geo.attributes);       // all attributes: position, normal, uv
console.log(geo.attributes.uv);    // just the UV coordinates
```

The `uv` attribute has a `count` property (number of vertices), an `itemSize` of 2 (U and V per vertex), and a `array` containing all the flat float values.

import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';

// --- Texture loading (only the color map matters for UV unwrapping) ---

const loadingManager = new THREE.LoadingManager();
const textureLoader = new THREE.TextureLoader(loadingManager);

const colorMap = textureLoader.load(
  '/textures/wooden_door/Door_Wood_001_basecolor.jpg',
);

// --- Create multiple geometries to compare UV behavior ---

const boxGeometry = new THREE.BoxGeometry(1, 1, 1);
const sphereGeometry = new THREE.SphereGeometry(1, 32, 32);
const coneGeometry = new THREE.ConeGeometry(1, 1, 32);
const torusGeometry = new THREE.TorusGeometry(1, 0.35, 32, 100);

const material = new THREE.MeshBasicMaterial({ map: colorMap });
const mesh = new THREE.Mesh(boxGeometry, material);
scene.add(mesh);

// --- GUI: switch geometries and inspect UV attributes ---

const gui = new GUI({ width: 250 });
const folder = gui.addFolder('Awsome cube');

folder
  .add(mesh, 'geometry', {
    boxGeometry,
    sphereGeometry,
    coneGeometry,
    torusGeometry,
  })
  .name('GEOMETRY')
  .onChange((geo: THREE.BufferGeometry) => {
    console.log(geo.attributes);      // position, normal, uv
    console.log(geo.attributes.uv);   // Float32BufferAttribute
  });

// --- Camera & renderer ---

const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);
camera.lookAt(mesh.position);

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;
const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
renderer.setSize(innerWidth, innerHeight);

// --- Render loop ---

function tick() {
  controls.update();
  camera.lookAt(mesh.position);
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
tick();

## Gotchas

- **Different geometries = different UV layouts** — The same texture looks completely different on a box vs. a sphere vs. a torus. This isn't a bug — it's how UV unwrapping works. Each geometry type has its own way of "unfolding" the surface into 2D.

- **Sphere UV pinching at the poles** — Sphere textures compress to a point at the top and bottom (like how a globe map squishes Antarctica). If you need even texture distribution on a sphere, you'd need custom UVs or a different projection.

- **`MeshBasicMaterial` ignores lighting** — This lesson uses `MeshBasicMaterial` to keep focus on UVs. If you switch to `MeshStandardMaterial` or `MeshPhysicalMaterial`, you'll need proper lighting to see the texture. Don't confuse "texture looks flat" with "UV is wrong."

- **Swapping geometry doesn't update subdivisions** — The GUI lets you switch geometries, but it doesn't preserve the subdivision level from the box. Each geometry uses its own default segments.

- **UV coordinates are per-vertex, not per-face** — Each vertex stores one UV coordinate. If two faces share a vertex, they share that UV point. This is why seams matter in UV unwrapping — you sometimes need to duplicate vertices to give different faces different UVs.

## Revisit

- **Texture repeat and wrap modes** — `THREE.RepeatWrapping` lets you tile a texture across a surface. Combined with UV scaling, this is how floor tiles and brick walls work. Not covered here.
- **UV editing in Blender** — If you model in Blender, the UV Editor is where you cut seams, unwrap, and arrange UV islands. Worth practicing when you start making your own models.
- **Custom BufferGeometry UVs** — When you create geometry from scratch with `BufferGeometry`, you must provide the `uv` attribute manually. Good exercise for understanding what UVs actually are.
- **Texture filtering** — `minFilter` and `magFilter` control how textures look at different distances. `THREE.NearestFilter` gives a pixelated retro look.
- **UDIM UV mapping** — An extension of UV mapping that uses multiple texture tiles across UV space. Used in film/VFX pipelines.

## Outdated

The approach is valid. UV mapping and the geometry attribute system in Three.js are stable core features. No deprecations to worry about.
