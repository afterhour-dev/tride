# 4.2 Camera Perspective

## Concept

A **PerspectiveCamera** projects 3D scenes with realistic depth — objects shrink as they move farther away, just like in real life. This is the camera type you'll use most often in 3D projects because it produces natural-looking results.

### PerspectiveCamera parameters

The constructor takes four arguments:

```ts
new THREE.PerspectiveCamera(fov, aspect, near, far)
```

- **fov** (field of view) — the vertical angle of the camera's view cone, in degrees. A value of `45` means the camera sees 45° vertically. Lower values zoom in (narrower view), higher values zoom out (wider view). `50`–`75` are common ranges.
- **aspect** — width divided by height of the canvas (`sizes.width / sizes.height`). This keeps objects from looking stretched. If you forget this, circles become ovals on non-square canvases.
- **near** — distance to the near clipping plane. Objects closer than this are invisible. Usually `0.1`.
- **far** — distance to the far clipping plane. Objects farther than this are invisible. Usually `100` or `1000`.

### PerspectiveCamera inheritance

`PerspectiveCamera` extends `Camera`, which extends `Object3D`. This means it inherits `position`, `rotation`, `scale`, and `lookAt()` — you move and orient a camera the same way you'd move any mesh.

```ts
// for example we can get je Euklidsko rastojanje od world origin-a, tj. tačke (0,0,0)
console.log(camera.position.length())
```

### Orbiting with sin/cos

The app orbits the camera around the scene origin using trigonometry:

```ts
camera.position.x = Math.cos(Math.PI * elapsedTime * 0.2) * 3;
camera.position.z = -Math.sin(Math.PI * elapsedTime * 0.2) * 3;
```

Breaking down the formula:

- **`elapsedTime`** — seconds since the animation started (from `THREE.Timer`)
- **`0.2`** — speed multiplier. Controls how fast the camera orbits. Higher = faster orbit.
- **`3`** — radius. How far from the center the camera orbits. Larger = camera is further out.
- **`Math.PI`** — scales the angle. With `Math.PI * t * 0.2`, one full orbit takes `1 / 0.2 = 5` seconds.
- The minus sign on `sin` controls the direction of rotation (clockwise vs counter-clockwise).

This is the standard pattern for circular motion in 3D: `cos` for one axis, `sin` for another, both sharing the same angle and radius.

### Center of rotation

The camera orbits around **(0, 0, 0)** — the scene origin — even though `lookAt(mesh.position)` keeps it pointed at the mesh at (-0.5, 0, 0.5). This works because:

1. The sin/cos functions generate positions around (0, 0, 0)
2. `lookAt()` only changes the camera's rotation (where it faces), not its position

So the position is determined by sin/cos, and the orientation is determined by `lookAt()`. These are independent — one doesn't affect the other.

### Axes helper

The `AxesHelper` draws colored lines for the X (red), Y (green), and Z (blue) axes. This makes it much easier to see where the camera is in 3D space, especially during orbit animations.

## Code

in repo - `apps/4_camera_perspective`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

const sizes = { width: 800, height: 600 };

const scene = new THREE.Scene();

// Box mesh
const boxGeometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
const material = new THREE.MeshBasicMaterial({ color: 0x4c9892 });
const mesh = new THREE.Mesh(boxGeometry, material);
mesh.position.set(-0.5, 0, 0.5);
scene.add(mesh);

// Perspective camera
const camera = new THREE.PerspectiveCamera(
  45,                          // FOV in degrees
  sizes.width / sizes.height,  // aspect ratio
  0.1,                         // near clipping plane
  100,                         // far clipping plane
);
camera.position.set(0.1, 0.5, 3);
scene.add(camera);

// Renderer
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setSize(sizes.width, sizes.height);
renderer.setClearColor(0x000000, 1);

// Axes helper
const axesHelper = new THREE.AxesHelper(5);
axesHelper.setColors('red', 'green', 'blue');
scene.add(axesHelper);

// Orbiting animation
const timer = new THREE.Timer();

function tick(timestamp: number) {
  timer.update(timestamp);
  const elapsed = timer.getElapsed();

  camera.position.x = Math.cos(Math.PI * elapsed * 0.2) * 3;
  camera.position.z = -Math.sin(Math.PI * elapsed * 0.2) * 3;
  camera.lookAt(mesh.position);

  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

## Gotchas

- **Aspect ratio** — Always pass `sizes.width / sizes.height` as the second parameter. A wrong aspect ratio makes everything look stretched or squished. If you resize the canvas later, you need to update this too.
- **Near/far clipping** — Objects closer than `near` or farther than `far` simply disappear. If objects vanish when the camera moves, these values are the first thing to check.
- **FOV sensitivity** — Small changes in FOV have a big visual impact. `45` feels natural; `120` looks like a fisheye lens. Start with `45`–`60` and adjust from there.
- **lookAt vs position** — `camera.lookAt(target)` changes the camera's rotation, not its position. If the camera "jumps" to a weird angle, it's usually because the position and lookAt target are too close together or aligned in an edge case.

## Revisit

- Try swapping PerspectiveCamera and OrthographicCamera on the same scene to feel the difference in depth perception
- Experiment with different FOV values (`30`, `45`, `75`, `90`) to see how it changes the scene's feel
- Change the orbit radius (`3` in the code) and speed (`0.2`) to build intuition for the sin/cos parameters
- Try replacing `camera.lookAt(mesh.position)` with `camera.lookAt(new THREE.Vector3(0, 0, 0))` to see what happens when the camera looks at the origin instead of the mesh
