# 7.5 gui-button

## Concept

lil-gui supports adding **functions as buttons**. When you add a function property to a GUI, it renders as a clickable button — no slider, no checkbox, just a button that calls your function when clicked.

The pattern works like this:

1. Create a **debug object** with a function property (initially a no-op):
   ```ts
   const debugObject = {
       spin: () => {},
   };
   ```

2. Define the actual function you want to call:
   ```ts
   const mojaFunkcije = () => {
       gsap.to(boxMesh.rotation, {
           duration: 1.5,
           y: boxMesh.rotation.y + Math.PI * 2,
       });
   };
   ```

3. Assign it to the debug object and add to GUI:
   ```ts
   debugObject.spin = mojaFunkcije;
   gui.add(debugObject, 'spin');
   ```

When lil-gui sees a property that's a function, it renders a button instead of a slider. Clicking the button calls the function.

### Why a debug object?

You can't add a standalone function to lil-gui — it needs to be a property on an object. The `debugObject` is just a plain object used as a container for things you want in the GUI. This is the same pattern used for tweaking material colors, geometry params, etc.

### GSAP for smooth animation

The `spin` function uses [GSAP](https://greensock.com/gsap/) to animate the rotation smoothly instead of snapping instantly. `gsap.to()` tweens the `y` property of `boxMesh.rotation` from its current value to `current + Math.PI * 2` (one full rotation) over 1.5 seconds.

This is equivalent to `boxMesh.rotation.y += Math.PI * 2` but with easing and duration control.

### Checkbox in GUI

The same `gui.add()` method also handles booleans — when the property is `true`/`false`, lil-gui renders a checkbox:

```ts
gui.add(axesHelper, 'visible').name('axesHelper visible');
```

Clicking the checkbox toggles `axesHelper.visible` between `true` and `false`.

## Code

in repo - `apps/7_gui_button`

```ts
import * as THREE from 'three/webgpu';
import GUI from 'lil-gui';
import gsap from 'gsap';

const gui = new GUI();

// Debug object — container for GUI-controllable properties
const debugObject = {
    spin: () => {},  // initially empty, will be overwritten
};

// Scene setup
const scene = new THREE.Scene();
const boxGeometry = new THREE.BoxGeometry(1, 1, 1, 2, 2, 2);
const material = new THREE.MeshBasicMaterial({ color: '#8f69c8', wireframe: true });
const boxMesh = new THREE.Mesh(boxGeometry, material);
boxMesh.position.x = -1.5;
boxMesh.position.z = 0.5;
scene.add(boxMesh);

// Button — assign function to debug object, then add to GUI
const mojaFunkcije = () => {
    gsap.to(boxMesh.rotation, {
        duration: 1.5,
        y: boxMesh.rotation.y + Math.PI * 2,
    });
};
debugObject.spin = mojaFunkcije;
gui.add(debugObject, 'spin');  // renders as a button

// Checkbox — boolean property renders as checkbox
const axesHelper = new THREE.AxesHelper(5);
axesHelper.visible = false;
scene.add(axesHelper);
gui.add(axesHelper, 'visible').name('axesHelper visible');
```

## Gotchas

- **Debug object pattern is mandatory** — lil-gui needs an object + property name, not a bare function. You can't do `gui.add(myFunction)`.
- **GSAP `.to()` uses absolute target** — `y: boxMesh.rotation.y + Math.PI * 2` adds to the *current* value at call time. If you wrote just `y: Math.PI * 2`, it would always rotate to the same absolute angle, not spin from wherever it currently is.
- **WebGPU renderer needs `await renderer.init()`** — unlike WebGL, you must wait for the GPU device to initialize before rendering. Forgetting this causes a silent failure or error.

## Revisit

- **GSAP timelines** — for chaining multiple animations (e.g., spin then scale), use `gsap.timeline()` instead of individual `.to()` calls.
- **More lil-gui features** — folders (`gui.addFolder('name')`), presets, and onChange callbacks are worth exploring as your GUI grows.
- **lil-gui `.onChange()`** — for non-button properties, you can add callbacks when values change.
