# 10.0 basic-scene-setup

## Concept

This lesson sets the stage for material exploration. A scene is built with four geometries (box, sphere, plane, torus) that all share a single `MeshBasicMaterial` — the focus is on how the material and its texture map work, not on the geometry itself.

### Materials

Materials determine how a surface looks when rendered. They control color, opacity, how light reacts to the surface, and more. Three.js ships with many built-in materials, each wrapping a shader program that runs on the GPU. The algorithms deciding the color of each visible pixel are written in programs called **shaders** — but Three.js provides pre-made materials so you don't have to write shaders from scratch.

A material can be assigned to multiple meshes. The mesh is just geometry (shape) + material (appearance). This means you can change the look of every mesh at once by tweaking a single material.

### Color Space and `colorSpace`

When loading textures, Three.js needs to know how to interpret the color data. There are two main settings:

- **`THREE.SRGBColorSpace`** — the standard color space for images (JPEG, PNG). Textures used as `map` (color) or `matcap` should use this. Colors look correct and vibrant.
![[srgb.png]]
- **`THREE.NoColorSpace`** — the default. The renderer treats the raw pixel values as-is, without any gamma correction. Textures look washed out and darker than expected.
![[nosrgb.png]]

Setting `texture.colorSpace = THREE.SRGBColorSpace` tells the renderer to convert from sRGB to linear space during rendering, which is the physically correct way to handle color. Without this step, all textures will appear too dark because the renderer is working in linear space but the texture data is encoded in sRGB.

```ts
const texture = textureLoader.load('/textures/my_texture.jpg');
texture.colorSpace = THREE.SRGBColorSpace; // correct for color maps
```

### PBR Texture Maps

The app loads a full set of PBR (Physically Based Rendering) textures for a wooden door. Each texture type encodes a different material property:

| Texture | What it controls |
|---|---|
| **Albedo** (basecolor) | The flat color of the surface, no lighting information |
| **Alpha** (opacity) | Which parts are transparent vs opaque |
| **Ambient Occlusion** | Soft shadowing in crevices and corners |
| **Height** | Surface displacement data |
| **Normal** | Fake surface detail by perturbing the normal direction |
| **Metallic** | Which parts are metal vs non-metal |
| **Roughness** | How shiny or matte the surface is |

These textures are loaded in advance using `THREE.TextureLoader` with a `LoadingManager` so they're ready when the scene renders.

### `MeshBasicMaterial`

This is the simplest material — it renders the surface with no lighting calculations at all. The `map` property assigns a texture that gets drawn directly onto the geometry. It's useful for debugging or for unlit effects, but doesn't respond to scene lights.

```ts
const material = new THREE.MeshBasicMaterial({
  map: doorAlbedoTexture,
});
```

The same material instance is shared across all four meshes. Changing `material.color` or `material.map` would affect every mesh that uses it.

## Code

in repo - `apps/10_0_materials_pepare`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

// Load a texture and set correct color space
const textureLoader = new THREE.TextureLoader();
const doorTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_basecolor.jpg');
doorTexture.colorSpace = THREE.SRGBColorSpace;

// Create a material and share it across multiple meshes
const material = new THREE.MeshBasicMaterial({ map: doorTexture });

const boxMesh = new THREE.Mesh(new THREE.BoxGeometry(1, 1, 1), material);
const sphereMesh = new THREE.Mesh(new THREE.SphereGeometry(0.5, 16, 16), material);
const planeMesh = new THREE.Mesh(new THREE.PlaneGeometry(1, 1), material);
const torusMesh = new THREE.Mesh(new THREE.TorusGeometry(0.3, 0.2, 16, 32), material);

// Position them apart
boxMesh.position.x = 3;
sphereMesh.position.x = -1.5;
torusMesh.position.x = 1.5;

const scene = new THREE.Scene();
scene.add(boxMesh, sphereMesh, planeMesh, torusMesh);

const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

function tick() {
  controls.update();
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
tick();
```

## Gotchas

- **Textures look dark/washed out** — forgetting to set `texture.colorSpace = THREE.SRGBColorSpace` on color textures (map, matcap). The default is `NoColorSpace`, which means no gamma correction is applied. Always set this on textures that carry color data.
- **Shared material reference** — materials are objects, so assigning the same material to multiple meshes means all of them share one instance. Modifying `material.color` affects every mesh using it. If you want independent colors, create separate material instances.
- **`colorSpace` vs `encoding`** — older Three.js versions used `texture.encoding = THREE.sRGBEncoding`. The current API (r152+) uses `texture.colorSpace = THREE.SRGBColorSpace`. If you see `encoding` in older tutorials, it's outdated.
- **PBR textures loaded but unused** — this lesson loads all door PBR textures (alpha, normal, roughness, metallic, AO, height) but only uses the albedo as `map`. The other textures will be used in upcoming material lessons (MeshStandardMaterial, MeshPhysicalMaterial).

## Revisit

- Explore how `MeshStandardMaterial` and `MeshPhysicalMaterial` use the full PBR texture set (normalMap, roughnessMap, metalnessMap, aoMap, displacementMap, alphaMap)
- Understand the difference between sRGB and linear color space in more depth — why rendering happens in linear space and why textures need conversion
- Practice with different texture formats (WebP, AVIF) and their impact on loading performance
- Look into `RGBELoader` and HDR environment maps for image-based lighting

## Outdated

The approach is valid. Using `three/webgpu` with `WebGPURenderer` is the current recommended path. The `colorSpace` API (replacing the older `encoding`) is up to date.
