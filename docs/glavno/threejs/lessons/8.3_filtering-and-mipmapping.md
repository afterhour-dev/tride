## Concept

When you zoom out from a textured surface or look at it from an extreme angle, the texture can look blurry or pixelated. **Filtering** and **mipmapping** are techniques the GPU uses to handle this — choosing the right version of a texture to display based on how much screen space it covers.

### Mipmapping

Mipmapping (sometimes written "mip mapping") is a technique where Three.js (and the GPU) creates progressively smaller versions of a texture — each one half the resolution of the previous — all the way down to a 1×1 pixel. These pre-scaled versions are called **mipmaps**. The GPU then picks the most appropriate mip level based on how far away or angled the surface is relative to the camera.

This is why distant surfaces look smooth rather than noisy — the GPU is sampling from a smaller, pre-filtered version of the texture instead of trying to squeeze the full-resolution texture into a few pixels.

Mipmaps are generated automatically by Three.js when you load a texture. You can disable them with:

```ts
texture.generateMipmaps = false;
```

This is useful when you specifically don't want the GPU to blur distant textures (e.g. when using a pixel-art style with `NearestFilter`).

### Minification Filter (`minFilter`)

Minification happens when the texture's pixels are **smaller** than the screen pixels — in other words, the texture is too big for the surface it covers (the surface takes up fewer pixels on screen than the texture has texels). This is the most common case — surfaces viewed from a distance or at a steep angle.

There are 6 `minFilter` options:

| Value | Behavior |
|-------|----------|
| `THREE.NearestFilter` | Picks the nearest texel, sharp but aliased. No mipmaps needed. |
| `THREE.LinearFilter` | Blends between nearest texels, smoother. No mipmaps needed. |
| `THREE.NearestMipmapNearestFilter` | Picks the nearest mip level, then the nearest texel. |
| `THREE.NearestMipmapLinearFilter` | Picks the nearest mip level, then linearly blends texels. |
| `THREE.LinearMipmapNearestFilter` | Linearly blends between two closest mip levels, then picks nearest texel. |
| `THREE.LinearMipmapLinearFilter` | Linearly blends between mip levels AND between texels. **Default.** Smoothest result. |

The first two don't use mipmaps at all. The last four each combine a mip-level selection method (Nearest or Linear) with a texel sampling method (Nearest or Linear).

### Magnification Filter (`magFilter`)

Magnification happens when the texture's pixels are **bigger** than the screen pixels — the texture is too small for the surface it covers (the surface takes up more pixels on screen than the texture has texels). This happens when you zoom in close to a surface.

There are only 2 `magFilter` options:

| Value | Behavior |
|-------|----------|
| `THREE.NearestFilter` | Sharp, blocky pixels. Good for pixel-art style. Better for performance. |
| `THREE.LinearFilter` | Smoothly blends between texels. **Default.** |

Since magnification doesn't involve multiple mip levels, there's no mipmap interaction — just nearest vs. linear interpolation.

### When to Use What

- **Default (`LinearMipmapLinearFilter` + `LinearFilter`)**: Works well for most cases. Smooth, no artifacts.
- **Pixel-art / retro style**: Use `NearestFilter` for both `minFilter` and `magFilter`, and set `generateMipmaps = false`.
- **Performance**: `NearestFilter` is cheaper than `LinearFilter` since it doesn't interpolate. On mobile or low-end hardware, this can matter.
- **If you use `NearestFilter` on `minFilter`**: You don't need mipmaps — set `texture.generateMipmaps = false` to avoid generating data you won't use.

> 📝 When testing with the `checkerboard-1024x1024.png` texture, some parts of the box appeared white when zooming out. This turned out to be a visual artifact related to how the texture was being sampled at certain distances — switching textures or adjusting filter settings resolved it. Pay attention to which texture you're testing with, as different textures can reveal different filter behaviors.

## Code

in repo - `apps/8_filtering_and_mipmapping`

```ts
import * as THREE from 'three/webgpu';

const textureLoader = new THREE.TextureLoader();
const colorMap = textureLoader.load('/textures/minecraft.png');

// Minification filter — pick one:
colorMap.minFilter = THREE.NearestFilter;         // sharp, no mipmaps
// colorMap.minFilter = THREE.LinearFilter;        // smooth, no mipmaps
// colorMap.minFilter = THREE.NearestMipmapNearestFilter;
// colorMap.minFilter = THREE.NearestMipmapLinearFilter;
// colorMap.minFilter = THREE.LinearMipmapNearestFilter;
// colorMap.minFilter = THREE.LinearMipmapLinearFilter; // default

// Disable mipmaps when using NearestFilter on minFilter
colorMap.generateMipmaps = false;

// Magnification filter — pick one:
colorMap.magFilter = THREE.NearestFilter;   // sharp, pixelated
// colorMap.magFilter = THREE.LinearFilter;  // smooth (default)

const material = new THREE.MeshBasicMaterial({ map: colorMap });
const mesh = new THREE.Mesh(new THREE.BoxGeometry(1, 1, 1), material);
```

## Gotchas

- **Forgetting to disable mipmaps with `NearestFilter`**: If you set `minFilter = THREE.NearestFilter` but leave `generateMipmaps = true`, the GPU still generates all the mip levels — wasting memory and time. Always pair `NearestFilter` on `minFilter` with `generateMipmaps = false`.

- **Texture choice matters for testing**: Some textures (like `checkerboard-1024x1024.png`) can produce unexpected white artifacts at certain zoom levels. If you see strange results, try a different texture before assuming your filter settings are wrong.

- **`magFilter` has no mipmaps**: There are only 2 options for magnification (`NearestFilter` and `LinearFilter`). Don't look for mipmap variants here — they don't exist.

- **Performance vs. quality trade-off**: `NearestFilter` is faster but looks blocky. `LinearMipmapLinearFilter` looks best but costs more GPU time. Choose based on your visual needs and target hardware.

## Revisit

- Experiment with each of the 6 `minFilter` values on the same texture to see the visual differences firsthand — especially zoom in/out and rotate the camera to extreme angles.
- Try `NearestFilter` on a pixel-art texture (like `minecraft.png`) for a retro aesthetic.
- Consider whether you actually need mipmaps for your use case — disabling them saves GPU memory.
- Check if your approach is outdated — the app uses `WebGPURenderer` which is the modern path. The filtering concepts apply identically to WebGL.

> 💡 More up to date alternative: WebGPU is the future of graphics on the web. The filtering and mipmap concepts are the same, but WebGPU gives you more control over the rendering pipeline. See the [WebGPU docs](https://www.w3.org/TR/webgpu/) for details.
