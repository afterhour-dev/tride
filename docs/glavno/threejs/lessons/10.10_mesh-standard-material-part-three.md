# 10.10 mesh-standard-material-part-three

## Concept

This lesson continues building on `MeshStandardMaterial` by loading a full set of textures onto a wooden door material. Building on the environment map setup from [[10.9_mesh-standard-material-part-two]], we now explore every texture map type available on the standard material.

### Color Map (`map`)

The simplest texture — it maps a base color image (albedo) onto the geometry's surface. Applied with `material.map = texture`. The texture's `colorSpace` property matters: setting it to `THREE.SRGBColorSpace` ensures the color is interpreted correctly for display, while `THREE.NoColorSpace` (the default) can make the texture look lighter or washed out.

### Ambient Occlusion Map (`aoMap`)

An ambient occlusion map adds soft contact shadows in the darker areas of a texture — cracks, crevices, and seams appear to be occluded from ambient light. The intensity of this effect is controlled by `aoMapIntensity` (range `0` to `1`, default `1`). This property impacts:

- **Ambient light** (if present)
- **Environment map light** (present in this lesson via the HDR environment)
- **HemisphereLight** (if present)

Lowering `aoMapIntensity` to `0` effectively disables the ambient occlusion effect.

### Displacement Map (`displacementMap`)

A displacement map physically moves vertices along their normals based on a height texture — unlike normal maps, this actually deforms the geometry. Key points:

- Use a **height texture** (grayscale image where white = high, black = low)
- The effect is controlled by `displacementScale` — a small value like `0.08` is usually enough; large values push vertices far out of position
- **Subdivisions matter**: low-poly geometry (e.g. `SphereGeometry` with 16 segments) will show stretched, broken vertices because there aren't enough vertices to displace smoothly. Increase segments (e.g. 64×64 for a sphere) for clean results
- The GUI in this app lets you lower segments to see the stretched effect in real time — switch to wireframe to really see what's happening

### Metalness Map (`metalnessMap`) and Roughness Map (`roughnessMap`)

Instead of setting `metalness` and `roughness` to uniform scalar values, you can use texture maps that define these properties per-pixel across the surface. In this app, both `metalness` and `roughness` are set to `1` so the maps control the variation entirely — the scalar values act as multipliers on top of the map values.

### Normal Map (`normalMap`)

A normal map fakes surface detail by altering the normal direction at each pixel, creating the illusion of bumps and grooves without extra geometry. You can see this clearly by temporarily commenting out `displacementMap` and `displacementScale` — the surface will still appear detailed thanks to the normal map alone.

`normalScale` is a `THREE.Vector2` instance, set via `material.normalScale.set(x, y)`. Both values typically match (e.g. `0.5, 0.5`). Lower values make the effect subtler; higher values exaggerate it.

### Alpha Map (`alphaMap`)

An alpha map controls per-pixel transparency. Black parts of the texture become transparent, white parts remain visible. **Critical**: you must set `material.transparent = true` for alpha maps to work — without it, the alpha map is ignored entirely.

### Environment Map Recap

The HDR environment map loaded via `HDRLoader` from the previous lesson (`10.9_mesh-standard-material-part-two`) provides both the scene background and the lighting for the standard material. The `EquirectangularReflectionMapping` on the HDR texture tells Three.js how to interpret the equirectangular projection for reflections.

## Code

in repo - `apps/10_10_MeshStandardMaterial_part_three`

```ts
// Load all door textures
const doorAlbedoTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_basecolor.jpg');
const doorAmbientOcclusionTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_ambientOcclusion.jpg');
const doorHeightTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_height.png');
const doorNormalTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_normal.jpg');
const doorMetalnessTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_metallic.jpg');
const doorRoughnessTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_roughness.jpg');
const doorAlphaTexture = textureLoader.load('/textures/wooden_door/Door_Wood_001_opacity.jpg');

// Color space for correct color interpretation
doorAlbedoTexture.colorSpace = THREE.SRGBColorSpace;

// Create material with all maps
const material = new THREE.MeshStandardMaterial();
material.map = doorAlbedoTexture;
material.aoMap = doorAmbientOcclusionTexture;
material.aoMapIntensity = 1;
material.displacementMap = doorHeightTexture;
material.displacementScale = 0.08;
material.metalness = 1;
material.roughness = 1;
material.metalnessMap = doorMetalnessTexture;
material.roughnessMap = doorRoughnessTexture;
material.normalMap = doorNormalTexture;
material.normalScale.set(0.5, 0.5);
material.transparent = true;
material.alphaMap = doorAlphaTexture;

// High subdivision geometry for displacement to work properly
const sphereGeometry = new THREE.SphereGeometry(0.5, 64, 64);
const torusGeometry = new THREE.TorusGeometry(0.3, 0.2, 64, 128);
const planeGeometry = new THREE.PlaneGeometry(1, 1, 100, 100);
```

## Gotchas

- **`transparent: true` is required for `alphaMap`** — without it, the alpha map is completely ignored. The white areas of the texture will show as solid white instead of being invisible.
- **Low subdivisions break `displacementMap`** — if your sphere has 16 segments and you apply a height texture, vertices will be displaced from too few points, creating a stretched, broken appearance. Increase segments (e.g. 64×64) for smooth displacement. The GUI in this app lets you experiment with segment counts to see this.
- **`displacementScale` needs to be small** — values like `0.08` are typical. Large values (e.g. `1.0`) will push vertices far from their original position and look broken.
- **`colorSpace` on albedo texture** — forgetting `doorAlbedoTexture.colorSpace = THREE.SRGBColorSpace` makes the texture appear lighter or washed out. This is easy to overlook because the default (`NoColorSpace`) still renders something that looks reasonable.
- **`normalScale` is a `Vector2`** — use `.set(x, y)` not a single number. Both values should typically match.

## Revisit

- Experiment with lowering geometry segments via the GUI while watching displacement — switch to wireframe mode to really see how subdivisions affect displacement quality
- Try commenting out `displacementMap` while keeping `normalMap` — notice that surface detail persists even without vertex displacement
- Explore different `displacementScale` values to find the sweet spot for your height texture
- Compare `colorSpace = THREE.SRGBColorSpace` vs leaving it at default on the albedo texture to see the visual difference
