## Concept

This lesson builds on [[4.3_camera-mousemove]] to focus specifically on **how mouse coordinates get normalized and mapped to camera position** — the math behind making the camera follow your cursor.

### Mouse Coordinate Normalization

When you move your mouse, the browser gives you pixel coordinates via `event.clientX` and `event.clientY`. These values range from `0` to the canvas dimensions (e.g. `0` to `800` for width). But Three.js works in world units, not pixels — so we need to **normalize** the mouse position.

The normalization formula used here:

```ts
cursor.x = ev.clientX / sizes.width - 0.5;   // range: [-0.5, 0.5]
cursor.y = 0.5 - ev.clientY / sizes.height;   // range: [-0.5, 0.5]
```

Breaking it down:

1. **Divide by canvas size** → maps pixel coordinates to `[0, 1]` range
2. **Subtract 0.5** → shifts the range to `[-0.5, 0.5]`, so the center of the screen is `0`

This gives you a symmetric range where:
- Left edge = `-0.5`, right edge = `+0.5`
- Top edge = `+0.5`, bottom edge = `-0.5`

### Y-Axis Inversion

Notice the Y formula is `0.5 - clientY / height`, not `clientY / height - 0.5`. This is because:

- **Browser coordinates**: `y = 0` is at the **top** of the screen, increases **downward**
- **Three.js coordinates**: `y = 0` is at the **center**, increases **upward**

The subtraction flips the axis so moving the mouse up gives a positive `cursor.y`, and moving down gives a negative `cursor.y` — matching Three.js's coordinate system.

### The Multiplier (Scaling Factor)

Once normalized, the cursor values are mapped to camera position by multiplying:

```ts
camera.position.x = cursor.x * 4;
camera.position.y = cursor.y * 4;
```

The `4` here is a **scaling factor** that controls how far the camera travels from the center. Since `cursor.x` ranges from `-0.5` to `+0.5`, multiplying by `4` gives a camera travel range of `-2` to `+2` world units. A larger number means the camera moves further; a smaller number keeps it tighter.

This is the key insight: **normalization gives you a predictable [-0.5, 0.5] range, and the multiplier converts that to whatever world-space range you want**.

### Why This Works as Camera Control

The camera's position is updated every frame in the animation loop (`tick`). As the mouse moves, `cursor.x` and `cursor.y` update, and on the next frame the camera snaps to the new position. The result is the camera continuously tracking your cursor position — a simple but effective interactive camera.

Note that `camera.lookAt(mesh.position)` is commented out in this version. Without it, the camera only **translates** (shifts position) but doesn't **rotate** to face the object. If you uncomment it, the camera will both move and rotate to keep looking at the box.

## Code

in repo - `apps/4_camera_move`

```ts
const cursor = { x: 0, y: 0 };

window.addEventListener('mousemove', (ev) => {
  cursor.x = ev.clientX / sizes.width - 0.5;
  cursor.y = 0.5 - ev.clientY / sizes.height;
});

function tick(timestamp: number) {
  camera.position.x = cursor.x * 4;
  camera.position.y = cursor.y * 4;
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
```

## Gotchas

- **Y-axis inversion** — the most common mistake. If you use `clientY / height - 0.5` instead of `0.5 - clientY / height`, the camera will move *opposite* to your mouse on the vertical axis.

- **Multiplier is arbitrary** — the `4` in `cursor.x * 4` has no special meaning. It's a hand-tuned value that felt right. Different values will give different travel ranges — try changing it to `2` or `8` to see the effect.

- **Camera doesn't face the object** — with `camera.lookAt()` commented out, the camera slides around but always faces the same direction. It's like moving your head side to side without turning it. Uncomment `camera.lookAt(mesh.position)` to make the camera track the object.

- **Canvas size is hardcoded** — the `sizes` object uses fixed `800x600`. If you resize the browser window, the normalization breaks because the cursor division uses the wrong denominator. A real app would use `window.innerWidth` / `window.innerHeight` and update on resize.

## Revisit

- **Smooth camera movement** — right now the camera snaps instantly to the cursor position. Try adding lerp (linear interpolation) to smooth it out: `camera.position.x += (targetX - camera.position.x) * 0.1`

- **OrbitControls** — Three.js provides `OrbitControls` which handles rotation, zoom, and panning out of the box. It's the standard way to do camera control — worth comparing to this manual approach.

- **Different scaling factors** — try varying the multiplier or making it responsive to window size
