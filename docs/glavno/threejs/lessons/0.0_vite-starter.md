# 0.0 vite-starter

> This is the starter template for all Three.js apps in this repo, using Vite + vanilla Three.js with a WebGL renderer.

## Concept

Every Three.js scene follows a strict rendering pipeline — each step depends on the previous one. This app demonstrates the absolute minimum to get a shape on screen, in the correct order.

### Rendering Order

1. **Canvas** — an HTML `<canvas>` element is the target for rendering. Three.js needs this to create a WebGL context.
2. **Scene** — a `THREE.Scene()` is the container for everything you want to render: meshes, lights, cameras, helpers.
3. **Geometry** — defines the shape of a 3D object (vertices, edges, faces). Here a `BoxGeometry` is used.
4. **Material** — defines how the surface looks (color, texture, lighting response). Here a `MeshBasicMaterial` is used — it doesn't react to lights, so it's the simplest option.
5. **Mesh** — combines geometry + material into a single object that can be positioned in the scene.
6. **Camera** — a `PerspectiveCamera` defines the viewpoint. You set the field of view (75°) and aspect ratio, then position it (`camera.position.z = 3` moves it back from the origin).
7. **Axes Helper** — a debug tool (`AxesHelper`) that draws colored lines for X (red), Y (green), Z (blue) axes. Useful for understanding orientation.
8. **Renderer** — `WebGLRenderer` takes the canvas element, then renders the scene from the camera's perspective with `renderer.render(scene, camera)`.

### Dependencies

- **three** — the Three.js core library
- **vite** — dev server and bundler
- **@td/ts-config**, **@td/lint-config** — shared workspace configs for TypeScript and ESLint

## Code

in repo - `apps/0_vite_starter`

```ts
// 1 - Canvas element
const canvas: HTMLCanvasElement | null =
    document.querySelector('canvas#tride');

if (!canvas) throw new Error('Canvas element is missing!');

const sizes = { width: 800, height: 600 };

// 2 - Scene
const scene = new THREE.Scene();

// 3 - Geometry and Material
const boxGeometry = new THREE.BoxGeometry(1, 1, 1);
const material = new THREE.MeshBasicMaterial({ color: 0x4c9892 });

// 4 - Mesh
const mesh = new THREE.Mesh(boxGeometry, material);
scene.add(mesh);

// 5 - Camera
const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height);
camera.position.z = 3;
camera.position.x = 0.5;
scene.add(camera);

// 6 - Renderer
const renderer = new THREE.WebGLRenderer({ canvas });
renderer.setSize(sizes.width, sizes.height);

// 7 - Axes Helper
const axesHelper = new THREE.AxesHelper(5);
axesHelper.setColors('red', 'green', 'blue');
scene.add(axesHelper);

// 8 - Render
renderer.render(scene, camera);
```

## Gotchas

- The canvas element must exist in the HTML before the script runs — the querySelector will return null otherwise. The check `if (!canvas) throw` is essential.
- `PerspectiveCamera` needs an aspect ratio (`width / height`), not just a single number — passing only the FOV will break the projection.
- `MeshBasicMaterial` does not react to lights. If you later add lights and nothing changes on the material, this is why — switch to `MeshStandardMaterial` or similar.
- The camera's default position is at the origin (0, 0, 0), same as the mesh. Without moving the camera back (`position.z = 3`), the mesh would be inside the camera and invisible.

## Revisit

- Practice setting up a scene from scratch without referencing the template — understanding the order is more important than memorizing the code.
- Experiment with different geometries (`SphereGeometry`, `ConeGeometry`, etc.) and see how the same material + camera setup behaves.
- When ready, replace `WebGLRenderer` with `WebGPURenderer` — the setup is nearly identical but unlocks future capabilities.

## Outdated

This app uses a **WebGL renderer**, which is the legacy approach. Three.js now supports **WebGPU** as a more modern and performant alternative.

> 💡 More up to date alternative: `THREE.WebGPURenderer` — same API surface, better performance, and future-proof. See [Three.js WebGPU examples](https://threejs.org/examples/?renderer=webgpu) for migration examples.
