## Concept

In Three.js, every `Mesh` has a `.position` property — a `Vector3` that determines where the mesh sits in 3D space. Understanding `Vector3` is foundational to working with any 3D scene: it powers position, rotation, scale, and vector math throughout the engine.

### What is `position`?

`mesh.position` is a `THREE.Vector3` instance — an object with three numeric components: `x`, `y`, and `z`. Setting these moves the mesh in the scene:

```ts
mesh.position.x = 0.7;
mesh.position.y = 1;
mesh.position.z = -1;
```

The coordinate system follows the Three.js convention: **+x** is right, **+y** is up, **−z** is toward the camera (for a default setup).

### `position` is a `Vector3`

This is not just a data holder — `position` is a full `THREE.Vector3` instance, inheriting all its methods. You can verify this:

```ts
console.log(mesh.position instanceof THREE.Vector3); // true
```

This matters because every `Vector3` method is available on `.position`.

### Key `Vector3` methods

**`length()`** — returns the distance from the origin (0, 0, 0) to the vector:

```ts
console.log(mesh.position.length()); // e.g. 1.61...
```

**`distanceTo(vector)`** — distance between two `Vector3` instances:

```ts
console.log(mesh.position.distanceTo(new THREE.Vector3(5, 5, 5)));
```

**`normalize()`** — scales the vector so its length becomes exactly 1, while preserving direction. Imagine a line from the origin through your vector — `normalize()` slides the vector along that line until it's exactly 1 unit from the center:

```ts
mesh.position.normalize();
console.log(mesh.position.length()); // 1
```

**`setX(val)` / `setY(val)` / `setZ(val)`** — set individual components by name. These are functionally equivalent to direct assignment (`mesh.position.x = val`), but can be useful in method chaining or when working with callbacks.

**`set(x, y, z?)`** — set all three components at once. The `z` parameter is optional and defaults to 0:

```ts
mesh.position.set(1, 1);    // x=1, y=1, z=0
mesh.position.set(0.9, -0.3, 1.2); // x=0.9, y=-0.3, z=1.2
```

### Direct assignment is not stateful

A critical detail: direct assignment **overwrites** the previous value, it doesn't add to it:

```ts
mesh.position.x = 0.7;
mesh.position.x = 0.8; // now x is 0.8, not 1.5
```

This is different from methods like `add()` which *do* modify in place (e.g. `mesh.position.add(new THREE.Vector3(1, 0, 0))` would add 1 to the current x).

## Code

in repo - `apps/2_transform_objects`

```ts
import * as THREE from 'three/webgpu';

const canvas = getRequiredElement<HTMLCanvasElement>('canvas#tride');

const sizes = { width: 800, height: 600 };

async function init() {
  const scene = new THREE.Scene();

  const boxGeometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
  const material = new THREE.MeshBasicMaterial({ color: 0x4c9892, wireframe: true });
  const mesh = new THREE.Mesh(boxGeometry, material);

  // Set position — each assignment overwrites, doesn't accumulate
  mesh.position.x = 0.7;
  mesh.position.z = -1;
  mesh.position.y = 1;

  // Useful Vector3 methods
  console.log(mesh.position.length());          // distance to origin
  console.log(mesh.position.distanceTo(new THREE.Vector3(5, 5, 5)));

  mesh.position.normalize();                    // length becomes 1
  console.log(mesh.position.length());          // 1

  // setX, set, and direct assignment
  mesh.position.setX(0.6);
  mesh.position.set(1, 1);                     // x=1, y=1, z=0
  mesh.position.set(0.9, -0.3, 1.2);

  scene.add(mesh);

  const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height);
  camera.position.z = 3;
  camera.position.y = 0.5;
  camera.position.x = 0.1;
  scene.add(camera);

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();

  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.setColors('red', 'green', 'blue');
  scene.add(axesHelper);

  renderer.setSize(sizes.width, sizes.height);
  renderer.setClearColor(0x000000, 1);
  renderer.render(scene, camera);
}

await init();
```

## Gotchas

- **`normalize()` is not stateful** — it replaces the vector's values with the normalized version. You can't "undo" it without saving the original length first. If you need the normalized direction without mutating, use `clone().normalize()`.

- **Direct assignment (`mesh.position.x = val`) overwrites, doesn't add** — this is the most common source of confusion. If you expect accumulation, use `position.x += val` or `position.add()` instead.

- **`set()` with two args defaults z to 0** — `mesh.position.set(1, 1)` is equivalent to `mesh.position.set(1, 1, 0)`. If you forgot that z is 0 by default, your object may appear in the wrong place.

- **`distanceTo()` takes a `Vector3`, not three numbers** — you can't call `distanceTo(x, y, z)`. You need `distanceTo(new THREE.Vector3(x, y, z))`.

## Revisit

- **Rotation and scale** — this lesson only covers position. `rotation` (Euler) and `scale` (Vector3) are the other two transform properties on a mesh. They use the same coordinate system but different math.
- **`position.add()` and `position.sub()`** — these modify the vector in place (unlike direct assignment). Worth practicing to understand when stateful vs non-stateful operations matter.
- **Matrix transforms** — under the hood, position/rotation/scale are composed into a 4×4 transformation matrix. Understanding `mesh.matrix` and `matrixWorld` comes later but builds directly on this lesson.
- **`Vector3` utility methods** — `cross()`, `dot()`, `lerp()`, `clamp()`, `reflect()` are all commonly used in 3D graphics. A good reference to have handy.
