## Concept

This lesson explores **animation using `THREE.Timer`** — a utility class in Three.js for tracking elapsed time with precision. Timer is preferred over Clock for most use cases because it handles timestamp normalization automatically, giving you clean elapsed time values without manual math.

### Timer vs Clock

`THREE.Timer` and `THREE.Clock` both track time, but Timer is more convenient:

- **Timer** — calls `update()` with the current timestamp, then `getElapsed()` returns seconds since the timer started (or since the last `update()`)
- **Clock** — uses `getDelta()` (time since last call) or `getElapsedTime()` (total time), but can have quirks with initial values

Timer's approach of explicitly passing the timestamp makes it more predictable.

### The requestAnimationFrame Loop

The animation loop uses `requestAnimationFrame(tick)` — this is **not** the same as calling `tick()` directly:

```ts
window.requestAnimationFrame(tick);
```

- `requestAnimationFrame(callback)` tells the browser: "call `tick` on the next frame, and pass it the current high-resolution timestamp"
- Calling `tick()` directly would run once and stop — no animation
- The timestamp parameter is how `timer.update(timestamp)` gets the current time

The loop is self-sustaining: `tick()` calls `requestAnimationFrame(tick)` at the end, scheduling the next frame.

### Trigonometric Functions for Motion

The animation uses `Math.cos()` and `Math.sin()` to create circular motion:

```ts
camera.position.x = Math.cos(elapsedTime);    // horizontal orbit
mesh.position.y = Math.sin(elapsedTime);      // vertical bob
```

- `sin` and `oscillate between -1 and 1` — perfect for smooth back-and-forth motion
- `cos` is just `sin` shifted by 90 degrees — combining them creates circular paths
- `Math.PI * 0.2` scales the rotation speed (0.2 revolutions per second)

## Code

in repo — `apps/3_animation_timer`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

async function init() {
  const scene = new THREE.Scene();

  const boxGeometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
  const material = new THREE.MeshBasicMaterial({
    color: 0x4c9892,
    wireframe: true,
  });
  const mesh = new THREE.Mesh(boxGeometry, material);
  mesh.position.x = -0.5;
  mesh.position.z = 0.5;
  scene.add(mesh);

  const camera = new THREE.PerspectiveCamera(75, 800 / 600);
  camera.position.set(0.1, 0.5, 3);
  scene.add(camera);

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();
  renderer.setSize(800, 600);
  renderer.setClearColor(0x000000, 1);
  renderer.render(scene, camera);

  // Timer tracks elapsed time
  const timer = new THREE.Timer();

  // Start the animation loop — tick receives the high-res timestamp
  window.requestAnimationFrame(tick);

  function tick(timestamp: number) {
    // Update timer with the browser-provided timestamp
    timer.update(timestamp);
    const elapsedTime = timer.getElapsed();

    // Trig for circular motion
    mesh.rotation.y = elapsedTime * Math.PI * 0.2;
    camera.position.x = Math.cos(elapsedTime);
    mesh.position.y = Math.sin(elapsedTime);

    camera.lookAt(mesh.position);
    renderer.render(scene, camera);

    // Schedule the next frame
    window.requestAnimationFrame(tick);
  }
}

await init();
```

## Gotchas

- **Don't call `tick()` directly** — it won't animate. Always use `requestAnimationFrame(tick)` so the browser controls timing
- **Timer requires explicit `update()`** — unlike Clock which auto-updates, Timer needs `timer.update(timestamp)` each frame
- **The timestamp comes from requestAnimationFrame** — don't pass `Date.now()` or `performance.now()` to `timer.update()`, use the parameter that `requestAnimationFrame` provides
- **WebGPU renderer needs `await renderer.init()`** — this is async, unlike WebGL renderer

## Revisit

- Try swapping Timer for Clock and notice the difference in API
- Experiment with different trig functions: `Math.tan()`, `Math.abs(Math.sin())` for different motion patterns
- Look into `THREE.MathUtils` for easing functions and interpolation helpers
