# 7.7 — GUI Folders

## Concept

When your lil-gui panel grows beyond a handful of controls, a flat list becomes hard to navigate. [lil-gui](https://lil-gui.docs.pmnd.rs/) supports **folders** — collapsible groups that keep related controls together.

### Creating a folder

```ts
const cubeTweaks = gui.addFolder('Awesome cube');
```

This returns a `GUI` instance scoped to that folder. All `.add()` and `.addColor()` calls on it go inside the folder, not at the root level.

### Closing by default

Folders can start collapsed so the user only opens what they care about:

```ts
cubeTweaks.close();
```

### Nesting folders

Folders can contain other folders — useful when you have sub-groups of controls:

```ts
const subFolder = cubeTweaks.addFolder('Sub group');
subFolder.add(debugObject, 'myStupidProp');
```

### Control types inside a folder

This app demonstrates every common lil-gui control type wired to a Three.js scene:

| Control | Code | What it does |
|---|---|---|
| **Slider** | `.add(object, 'prop').min(-3).max(3).step(0.01)` | Continuous numeric value |
| **Checkbox** | `.add(object, 'visible')` | Boolean on/off |
| **Dropdown** | `.add(object, 'prop', { option1: val1, option2: val2 })` | Enum selection from a map |
| **Button** | `.add(object, 'functionName')` | Calls the function on click |
| **Color picker** | `.addColor(object, 'color')` | Opens a color wheel; use `.onChange()` to sync back |
| **Finish callback** | `.onFinishChange(fn)` | Fires only when the user releases the handle — good for expensive operations like rebuilding geometry |

The `onFinishChange` callback is particularly useful for operations that are too heavy to run on every drag tick — like rebuilding a `BoxGeometry` with new subdivision counts:

```ts
cubeTweaks
  .add(debugObject, 'subdivisions')
  .min(1)
  .max(20)
  .step(1)
  .onFinishChange((subdivs: number) => {
    boxGeometry.dispose();
    boxMesh.geometry = new THREE.BoxGeometry(1, 1, 1, subdivs, subdivs, subdivs);
    boxGeometry = boxMesh.geometry;
  });
```

```ts
import { OrbitControls } from 'three/examples/jsm/Addons.js';

const debugObject = {
  color: '#527eaa',
  spin: () => {},
  lookAtMesh: false,
  subdivisions: 2,
  speed: 2,
};

// Slider
cubeTweaks.add(boxMesh.position, 'y').min(-3).max(3).step(0.01).name('boxMesh.position.y');

// Checkbox
cubeTweaks.add(boxMesh, 'visible').name('boxMesh visible');

// Dropdown
cubeTweaks.add(debugObject, 'speed', { sporo: 2, brzo: 8 });

// Button
cubeTweaks.add(debugObject, 'spin');

// Color picker with onChange
cubeTweaks
  .addColor(debugObject, 'color')
  .onChange((colorVal: THREE.Color) => {
    material.color.set(colorVal);
  });

// Geometry rebuild on finish
cubeTweaks
  .add(debugObject, 'subdivisions')
  .min(1)
  .max(20)
  .step(1)
  .onFinishChange((subdivs: number) => {
    boxGeometry.dispose();
    boxMesh.geometry = new THREE.BoxGeometry(1, 1, 1, subdivs, subdivs, subdivs);
    boxGeometry = boxMesh.geometry;
  });
```

## Gotchas

- **Disposing geometry**: When replacing geometry (like the subdivision tweak), always call `.dispose()` on the old geometry first to avoid [GPU memory leaks](https://threejs.org/docs/#api/en/core/Object3D.dispose). Forgetting this leaks buffers on every tweak.
- **`onChange` vs `onFinishChange`**: `onChange` fires on every drag tick — fine for lightweight updates (color, visibility). Use `onFinishChange` for expensive operations (geometry rebuilds, texture loading) to avoid lag.
- **`.name()` for labels**: Without `.name()`, the control shows the raw property path (e.g. `boxMesh.position.y`). Use `.name()` for cleaner labels.

## Revisit

- Practice organizing a larger GUI with multiple nested folders — grouping by mesh, by camera, by lighting, etc.
- Consider using a `debugObject` pattern consistently across projects so all tweakable state lives in one place.
- Look into lil-gui's `.title()` method for customizing folder header text.
