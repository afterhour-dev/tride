# Hemisphere Light

Exploring `HemisphereLight` — three.js's two-color ambient light that simulates the sky above and the ground below, so surfaces get a gradient between two colors depending on their orientation.

## Concept

![[hemisphere.png]]

A `HemisphereLight` sits conceptually between `AmbientLight` and `DirectionalLight`. Like an ambient light it illuminates from **everywhere** — there's no single source point you can see. But unlike a pure ambient light (which tints the whole scene one uniform color), a hemisphere light splits the world into two halves:

- **The sky (up)** — light coming from above.
- **The ground (down)** — light bounced back up from below.

Every surface picks up the color that matches the direction it faces: a surface pointing **up** gets the sky color, a surface pointing **down** gets the ground color (via `groundColor`), and surfaces oriented in between receive a **blend of the two**. This is much cheaper and more natural than the uniform gray of ambient light, because it conveys a sense of "there is a bright sky and a darker ground" — a very common real-world lighting situation.

**Would look cool in the scene where you would have grass on the ground where you would define groundColor as green and sky color as blue.**

### The three properties

- **`color`** — the light coming from the sky/above (default `0xffffff`, white).
- **`groundColor`** — the light coming from the ground/below (default `0xffffff`).
- **`intensity`** — overall brightness (default `1`).

There's an important naming quirk: the **first constructor argument is called `skyColor`**, not `color`. In the docs you'll see:

```ts
new THREE.HemisphereLight(skyColor, groundColor, intensity)
```

So the argument is named `skyColor`, but there is **no property called `skyColor`** on the light — the property you set afterwards is `color`. That mismatch is exactly why the `// EXPLAIN` comment in the source calls out "explain arguments also."

You can pass all three at construction, or (as this app does) create an empty light and assign `.color`, `.groundColor`, and `.intensity` afterwards:

```ts
const hemisphereLight = new THREE.HemisphereLight();
hemisphereLight.color = new THREE.Color(0xff0000);    // red sky
hemisphereLight.groundColor = new THREE.Color(0x0000ff); // blue ground
hemisphereLight.intensity = 0.3;
scene.add(hemisphereLight);
```

### What you actually see

With `color = red` (sky) and `groundColor = blue` (ground):

- The **tops** of objects are tinted **red** — light from above.
- The **bottoms** and downward-facing surfaces are tinted **blue** — light from below.
- **In-between** orientations get a mix of red and blue, whichever way they lean.

That's the defining visual of a hemisphere light: instead of a uniform tint you get a directional gradient that makes the scene read as lit from above by a colored sky and reflected by a colored ground. This app's README describes exactly this — "purple illumination from the bottom and red illumination from the top; in between an object will get the mix between those colors" (red top + blue bottom visualizes as a purple blend in the middle).

### Why it doesn't read clearly until you isolate it

In the app, the ambient and directional lights exist too. Until you turn those off in the GUI, the hemisphere light's contribution is swamped — ambient fill and directional shading mask what the two hemisphere colors are doing. Once you **toggle ambient and directional off** (leave only hemisphere visible), the red-top / blue-bottom gradient becomes obvious. This is the README's key gotcha: you won't see how the hemisphere light is applied until the other lights are out of the way.

### Illumination everywhere, including crevices

Because the hemisphere light illuminates from all directions (not a single point), there's light hitting **every** surface orientation — including inward-facing and recessed areas. So yes, unlike a directional light, crevices and sides of objects get illuminated (with the appropriate sky-or-ground color for their facing). It's still a cheap approximation of real bounced light, not a true global-illumination solution.

## Code

in repo - `apps/12_3_hemisphere_light`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

async function init() {
  const scene = new THREE.Scene();

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();

  // Ambient and directional lights exist, but are hidden (visible = false)
  // so the hemisphere light's two colors show clearly.
  const ambientLight = new THREE.AmbientLight();
  ambientLight.color = new THREE.Color(0xffffff);
  ambientLight.intensity = 0.5;
  ambientLight.visible = false;
  scene.add(ambientLight);

  const directionalLight = new THREE.DirectionalLight(0x00fffc, 0.3);
  directionalLight.position.set(1, 0.25, 0);
  directionalLight.visible = false;
  scene.add(directionalLight);

  // Hemisphere light — red from the sky, blue from the ground.
  const hemisphereLight = new THREE.HemisphereLight();
  hemisphereLight.color = new THREE.Color(0xff0000);      // sky
  hemisphereLight.groundColor = new THREE.Color(0x0000ff); // ground
  hemisphereLight.intensity = 0.3;
  scene.add(hemisphereLight);

  // MeshStandardMaterial needs lights to be visible
  const material = new THREE.MeshStandardMaterial();
  material.roughness = 0.4;

  const box = new THREE.Mesh(new THREE.BoxGeometry(0.75, 0.75, 0.75), material);
  const torus = new THREE.Mesh(new THREE.TorusGeometry(0.3, 0.2, 32, 64), material);
  torus.position.x = 1.5;
  const sphere = new THREE.Mesh(new THREE.SphereGeometry(0.5, 32, 32), material);
  sphere.position.x = -1.5;
  const floor = new THREE.Mesh(new THREE.PlaneGeometry(5, 5), material);
  floor.rotation.x = -Math.PI / 2;
  floor.position.y = -0.65;

  scene.add(box, torus, sphere, floor);

  // Camera
  const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
  camera.position.set(2, 1, 1);
  scene.add(camera);

  // Render loop
  renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
  renderer.setSize(innerWidth, innerHeight);
  renderer.setAnimationLoop(() => {
    renderer.render(scene, camera);
  });
}

await init();
```

## Gotchas

- **There is no `skyColor` property.** The constructor's first argument is called `skyColor`, but the property you set afterwards is `color`. Trying `hemisphereLight.skyColor = ...` won't work — it's `hemisphereLight.color`. This naming mismatch between the argument and the property is easy to trip over.

- **You won't see the effect until the other lights are off.** The ambient and directional lights are still in the scene (just `visible = false`). If you forget to disable them in the GUI, the hemisphere light's red-top / blue-bottom gradient is swamped and you'll wonder why nothing changes. Isolate it first.

- **`MeshStandardMaterial` renders black without lights.** As in the previous lessons, standard/physical materials need at least one visible light source. The hemisphere light's `intensity = 0.3` is low, so expect a fairly dark scene once the other lights are hidden — that's normal for this setup's luminance.

- **`await renderer.init()` is mandatory for WebGPU.** The `WebGPURenderer` must finish async initialization before the first render, or you get a blank canvas.

- **Intensity in this app is clamped to `0–1`** in the lil-gui panel (`min(0)`, `max(1)`, `step(0.001)`). Values above `1` are possible in three.js but this GUI won't let you reach them — the effective visible range here is `0–1`.

## Revisit

- **Performance.** One of the README's open questions is how a hemisphere light compares performance-wise. It's extremely cheap — it's a constant-cost analytic ambient term, no shadow maps, no per-pixel ray work. Its cost is essentially the same as `AmbientLight` regardless of scene size. Worth internalizing that "fill lighting" of any kind is far cheaper than shadow-casting direct lights.

- **Illumination in crevices.** Confirm by inspecting the recessed/side areas of the torus and box in the app with only the hemisphere light on — light should still reach them (as sky or ground color), unlike a pure directional light which leaves back-facing sides dark. This is the README's "so we do have illumination from everywhere, also in the crevices?" question — yes, but it's a cheap approximation, not true GI.

- Combine a **`HemisphereLight` for the sky/ground ambient fill** with a **`DirectionalLight` for the sun** — the classic outdoor setup. A neutral gray-ish hemisphere light (e.g. light blue sky above, dark ground below) adds a natural brightness gradient that a single flat `AmbientLight` can't.

- Come back to this when doing **shadows**: hemisphere lights do not cast shadows (they're ambient), so any scene needing hard shadowed areas still needs a `DirectionalLight` or `SpotLight`.

## Outdated

Approach is valid — this is a current WebGPU-based Three.js setup using the recommended `WebGPURenderer` and PBR (`MeshStandardMaterial`). `HemisphereLight` remains a standard, supported light type. No parts are obsolete.
