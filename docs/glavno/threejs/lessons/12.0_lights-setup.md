# Lights Setup

A starter scene pre-configured with lights, materials, and helper objects — the foundation for upcoming lighting lessons.

## Concept

This app sets up a WebGPU-rendered scene with **two light sources** and **reactive materials**, ready to be expanded on in future lessons about lighting.

### Lights

Two light types are included as a baseline:

- **`AmbientLight`** — provides uniform, omnidirectional illumination across the entire scene. It simulates bounced light so that surfaces not facing any direct light source are not completely black. The intensity is set to `1.5`, which is bright enough to keep all faces visible.

- **`PointLight`** — emits light from a single point in all directions, like a bare light bulb. It is positioned at `(2, 3, 4)`, on the **same side as the camera** so the effect of its emanation onto the objects is clearly visible. The intensity is set to `50` (Three.js WebGPU units).

### Material

A single `MeshStandardMaterial` with `roughness = 0.4` is used for all objects. This is a [physically-based material](https://threejs.org/docs/#api/en/materials/MeshStandardMaterial) that responds to lights. Without any light source, `MeshStandardMaterial` surfaces would appear completely black — it depends on lights to be visible.

The roughness value of `0.4` is a deliberate starting point for exploring lighting: low enough to show specular highlights clearly, high enough to still have diffuse shading. As you adjust lights in later lessons, this roughness makes the interplay between diffuse and specular easy to observe.

### Geometry & Layout

Four objects demonstrate how light interacts with different shapes:

- **Box** (`0.75 × 0.75 × 0.75`) — flat faces show uniform lighting per face
- **Torus** (radius `0.3`, tube `0.2`) — curved surface with inner and outer faces
- **Sphere** (`radius 0.5`) — smooth gradient from lit to shadowed side
- **Floor** (`5 × 5` plane, rotated `-90°` on X) — a surface for the objects to cast onto

All meshes rotate slowly in the animation loop (`0.1` on Y, `0.15` on X) so the lighting effect can be observed from changing angles.

### Other Setup

- **WebGPU Renderer** via `three/webgpu` with `await renderer.init()`
- **OrbitControls** with damping for free camera movement
- **AxesHelper** (toggled via GUI) for spatial reference
- **lil-gui** panel with `h` key toggle for quick debugging
- Resize listener and fullscreen toggle (double-click)

## Code

in repo - `apps/12_0_lights_setup`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

async function init() {
  const scene = new THREE.Scene();

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();

  // Lights
  const ambientLight = new THREE.AmbientLight(0xffffff, 1.5);
  scene.add(ambientLight);

  const pointLight = new THREE.PointLight(0xffffff, 50);
  pointLight.position.set(2, 3, 4);
  scene.add(pointLight);

  // Material — responds to lights
  const material = new THREE.MeshStandardMaterial();
  material.roughness = 0.4;

  // Meshes
  const boxMesh = new THREE.Mesh(new THREE.BoxGeometry(0.75, 0.75, 0.75), material);
  const sphereMesh = new THREE.Mesh(new THREE.SphereGeometry(0.5, 32, 32), material);
  sphereMesh.position.x = -1.5;

  scene.add(boxMesh, sphereMesh);

  // Camera
  const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
  camera.position.set(2, 1, 1);
  scene.add(camera);

  const controls = new OrbitControls(camera, canvas);
  controls.enableDamping = true;

  renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
  renderer.setSize(innerWidth, innerHeight);

  // Render loop
  renderer.setAnimationLoop((timestamp) => {
    controls.update();
    boxMesh.rotation.y = timestamp * 0.0001;
    renderer.render(scene, camera);
  });
}

await init();
```

## Gotchas

- **`MeshStandardMaterial` without lights = black.** Unlike `MeshBasicMaterial`, standard/physical materials require light sources to be visible. If you remove all lights, objects disappear into the background.

- **`await renderer.init()` is mandatory for WebGPU.** The WebGPU renderer needs an async initialization step before it can render. Forgetting this will throw or produce a blank canvas.

- **Point light intensity units differ between WebGL and WebGPU.** Three.js WebGPU uses physically-correct lighting units by default, so intensity values like `50` for a `PointLight` are expected — they would look drastically different (over-bright) on the legacy WebGL renderer.

- **Roughness and metalness are the two key levers for PBR.** Roughness `0` = mirror-smooth, `1` = fully diffuse. Metalness `0` = dielectric (plastic-like), `1` = metallic. The combination of these two values defines the visual character of the surface.

## Revisit

- The ambient + point light combo is intentionally minimal. Future lessons will introduce directional lights, spotlights, hemisphere lights, and area lights — revisit this starter each time to compare how different light types affect the same scene.

- Experiment with moving the point light around the scene (use lil-gui to tweak `pointLight.position`) to observe how light falloff and surface angle interact.

- Try swapping `MeshStandardMaterial` for `MeshPhysicalMaterial` and adjusting `clearcoat`, `sheen`, or `transmission` to see advanced light interactions on the same geometry.
