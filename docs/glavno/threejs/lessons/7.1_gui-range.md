# GUI Range

A focused deep-dive into the **range (slider) control** in [lil-gui](https://lil-gui.georgealways.com/), following the broader introduction in [[7.0_debug-ui]].

## Concept

### What is a Range Control?

A range control is a slider that lets you tweak a numeric value between a minimum and maximum, with an optional step increment. In lil-gui, it's the default control type created when you call `.add()` with a numeric property.

### Two Ways to Create a Range

lil-gui supports both **positional parameters** and **chaining** — but chaining is strongly preferred:

```ts
// Positional style — less readable, harder to maintain
gui.add(boxMesh.position, 'y', -3, 3, 0.01);

// Chaining style — each method speaks for itself
gui
  .add(boxMesh.position, 'y')
  .min(-3)
  .max(3)
  .step(0.01)
  .name('boxMesh.position.y');
```

**Why chaining is better:** With positional args, `gui.add(obj, 'y', -3, 3, 0.01)` — you have to remember what each number means. With chaining, `.min(-3).max(3).step(0.01)` is self-documenting. You can also skip a method — e.g. omit `.step()` if the default is fine — without worrying about argument position.

### The `.name()` Method

By default, lil-gui uses the property name as the label. `.name()` lets you override it:

```ts
gui.add(boxMesh.position, 'y').name('boxMesh.position.y');
// vs without .name() — it would show "y"
```

### Plain Variables vs Objects

lil-gui binds to **object properties**, not plain variables:

```ts
// ❌ This doesn't work — no property name to bind to
let myVariable = 256;
gui.add(myVariable, "???");

// ✅ Wrap in an object
const myObject = {
  myStupidProp: 256,
};
gui.add(myObject, 'myStupidProp');
```

This is the same `debugObject` pattern from [[7.0_debug-ui]] — you need a named property that lil-gui can read and write to.

### Why lil-gui Can't Use Plain Variables

lil-gui works by **reading and writing object properties**. When you call `gui.add(obj, 'prop')`, it stores a reference to `obj.prop`. As the user drags the slider, lil-gui updates `obj.prop` in real time — Three.js (or your code) reads that property on the next frame and the scene updates. A plain variable like `let myVariable = 256` has no object wrapper, so lil-gui has nowhere to write the updated value.

## Code

in repo - `apps/7_gui_range`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';

const canvas = getRequiredElement<HTMLCanvasElement>('canvas#tride');
const gui = new GUI();

const sizes = {
  width: window.innerWidth,
  height: window.innerHeight,
};

async function init() {
  const scene = new THREE.Scene();

  // Geometry + Material + Mesh
  const boxGeometry = new THREE.BoxGeometry(1, 1, 1, 2, 2, 2);
  const material = new THREE.MeshBasicMaterial({
    color: 0x4c9892,
    wireframe: true,
  });
  const boxMesh = new THREE.Mesh(boxGeometry, material);
  boxMesh.position.x = -1.5;
  boxMesh.position.z = 0.5;
  scene.add(boxMesh);

  // Range control — chaining style
  gui
    .add(boxMesh.position, 'y')
    .min(-3)
    .max(3)
    .step(0.01)
    .name('boxMesh.position.y');

  // Plain number via object wrapper
  const myObject = { myStupidProp: 256 };
  gui.add(myObject, 'myStupidProp');

  // Camera
  const camera = new THREE.PerspectiveCamera(
    75,
    sizes.width / sizes.height,
    0.1,
    100,
  );
  camera.position.set(1, 1.5, 3);
  scene.add(camera);

  // Orbit Controls
  const orbitControls = new OrbitControls(camera, canvas);
  orbitControls.enableDamping = true;

  // Renderer
  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  renderer.setSize(sizes.width, sizes.height);
  renderer.setClearColor(0x000000, 1);
  renderer.render(scene, camera);

  // Axes helper
  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.visible = false;
  scene.add(axesHelper);

  // Resize handler
  window.addEventListener('resize', () => {
    sizes.width = window.innerWidth;
    sizes.height = window.innerHeight;
    camera.aspect = sizes.width / sizes.height;
    camera.updateProjectionMatrix();
    renderer.setSize(sizes.width, sizes.height);
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  });

  // Fullscreen toggle
  window.addEventListener('dblclick', () => {
    const fullScreenElement =
      // @ts-expect-error can't find it on document but it is there
      document.fullscreenElement || document.webkitExitFullscreenExit;

    if (!fullScreenElement) {
      if (canvas.requestFullscreen) {
        canvas.requestFullscreen();
      } else if (canvas.webkitRequestFullScreen) {
        // @ts-expect-error can't find it on document but it is there
        canvas.webkitRequestFullScreen();
      }
    } else {
      if (document.exitFullscreen) {
        document.exitFullscreen();
      } else if (document.webkitExitFullscreen) {
        document.webkitExitFullscreen();
      }
    }
  });

  // Animation loop
  const timer = new THREE.Timer();
  window.requestAnimationFrame(tick);

  function tick(timestamp: number) {
    timer.update(timestamp);
    orbitControls.update();
    renderer.render(scene, camera);
    window.requestAnimationFrame(tick);
  }
}

await init();
```

## Gotchas

- **Plain variables can't be GUI-tweaked** — `gui.add(myVariable, "???")` has no property name to bind to. Always wrap in an object with a named property.

- **`onChange` fires on every pixel of drag** — If you attach expensive operations (geometry recreation, texture reloads) to `onChange`, the browser will freeze. Use `onFinishChange` for expensive work. For simple position/color tweaks, `onChange` is fine.

- **Range defaults** — If you omit `.min()`, `.max()`, or `.step()`, lil-gui uses defaults (step of `0.01` if omitted). This can lead to unexpected behavior if you expect integer steps.

## Revisit

- **The `debugObject` pattern** — This is a recurring pattern in Three.js debugging. Practice wrapping properties in an object before adding them to the GUI.
- **`onFinishChange` vs `onChange`** — Know when to use each. See the geometry tweaking pattern in [[7.0_debug-ui]] for a practical example.
- **Color handling** — Color tweaking has its own quirks due to Three.js color management. Covered in [[7.0_debug-ui]].

## Outdated

The approach is valid. lil-gui is lightweight, well-maintained, and purpose-built for this use case.
