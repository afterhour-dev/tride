# 10.4 MeshDepthMaterial + WebGPU

## Concept

`MeshDepthMaterial` renders objects based on their depth (distance from the camera). Objects closer to the camera appear darker, objects farther away appear lighter (or the reverse, depending on `depthPacking`). It's useful for depth-based effects like fog, depth-of-field, or shadow mapping — but it's not a material you'd typically use for visible surfaces in a scene.

### How depth materials work

1. For each pixel, the material calculates the object's distance from the camera.
2. That distance is mapped to a grayscale value — near = dark, far = light (by default).
3. The result is a grayscale image where brightness encodes depth.

This means:
- **No lighting needed** — like `MeshBasicMaterial`, it ignores lights entirely
- **Grayscale output** — the result is always black-to-white based on depth
- **Useful for post-processing** — often used as a render target for effects that need depth information

### The WebGPU compatibility problem

This is the key lesson here. When using `three/webgpu` with `WebGPURenderer`, creating a `MeshDepthMaterial` throws this error:

```
THREE.NodeBuilder: Material "MeshDepthMaterial" is not compatible.
```

**Why this happens:** WebGPU in Three.js uses a node-based material system. Legacy materials like `MeshDepthMaterial`, `MeshNormalMaterial`, and `MeshMatcapMaterial` were written for the older WebGL rendering pipeline. They haven't been ported to the node material system that WebGPU requires.

**Workarounds:**
- Use `WebGLRenderer` instead of `WebGPURenderer` for legacy materials
- Use `MeshStandardMaterial` or other PBR materials that have been ported to the node system
- For depth-based effects, consider using a depth render target or post-processing pass instead

> ⚠️ This is a known limitation of Three.js's WebGPU renderer. Check the [Three.js WebGPU roadmap](https://threejs.org/manual/#en/webgpu) for updates on which materials are supported.

in repo - `apps/10_4_MeshDepthMaterial`

```ts
import * as THREE from 'three/webgpu';

// ⚠️ This will throw an error with WebGPURenderer:
// "Material 'MeshDepthMaterial' is not compatible"
const material = new THREE.MeshDepthMaterial();

const boxMesh = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  material
);

const sphereMesh = new THREE.Mesh(
  new THREE.SphereGeometry(0.5, 16, 16),
  material
);

// The material renders depth as grayscale — closer = darker
// This works with WebGLRenderer, but not WebGPURenderer
```

## Gotchas

- **WebGPU doesn't support all legacy materials** — `MeshDepthMaterial`, `MeshNormalMaterial`, and `MeshMatcapMaterial` may throw `NodeBuilder` errors when used with `WebGPURenderer`. Check the [Three.js WebGPU compatibility table](https://threejs.org/docs/#api/en/materials/MeshDepthMaterial) before using these.
- **Depth materials are grayscale** — they don't produce "pretty" output by default. They're meant for technical purposes (depth buffers, post-processing), not for visual presentation.
- **`depthPacking`** — by default, depth is packed into the RGB channels. You can change this with the `depthPacking` property, but for most use cases the default is fine.

## Revisit

- If you need depth-based effects with WebGPU, look into `DepthTexture` and render targets instead of `MeshDepthMaterial`
- Explore how Three.js's built-in shadow system uses depth information internally
- Try switching to `WebGLRenderer` to see `MeshDepthMaterial` work correctly
- Check if Three.js has ported `MeshDepthMaterial` to the node material system in newer versions

## Outdated

**Partially outdated.** `MeshDepthMaterial` works fine with `WebGLRenderer`, but it's **not compatible with `WebGPURenderer`** as of Three.js r185. WebGPU uses a node-based material system, and legacy materials like `MeshDepthMaterial` haven't been ported yet.

> 💡 More up to date alternative: For depth-based effects in WebGPU, use `DepthTexture` with render targets or post-processing passes instead of `MeshDepthMaterial` directly.
