# 14.2 — Color, Map, AlphaMap, Blending for Particles

## Concept

In [14.0 particles webgl intro](14.0_particles-webgl-intro.md) and [14.1 particles custom geometry](14.1_particles-custom-geometry.md) we got a particle cloud rendering from a flat buffer of positions. That cloud was a spray of plain square points. This lesson is where particles start to look like **actual particles**: each point gets its own color, and the square is cut into a soft shape so the cloud reads as smoke, fire, sparks, glitter — instead of a grid of glowing rectangles.

The star of the show is `THREE.PointsMaterial`. Almost every idea in this lesson is one property on that material instance.

### `color` — the base color

`color` is the material's base color, settable right at instantiation:

```ts
const material = new THREE.PointsMaterial({
	color: new THREE.Color('#8c499a'),
});
```

or on the instance after creation:

```ts
material.color = new THREE.Color('#8c499a');
```

But here's the twist from the README: **if you also give each particle its own color through a vertex color attribute, the material `color` and the buffer colors blend**. That's why the sample leaves `color` commented out — once `vertexColors` is on, the base color just muddies the per-particle colors you actually want to see.

### `vertexColors` + the `color` buffer attribute — one color per particle

The geometry (not the material) carries per-particle colors. We add a second buffer alongside `position`:

```ts
const colors = new Float32Array(count * 3);
for (let i = 0; i < count * 3; i++) {
	colors[i] = Math.random();            // 0 .. 1 per RGB channel
}

geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3));
```

Same `count * 3` layout we already know from [14.1 particles custom geometry](14.1_particles-custom-geometry.md): three numbers — red, green, blue — per particle. Each channel is a float in `0 ... 1` (not `0 ... 255`).

On the material we must opt in:

```ts
particlesMaterial.vertexColors = true;
```

**Forgetting `vertexColors = true` is the classic miss** — the buffer is silently ignored and you get one flat color for the whole cloud.

### `map` vs `alphaMap` vs `transparent` — putting a shape on the point

By default a point is a **square** (or rectangle). Particles are rarely squares. There are two ways to give the point a non-rectangular shape, and both come from an image texture:

- **`map`** — an image whose **own transparency** cuts the shape. This is for textures that already carry an alpha channel (a PNG with real transparent pixels).
- **`alphaMap`** (`+ transparent`) — an image that is just **black and white, with no transparency baked in**. A white shape on black. When you set `transparent = true`, the black pixels become fully transparent.

The particle textures from the [Kenney particle pack](https://kenney.nl/assets/particle-pack) are black-and-white by design — a soft circle (like `circle_04.png`) is a white disc on black. The app loads one with `TextureLoader.load()` and applies it with:

```ts
particlesMaterial.transparent = true;
particlesMaterial.alphaMap = particleTexture;
```

So the rule of thumb:
- texture already has transparency baked in → use it as `map`.
- texture is black & white with no alpha → use it as `alphaMap` and flip `transparent = true`.

### The edge problem: WebGL has no idea which particle is in front

Cutting the square with `alphaMap` helps, but it is not a perfect fix. As you orbit, you'll catch faint edges or see particles pop. The README explains why: **particles are drawn in the order they were created, and WebGL doesn't know which one is actually in front of another**. When you look through a pile of semi-transparent points, the "back" ones' edges occasionally show.

The README walks through three knobs, each a partial fix:

1. **`alphaTest`** — a threshold in `0 ... 1` on the pixel's transparency. Any pixel whose alpha drops below it is not rendered. The app tried `material.alphaTest = 0.001`. Not perfect — with a static scene you can still sometimes catch an edge.
2. **`depthTest = false`** — WebGL normally skips drawing anything *behind* something already at that pixel (depth testing). Turning it off makes every particle render regardless of depth order. Works for a single-color cloud, but breaks when there are other objects in the scene or differently-colored particles — the README shows this by adding a cube.
3. **`depthWrite = false`** — instead of disabling the *test*, disable the *write*: particles still check the depth buffer, but they don't write themselves into it. The README calls this the best-looking of the three, but it too can create bugs.

The final honest summary: **there is no perfect solution — you pick the combination that fits the project.**

### `blending` — additive glow

By default WebGL just paints the new pixel *over* the one below. Set blending to `THREE.AdditiveBlending` (with `depthWrite = false` from above kept off) and instead of overwriting, the shader **adds** the pixel's color to what's already there. Overlapping particles accumulate toward white — that is how you get glow. The README warns **this costs performance**.

The cube observation is worth remembering: with additive blending, all particles show *behind* the cube while you orbit, even ones that are in front of the camera.

### Vertex colors + the cube

The cube experiment also reveals a deeper truth: deactivating depth test ("deactivating depth testing isn't ideal") behaves badly when objects or differently-colored particles mix. Closed-cube-and-glowing-cloud is exactly the kind of scene where these trade-offs collide.

## Code

in repo - `apps/14_2_particles_color_map_alpha_map`

```ts
import * as THREE from 'three';

const canvas = document.querySelector('canvas#tride')!;
const scene = new THREE.Scene();
const renderer = new THREE.WebGLRenderer({ canvas });

// -- load a black & white particle texture ------------------------------
const loadingManager = new THREE.LoadingManager();
const textureLoader = new THREE.TextureLoader(loadingManager);
const particleTexture = textureLoader.load('/textures/particles/circle_04.png');

// -- geometry: positions AND one color per particle ---------------------
const count = 20000;
const positions = new Float32Array(count * 3);
const colors = new Float32Array(count * 3);

for (let i = 0; i < count * 3; i++) {
	positions[i] = (Math.random() - 0.5) * 10; // -5 .. +5
	colors[i] = Math.random();                  // 0 .. 1 per channel
}

const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3));
geometry.setAttribute('color', new THREE.BufferAttribute(colors, 3));

// -- PointsMaterial: shape + per-particle color + blending ---------------
const material = new THREE.PointsMaterial();
material.vertexColors = true;        // opt-in to per-vertex color buffer
material.size = 0.1;
material.sizeAttenuation = true;
material.transparent = true;         // black & white texture -> transparency
material.alphaMap = particleTexture; // the shape, white on black
material.depthWrite = false;         // still tests depth, stops writing into it
material.blending = THREE.AdditiveBlending; // overlapping points add toward white

const particles = new THREE.Points(geometry, material);
scene.add(particles);

// -- camera + render loop ------------------------------------------------
const camera = new THREE.PerspectiveCamera(
	75,
	window.innerWidth / window.innerHeight,
	0.1,
	100,
);
camera.position.z = 3;
scene.add(camera);

renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.setClearColor(0x000000, 1);
renderer.render(scene, camera);
```

## Gotchas

- **`vertexColors = true` is easy to forget.** The `'color'` buffer attribute on the geometry is flat ignored unless the material has `vertexColors` on. You'll get one uniform color and no error.
- **`map` needs textures with baked-in transparency; `alphaMap` needs black & white with `transparent` on.** Use the wrong pairing and the square shows through, or the shape disappears.
- **Colors are floats `0..1`, not `0..255`.** `Math.random()` already lands in the right range; if you feed 8-bit channel values you'll clamp the cloud.
- **No single transparency fix is perfect.** `alphaTest`, `depthTest = false`, and `depthWrite = false` each trade off against ordering bugs with other objects or multi-color clouds. Plan to combine and test per project.
- **`AdditiveBlending` costs performance.** Overlapping glowing particles accumulate toward white; that's the effect you want, but it is not "free".
- **With additive blending, depth rendering behaves oddly with other meshes** — the cube shows every particle *behind* it regardless of camera position.
