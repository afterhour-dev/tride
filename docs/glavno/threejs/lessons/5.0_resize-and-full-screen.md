# Resize and Full Screen

When building Three.js applications, the canvas needs to adapt to the browser viewport. This lesson covers handling window resize, CSS setup, pixel ratio management, and the Fullscreen API.

## Concept

### CSS Setup

The canvas must fill the entire viewport without causing scrollbars. The key CSS properties are:

```css
canvas#tride {
  position: fixed;
  left: 0;
  top: 0;
  outline: none;
}

html, body {
  overflow: hidden;
}
```

- **`position: fixed`** — positions the canvas relative to the viewport, not the document flow
- **`overflow: hidden`** — prevents scrollbars when the canvas exceeds the viewport size

> 📝 The CSS is linked in `index.html` rather than imported in TypeScript — both approaches work in Vite, but linking in HTML is more explicit.

### Window Resize Handling

When the browser window resizes, we need to update three things:

1. **Canvas size** — `renderer.setSize()`
2. **Camera aspect ratio** — `camera.aspect`
3. **Camera projection matrix** — `camera.updateProjectionMatrix()`

```ts
window.addEventListener('resize', () => {
  // Update sizes
  sizes.width = window.innerWidth;
  sizes.height = window.innerHeight;

  // Update camera
  camera.aspect = sizes.width / sizes.height;
  camera.updateProjectionMatrix();

  // Update renderer
  renderer.setSize(sizes.width, sizes.height);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
});
```

**Why update the projection matrix?** The projection matrix defines how 3D coordinates map to 2D screen space. When the aspect ratio changes, the matrix must be recalculated to prevent stretching or squishing.

### Pixel Ratio

The device pixel ratio (DPR) determines how many physical pixels correspond to one CSS pixel. Higher DPR means sharper rendering but more GPU work.

```ts
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
```

- **Cap at 2** — most devices have DPR ≤ 2; higher values cause significant GPU load with minimal visual improvement
- **Set on resize** — some browsers change DPR when moving windows between monitors

### Fullscreen API

Double-click to enter/exit fullscreen using the Fullscreen API:

```ts
window.addEventListener('dblclick', () => {
  const fullScreenElement =
    // @ts-expect-error can't find it on document but it is there
    document.fullscreenElement || document.webkitExitFullscreenExit;

  if (!fullScreenElement) {
    if (canvas.requestFullscreen) {
      canvas.requestFullscreen();
    } else if (canvas.webkitRequestFullScreen) {
      // @ts-expect-error can't find it on document but it is there
      canvas.webkitRequestFullScreen();
    }
  } else {
    if (document.exitFullscreen) {
      document.exitFullscreen();
    } else if (document.webkitExitFullscreen) {
      document.exitFullscreen();
    }
  }
});
```

- **webkit prefixes** — Safari still requires `webkitRequestFullScreen` and `webkitExitFullscreen`
- **@ts-expect-error** — TypeScript doesn't include these vendor-prefixed methods in its type definitions

## Code

in repo - `apps/5_resize_and_full_screen`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

const sizes = {
  width: window.innerWidth,
  height: window.innerHeight,
};

async function init() {
  const scene = new THREE.Scene();
  const camera = new THREE.PerspectiveCamera(
    75,
    sizes.width / sizes.height,
    0.1,
    100,
  );
  camera.position.z = 3;

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  renderer.setSize(sizes.width, sizes.height);

  // Handle resize
  window.addEventListener('resize', () => {
    sizes.width = window.innerWidth;
    sizes.height = window.innerHeight;
    camera.aspect = sizes.width / sizes.height;
    camera.updateProjectionMatrix();
    renderer.setSize(sizes.width, sizes.height);
    renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  });

  // Handle fullscreen
  window.addEventListener('dblclick', () => {
    if (!document.fullscreenElement) {
      canvas.requestFullscreen();
    } else {
      document.exitFullscreen();
    }
  });

  function tick() {
    renderer.render(scene, camera);
    window.requestAnimationFrame(tick);
  }
  tick();
}

await init();
```

## Gotchas

- **Forgetting `updateProjectionMatrix()`** — resizing the renderer without updating the camera's projection matrix causes distorted proportions
- **Pixel ratio in resize handler** — some browsers change DPR when moving between monitors; always reset it on resize
- **webkit prefixes** — Safari requires `webkitRequestFullScreen` and `webkitExitFullscreen`; check for both standard and prefixed versions
- **CSS overflow** — without `overflow: hidden` on `html, body`, trackpad scrolling can cause unexpected behavior

## Revisit

- **Dual monitor setups** — different monitors may have different pixel ratios; test on your actual hardware
- **Stair effect (aliasing)** — on low DPR devices (DPR = 1), edges may appear jagged; this is normal and can be addressed with antialiasing
- **Fullscreen API changes** — the API is stable but vendor prefixes may evolve; check MDN periodically
