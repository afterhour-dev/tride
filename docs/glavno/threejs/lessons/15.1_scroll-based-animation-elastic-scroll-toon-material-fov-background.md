## Concept

This lesson is the **setup** for a scroll-based animation project: getting Three.js to coexist with real HTML content that scrolls. The goal isn't animation yet — it's a clean foundation where a fixed full-screen `<canvas>` renders a 3D scene behind normal scrolling HTML sections, with no visual glitches like a white flash or a bouncing "elastic scroll" edge.

### Fixed canvas + scrolling HTML

The idea is simple to state: the canvas is `position: fixed` (covering the whole viewport), and the scrolling happens in normal HTML content stacked above it. In CSS:

```css
canvas#tride {
	position: fixed;
	left: 0;
	top: 0;
	outline: none;
}

html, body {
	/* we enabled overflow. */
	/* overflow: hidden; */

}

html {
	/* EXPLAIN: we set up background color */
	background-color: var(--color-surfacebl-800);
}

* {
	margin:0; padding: 0;
}

/* .sekcija will be above canvas because both are positioned
which means they are not in normal flow of page anymore,
since .sekcija comes after as a sibling of canvas it goes on top
of him; we don't need to use z-index  */
section.sekcija {
	border: var(--color-information-500) solid 0px;
	position: relative;
	height: 100vh;
	color: var(--color-inkbl-200);
	/* this means depending of what is smaller -
	heigh or width of viewport, your font color will be 7% of that
	*/
	font-size: 7vmin;

	font-family: 'Manrope Variable', sans-serif;
	/* font-family: 'Bitter Variable', serif; */
	/* font-family: 'Fira Code Variable', monospace; */
	
	text-transform: uppercase;

	display: flex;
	align-items: center;

	padding-left: 10%;
	padding-right: 10%;
}

section.sekcija:nth-of-type(odd){
	justify-content: flex-end;
}
```

Each HTML section is one viewport tall (`height: 100vh`), so the page scrolls through a series of full-screen panels while the 3D scene stays glued behind them. This is the bridge between Three.js and the document scroll — later lessons will hook the scroll offset into the scene, but here we just make the coexistence clean.

### Fixing elastic scroll

When you scroll past the top or bottom of a page, some browsers/systems show a subtle elastic/stretch effect (the background lifts to reveal whatever is underneath). The default backdrop is **white**, which clashes with a dark 3D scene. Options to handle it:

1. Give the page `background-color` the same color as the renderer's clear color — quick, but couples the two.
2. **Make the clear color transparent** and let the HTML background show through. This is the approach taken here.

### Transparency of the clear color (WebGL vs WebGPU)

In WebGL, `WebGLRenderer` defaults to `alpha: false`, so the canvas is opaque until you opt in. You can get transparency in a few ways:

- `new THREE.WebGLRenderer({ alpha: true })` at construction.
- `renderer.setClearColor(color, 0)` — second argument is the alpha.
- `renderer.setClearAlpha(0)` — method to set just the alpha.

> 💡 In **WebGPU** (used here via `import * as THREE from 'three/webgpu'` and `WebGPURenderer`), the behavior is different. You are right — by default `WebGPURenderer` does **not** force an opaque clear. If you never set a clear color, the clear alpha stays at `0` (transparent) already. So no `alpha: true`, no `setClearColor`, no `setClearAlpha` needed — the page's `background-color` shows straight through. That's exactly why the constructor comment in the app says the line for `alpha: true` is unnecessary.

### `magFilter`, `NearestFilter`, and gradient maps

The `MeshToonMaterial` uses a `gradientMap` — a tiny texture (here `three-colors.jpg`) whose colors become the discrete shading steps of the toon look. By default a texture is filtered with linear interpolation (`LinearFilter`), which would **smooth** the boundaries between the color bands. Setting:

```ts
gradientTexture.magFilter = THREE.NearestFilter;
```

makes the sampler use the **nearest** texel, producing a **hard step** between colors instead of a gradual bleed. Even though the texture is small, without the `NearestFilter` the toon cells would blur into each other — the sharp cartoon bands are exactly what this flag produces. This is the `magFilter` (magnification filter, used when a texel covers more than a screen pixel).

### Field of view is vertical

In Three.js, `PerspectiveCamera`'s `fov` is measured **vertically** (the angle along the up-down axis), not horizontally. To feel this out the app places a torus at `y = 2`, a knot at `y = -2`, and a cone disabled. If you resize the browser window **vertically**, the scene stays fully visible — objects at the top and bottom don't get cut off; the vertical extent is content is preserved and the aspect ratio of the *scene* widens. If you shrink the window **horizontally**, the sides crop (like a vertical Sauron eye closing). This makes positioning objects along the vertical axis much easier and more predictable, because what you see up/down is tied to the fixed vertical angle, not the window's shape.

Tested by temporary moving objects by y in the scene, and resizing window vertically.

### Toon materials need light

Unlike `MeshBasicMaterial`, `MeshToonMaterial` (and other lit materials) need at least one light or they render black. The setup uses a single `MeshToonMaterial` for the torus, cone, and torus knot, each with its own color and the same gradient map, plus a GUI folder to tweak color and position per mesh.

## Code

in repo - `apps/15_1_scroll_based_animation_setup`

```ts
import * as THREE from 'three/webgpu';
import { getRequiredElement } from './util';

// Canvas + texture for the toon gradient map
const canvas = getRequiredElement<HTMLCanvasElement>('canvas#tride');
const gradientTexture = new THREE.TextureLoader().load(
	'textures/gradients/three-colors.jpg',
);
gradientTexture.magFilter = THREE.NearestFilter; // hard color steps

const sizes = { width: window.innerWidth, height: window.innerHeight };

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();

const scene = new THREE.Scene();

// Lights required by toon material
const light = new THREE.DirectionalLight();
light.intensity = 1 * Math.PI;
scene.add(light);

const torusMaterial = new THREE.MeshToonMaterial();
torusMaterial.gradientMap = gradientTexture;
const torus = new THREE.Mesh(new THREE.TorusGeometry(1, 0.4, 16, 60), torusMaterial);
scene.add(torus);

const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height, 0.1, 100);
camera.position.z = 3;
scene.add(camera);

renderer.setSize(sizes.width, sizes.height);
renderer.render(scene, camera);

// Growing infrastructure: full-screen, resize, double-click fullscreen
window.addEventListener('resize', () => {
	sizes.width = window.innerWidth;
	sizes.height = window.innerHeight;
	camera.aspect = sizes.width / sizes.height;
	camera.updateProjectionMatrix();
	renderer.setSize(sizes.width, sizes.height);
});
```

## Gotchas

- **Transparency is the wrong layer for the HTML backdrop** — that's `html, body { background-color: ... }`. The canvas is fixed and transparent as transport; it shows CSS through. Get the styles wrong and you get a white flash instead.
- **Forgetting `gradientMap`'s filter** gives smooth, muddy toon cells instead of crisp cartoon bands. `NearestFilter` on a small texture is the sharpness lever.
- **Toon without lights** renders black. `MeshToonMaterial` is lit; a `DirectionalLight` is a minimal setup.
- **Vertical vs horizontal resize mixup** — resizing horizontally changes what's visible (crops view); resizing vertically preserves the top/bottom instead. It's the fov axis, not the canvas, that defines what objects stay in shot.

## Revisit

- The elastic (overscroll) behavior really is device/browser specific — `overscroll-behavior` in CSS is the standard cross-scrolling control if you want to lock it, worth testing on trackpads and touch devices.
- The exact set of clear-color/transparency knobs (`alpha`, `setClearColor(color, alpha)`, `setClearAlpha`) is worth one careful pass in WebGL to compare against the WebGPU default, rather than trusting memory.
- In the follow-up lessons, hooking the scroll offset into the animation loop is the next step.

## Outdated

approach is valid

The scroll-based technique (fixed canvas + scrolling HTML content) remains a current, widely used pattern. The subtlety here is the **renderer API**: this project uses the modern `three/webgpu` import with `WebGPURenderer`. If you were doing this in the classic WebGL path, `new THREE.WebGLRenderer({ alpha: true })` and `setClearColor` behave differently — the WebGPU transparent-by-default clear is the cleaner path and this is the way the WebGPU-first Three.js tool is moving.
