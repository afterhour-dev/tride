## Concept

This lesson builds on cursor-based camera movement from the previous lesson and adds **circular orbital motion** using trigonometry. Instead of moving the camera in a straight line as the mouse moves left/right, the camera now travels along a circular arc around the scene's center.

### The core idea: sin and cos for circles

On the [unit circle](https://en.wikipedia.org/wiki/Trigonometric_functions#Right-angled_triangle_definitions), any point on the circle can be described by:

$$x = \cos(\theta)$$
$$z = \sin(\theta)$$

where $\theta$ is the angle in radians. As $\theta$ goes from $0$ to $2\pi$, the point traces a full circle. This is the foundation for circular motion in games, simulations, and 3D scenes.

### How cursor input maps to circular motion

The mouse position is normalized to a range of $[-0.5, 0.5]$:

```ts
cursor.x = ev.clientX / sizes.width - 0.5;   // [-0.5, 0.5]
cursor.y = 0.5 - ev.clientY / sizes.height;   // [-0.5, 0.5] (Y inverted)
```

Then in the animation loop:

```ts
camera.position.x = Math.sin(Math.PI * cursor.x * 2) * 2.5;
camera.position.z = Math.cos(Math.PI * cursor.x * 2) * 2.5;
```

Breaking this down step by step:

1. **`cursor.x * 2`** — the normalized $[-0.5, 0.5]$ range becomes $[-1, 1]$. This controls how far around the circle the camera can travel.

2. **`Math.PI * (cursor.x * 2)`** — multiplying by $\pi$ converts the $[-1, 1]$ range into $[-\pi, \pi]$. At $\pi$ radians (180°), the camera has traveled halfway around the circle. At $2\pi$ (360°), it would complete a full loop. With the range limited to $\pi$, the camera sweeps a **half-circle** arc.

3. **`* 2.5`** — this is the **radius** of the orbit. The camera is always $2.5$ units away from the origin (the center of the scene).

4. **`sin` for x, `cos` for z** — on the unit circle, `sin` gives the horizontal component and `cos` gives the depth component. Together they produce circular motion in the XZ plane.

> **Visualization tip:** Open [GeoGebra](https://www.geogebra.org/classic) and plot `f(t) = sin(t)` and `g(t) = cos(t)` on the same graph. As $t$ increases, watch how the two functions together trace a circle when plotted as $(x, z)$ coordinates. You can also use the [unit circle tool](https://www.geogebra.org/m/REJbNw8q) to see this interactively.

### Why the camera orbits around the center

Since `cursor.x` ranges from $-0.5$ to $0.5$, the argument to `sin`/`cos` ranges from $-\pi$ to $\pi$. This means the camera traces a half-circle arc, always $2.5$ units from the origin. The camera never strays closer or farther — it maintains a constant radius.

### Keeping the camera aimed at the subject: `lookAt`

```ts
camera.lookAt(mesh.position);
```

Without `lookAt`, the camera would orbit around the mesh but always face the same direction (forward along its local Z axis). `lookAt` reorients the camera so its lens always points at the mesh — essential for an orbiting camera to actually look at what it's orbiting.

> 🤖 suggested: For a deeper understanding of how `lookAt` works internally, see the [Three.js Camera docs](https://threejs.org/docs/#api/en/cameras/Camera.lookAt).

### Y-axis movement (separate from the circle)

The vertical position is handled independently:

```ts
camera.position.y = cursor.y * 0.9;
```

This is a simple linear mapping — no trigonometry needed. Moving the mouse up/down lifts or lowers the camera. The `0.9` factor limits the vertical range slightly.

## Code

in repo - `apps/4_camera_move_circular`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;
const sizes = { width: 800, height: 600 };

const cursor = { x: 0, y: 0 };

window.addEventListener('mousemove', (ev) => {
  cursor.x = ev.clientX / sizes.width - 0.5;
  cursor.y = 0.5 - ev.clientY / sizes.height;
});

async function init() {
  const scene = new THREE.Scene();

  const mesh = new THREE.Mesh(
    new THREE.BoxGeometry(0.5, 0.5, 0.5),
    new THREE.MeshBasicMaterial({ color: 0x4c9892 })
  );
  mesh.position.set(-0.5, 0, 0.5);
  scene.add(mesh);

  const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height, 0.1, 100);
  camera.position.set(1, 0.5, 3);
  scene.add(camera);

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();
  renderer.setSize(sizes.width, sizes.height);
  renderer.setClearColor(0x000000, 1);

  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.setColors('red', 'green', 'blue');
  scene.add(axesHelper);

  const timer = new THREE.Timer();
  requestAnimationFrame(tick);

  function tick(timestamp: number) {
    timer.update(timestamp);

    // Vertical: simple linear mapping
    camera.position.y = cursor.y * 0.9;

    // Horizontal: circular orbit via trigonometry
    // sin for x, cos for z — traces a circle in the XZ plane
    // cursor.x * 2 maps [-0.5, 0.5] → [-1, 1]
    // Math.PI * that maps to [-π, π] — a half-circle arc
    // * 2.5 sets the orbit radius
    camera.position.x = Math.sin(Math.PI * cursor.x * 2) * 2.5;
    camera.position.z = Math.cos(Math.PI * cursor.x * 2) * 2.5;

    // Always look at the mesh so the camera faces its subject
    camera.lookAt(mesh.position);

    renderer.render(scene, camera);
    requestAnimationFrame(tick);
  }
}

await init();
```

## Gotchas

- **Y is inverted on screen vs 3D.** Mouse Y increases downward, but Three.js Y increases upward. That's why the normalization is `0.5 - ev.clientY / sizes.height` — flipping the direction. Forgetting this inversion makes the camera move opposite to what you expect.

- **`sin` and `cos` are swapped relative to what you might expect.** On the unit circle in math class, `cos` is usually X and `sin` is Y. Here, `sin` is used for X and `cos` for Z because the circle is in the XZ plane (horizontal), not XY. The mapping depends on which axes you're orbiting in.

- **`lookAt` overwrites the camera's rotation every frame.** If you also try to manually set `camera.rotation` in the same loop, `lookAt` will win. Let `lookAt` handle orientation entirely.

- **The multiplier values are arbitrary tuning.** The `2` in `cursor.x * 2` and `2.5` as the radius are not mathematically special — they control how much of the circle you sweep and how far the camera is. Change them and observe the effect to build intuition.

## Revisit

- Experiment with changing the multiplier values: try `cursor.x * 1` (quarter circle), `cursor.x * 4` (full circle + overlap), and radius values like `1.5` or `5`. Observe how each parameter changes the orbit.

- Try removing `lookAt` to see what happens — the camera orbits but never faces the mesh. This makes it clear why `lookAt` is essential for orbit cameras.

- Look into [OrbitControls](https://threejs.org/docs/#examples/en/controls/OrbitControls) — Three.js has a built-in orbit camera that handles this pattern (and more) automatically. Understanding the manual version first makes OrbitControls much less mysterious.

- The `MATH.md` in this app references the unit circle visualization problem — revisit it after understanding this lesson to see if your intuition for `sin`/`cos` has improved.
