## Concept

This lesson explores creating **randomly generated triangle meshes** using raw `BufferGeometry` in Three.js. Instead of using built-in geometries like `BoxGeometry` or `SphereGeometry`, we build geometry from scratch by defining individual vertices.

### Vertex layout for triangles

A single triangle needs **3 vertices**. Each vertex has **3 coordinates** (x, y, z). So one triangle requires:

```
3 vertices × 3 coordinates = 9 Float32 values
```

When you have `N` triangles, the total buffer size is:

```
N × 3 × 3 = N × 9 values
```

### The BufferAttribute stride

When you call `bufferGeometry.setAttribute('position', attribute)`, the second argument is the **item size** (stride) — how many array elements make up one vertex. Since each vertex has x, y, z, the item size is **3** (not the total number of vertices).

```ts
new THREE.BufferAttribute(verticesPositionArray, 3) // 3 = xyz per vertex
```

A common mistake is passing `verticesCount` here — that tells the GPU how many floats per vertex, not how many vertices total. Three.js infers the vertex count from `array.length / itemSize`.

### Random vertex generation

To scatter triangles randomly in space:

1. Create a `Float32Array` of size `verticesCount * 3 * 3`
2. Fill it with `Math.random()` values, centered around zero
3. Attach it as the `position` attribute

```ts
for (let i = 0; i < verticesCount * 3 * 3; i++) {
    verticesPositionArray[i] = (Math.random() - 0.5) * 4;
}
```

- `Math.random()` returns `[0, 1)`
- Subtracting `0.5` shifts to `[-0.5, 0.5)` (centered at origin)
- Multiplying by `4` scales the cloud to span roughly `[-2, 2]`

### Using wireframe mode

A `MeshBasicMaterial` with `wireframe: true` renders only the edges of each triangle. This is the easiest way to see the individual triangles in a random mesh — without it, overlapping faces would obscure the structure.

## Code

in repo - `apps/6_random_buffer_geometries`

```ts
const bufferGeometry = new THREE.BufferGeometry();

const verticesCount = 5000;

// 5000 triangles × 3 vertices × 3 coordinates = 45000 floats
const verticesPositionArray = new Float32Array(verticesCount * 3 * 3);

for (let i = 0; i < verticesCount * 3 * 3; i++) {
    verticesPositionArray[i] = (Math.random() - 0.5) * 4;
}

bufferGeometry.setAttribute(
    'position',
    new THREE.BufferAttribute(verticesPositionArray, 3),
);

const material = new THREE.MeshBasicMaterial({
    color: 0x4c9892,
    wireframe: true,
});

const mesh = new THREE.Mesh(bufferGeometry, material);
scene.add(mesh);
```

## Gotchas

- **BufferAttribute item size must be 3, not verticesCount.** The second argument to `BufferAttribute` is the number of floats per vertex (3 for xyz), not the total number of vertices. Passing `verticesCount` there will produce a garbled mesh or an error — Three.js uses `array.length / itemSize` to determine vertex count.

- **Without indices, vertices are never shared.** Each triangle gets its own 3 vertices even if two triangles touch the same point. This is intentional here (random triangles don't share vertices), but in production you'd use an index buffer to avoid redundant data.

- **Overlapping triangles in wireframe look chaotic.** At high vertex counts with random positions, the wireframe mesh becomes a dense cloud of lines. Dropping to ~50 triangles makes the individual triangles easier to see and understand.

## Revisit

- **Index buffers (`setIndex`)** — when two faces share a vertex, you can store each vertex once and reference it by index. This saves memory and is how real meshes work. Practice this next with a simple shape like a cube to see the difference.
- **`BufferAttribute` usage** — experiment with other attributes like `normal`, `color`, or `uv` on the same geometry to understand how per-vertex data is laid out.
- **Performance at scale** — 5000 random triangles is lightweight, but `Float32Array` allocation and random fill could be slow for millions of vertices. Consider `InstancedMesh` or compute shaders for large counts.
