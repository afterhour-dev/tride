## Concept

This lesson is a direct continuation of [[15.5_scroll-based-animation-easing-lerp]]. By now we have a scene where the camera scrolls down a vertical stack of toon-shaded meshes (a torus, a cone, and a torus knot, each `objectsDistance` apart) while a mouse parallax smoothly offsets a wrapping `cameraGroup`. The scene works and scrolls, but visually it feels empty — the objects sit alone in a void.

**The goal of this lesson is to make the experience more immersive and help the user feel depth by adding particles** (small floating points strewn through the scene). Particles that drift in the background as you scroll give the eye parallax cues and make the whole world feel bigger.

There are two key technical consequences of adding particles:

### 1. We must switch from WebGPU to WebGL

`// EXPLAIN:` everything in this series up to now ran on a `WebGPURenderer`. **`PointsMaterial` (the built-in material for `THREE.Points`) is not available on the WebGPU renderer in the current Three.js version — particles require a WebGL renderer.**

The change is small but touches several spots:

```ts
// before (webgpu)
import * as THREE from 'three/webgpu';
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();

// after (webgl)
import * as THREE from 'three';              // plain three, not three/webgpu
const renderer = new THREE.WebGLRenderer({
    canvas,
    alpha: true,   // EXPLAIN: WebGLRenderer does NOT default to alpha
});
// no renderer.init() needed for WebGLRenderer
```

`// GOTCHA:` note that `alpha` is the real trap here. The `WebGPURenderer` had a transparent canvas by default. The `WebGLRenderer` does **not** — its default clear alpha is fully opaque — so we must set `alpha: true` explicitly, otherwise the fixed fullscreen canvas will hide the HTML content behind it (and nothing will show through). Also, `renderer.init()` is an async WebGPU-only step; `WebGLRenderer` has no need for it.

### 2. Particles must be tall enough to cover the whole scroll range

The key idea: as the user scrolls, the camera travels vertically by roughly `objectsDistance` for each of the three meshes. So over the full page the camera moves roughly `3 * objectsDistance` units down.

`// EXPLAIN:` the particles therefore need to be spread by `y` enough that they're visible at *every* point in the scroll — they must start high enough and extend far enough below to last the whole scroll. This is why the code uses the radius-driven y formula based on `objectsDistance` and the number of meshes:

```ts
positions[i * 3 + 1] =
    debugObject.objectsDistance * 0.5 -
    Math.random() * debugObject.objectsDistance * selectionMeshes.length;
```

Let's unpack that in steps:

- **`selectionMeshes.length` is `3`.** `// EXPLAIN: why length?` Because there are three meshes (torus, cone, knot), and each is spaced one `objectsDistance` apart. The total vertical span the camera travels is roughly `3 * objectsDistance`. So the particles must be spread over that same total vertical extent — hence use the *count* of meshes as a multiplier.
- **`debugObject.objectsDistance * selectionMeshes.length`** is the total height of the particle cloud — a little over `3 * objectsDistance` (with `objectsDistance = 4`, that's `12`).
- **`Math.random() * totalHeight`** gives a random vertical offset ranging from `0` to that total height.
- **`debugObject.objectsDistance * 0.5 - ...`** shifts the whole cloud up by half a `objectsDistance` so it starts *above* the first mesh and extends a little *below* the last one. The small overshoot at the top (`0.5 * objectsDistance`) guarantees some particles are already visible right at the start of the page, before you scroll at all.

Net result: a vertically continuous cloud of particles that covers the entire scroll journey, top to bottom. Because particles sit behind and around the meshes, combined with the camera's scroll + parallax movement, they strongly reinforce the feeling of depth and speed.

The full particle setup is a standard `THREE.Points` from a `BufferGeometry`:

```ts
const particlesCount = 200;
const positions = new Float32Array(particlesCount * 3);
for (let i = 0; i < particlesCount; i++) {
    positions[i * 3 + 0] = (Math.random() - 0.5) * 10;     // x
    positions[i * 3 + 1] = /* y formula above */;
    positions[i * 3 + 2] = (Math.random() - 0.5) * 10;     // z
}

const pointsGeometry = new THREE.BufferGeometry();
pointsGeometry.setAttribute(
    'position',
    new THREE.BufferAttribute(positions, 3),
);

const pointsMaterial = new THREE.PointsMaterial({
    color: debugObject.particlesColor,
    size: 0.03,
    sizeAttenuation: true,
});

const points = new THREE.Points(pointsGeometry, pointsMaterial);
scene.add(points);
```

An `// EXPLAIN:` comment notes that **we won't do more with particles here** — this is a minimal cloud. Improvements from the earlier particle lessons (random sizes, random alpha, animation) are possible but out of scope for this lesson. To recursively study them, see [[14.0_particles-webgl-intro]], [[14.1_particles-custom-geometry]], [[14.2_map-alpha-map-colors-blending]] and [[14.3_particle-animation]].

```ts
import * as THREE from 'three';                       // webgl (particles)
// import * as THREE from 'three/webgpu';             // webgpu WITH particles
// no OrbitControls — the camera is driven by scroll + parallax

const gradientTexture = textureLoader.load('textures/gradients/three-colors.jpg');
gradientTexture.magFilter = THREE.NearestFilter;      // crisp toon steps

const renderer = new THREE.WebGLRenderer({
    canvas,
    alpha: true,                                      // WebGL is not transparent by default
});

// --- three toon meshes spaced objectsDistance apart along -Y ---
const torusMesh = new THREE.Mesh(new THREE.TorusGeometry(1, 0.4, 16, 60), torusMaterial);
const coneMesh  = new THREE.Mesh(new THREE.ConeGeometry(1, 2, 32), coneMaterial);
const knotMesh  = new THREE.Mesh(new THREE.TorusKnotGeometry(0.8, 0.35, 100, 16), knotMaterial);

torusMesh.position.y = -debugObject.objectsDistance * 0;
coneMesh.position.y  = -debugObject.objectsDistance * 1;
knotMesh.position.y  = -debugObject.objectsDistance * 2;

const selectionMeshes = [torusMesh, coneMesh, knotMesh];
scene.add(...selectionMeshes);

// --- particles ---
const particlesCount = 200;
const positions = new Float32Array(particlesCount * 3);
for (let i = 0; i < particlesCount; i++) {
    positions[i * 3 + 0] = (Math.random() - 0.5) * 10;                 // x: -5..5
    positions[i * 3 + 1] =
        debugObject.objectsDistance * 0.5 -                             // start above
        Math.random() * debugObject.objectsDistance * selectionMeshes.length; // span whole scroll
    positions[i * 3 + 2] = (Math.random() - 0.5) * 10;                 // z: -5..5
}

const pointsGeometry = new THREE.BufferGeometry();
pointsGeometry.setAttribute('position', new THREE.BufferAttribute(positions, 3));

const pointsMaterial = new THREE.PointsMaterial({
    color: debugObject.particlesColor,
    size: 0.03,
    sizeAttenuation: true,
});
scene.add(new THREE.Points(pointsGeometry, pointsMaterial));

// --- camera in a group, scrolled and parallaxed ---
const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height, 0.1, 100);
camera.position.z = 3;
const cameraGroup = new THREE.Group();
cameraGroup.add(camera);
scene.add(cameraGroup);

const timer = new THREE.Timer();
renderer.setAnimationLoop(tick);

function tick(timestamp: number) {
    timer.update(timestamp);
    const elapsedTime = timer.getElapsed();
    const delta = timer.getDelta();

    // scroll drives the camera down the stack
    camera.position.y = -(scrollY * debugObject.objectsDistance) / sizes.height;

    // mouse parallax targets, eased with delta
    const parallaxX = cursor.x * 0.5;
    const parallaxY = -cursor.y * 0.5;
    cameraGroup.position.x += (parallaxX - cameraGroup.position.x) * 5 * delta;
    cameraGroup.position.y += (parallaxY - cameraGroup.position.y) * 5 * delta;

    for (const mesh of selectionMeshes) {
        mesh.rotation.x = elapsedTime * 0.1;
        mesh.rotation.y = elapsedTime * 0.12;
    }

    renderer.render(scene, camera);
}
```

## Gotchas

- **Forgetting `alpha: true` on `WebGLRenderer`.** The WebGPU renderer was transparent by default; WebGL is not. Omit `alpha: true` and the painted canvas covers the scrolling HTML sections — the core illusion of this demo breaks. `// GOTCHA:` set it as soon as you switch renderers.
- **`import * as THREE from 'three'` vs `'three/webgpu'`.** You must use the plain `three` entry point for `PointsMaterial`. Importing `'three/webgpu'` while also creating a `WebGLRenderer` (or `PointsMaterial`) will fail / mismatch. The import and the renderer must agree.
- **Forgetting `renderer.init()` is WebGPU-only.** `WebGPURenderer` needed `await renderer.init()`; `WebGLRenderer` has no such method. Copying the init call over is a leftover that just errors.
- **Particles only covering part of the scroll.** If you position particles in a small y-range, they run out halfway down the page and the scene silently gets empty. The y must translate the *entire* `3 * objectsDistance` scroll extent — that's why the formula multiplies by `selectionMeshes.length`.
- **`objectsDistance` is a debug tunable.** It is the single value controlling both the mesh spacing and the particle cloud; changing it affects the whole composition. The README and debug GUI expose it (`debugObject.objectsDistance = 4`).

## Revisit

- **Step-by-step origin of the y-formula.** Make sure you can re-derive `objectsDistance * 0.5 - random * objectsDistance * meshCount` from "camera moves 3× objectsDistance" on your own. That derivation is worth practicing.
- **Improve the particles.** The code comment (`// EXPLAIN:` note) says this is a deliberate minimal version. Try adding random sizes, random alpha, and optional animation as learned in [[14.0_particles-webgl-intro]] through [[14.3_particle-animation]].
- **Revisit the renderer flip.** Understand *why* `PointsMaterial` forces WebGL and is absent(ing/limited) on the current WebGPU path so you can anticipate the switch on future particle experiments.

## Outdated

The overall scroll + parallax + particle technique is still current. **However, this lesson deliberately runs particles on the older WebGL path** because the WebGPU renderer's built-in `Points`/`PointsMaterial` support is not yet available. ⚠️ **Note:** this app is WebGL because we need `PointsMaterial`, which lives on the WebGL path. If you want a particle experiment fully on WebGPU, you currently need a custom `Points`-style ShaderMaterial (or revisit the Three.js release notes once the WebGPU renderer lands built-in points support) — that's the direction new particle work should head.
