# MeshStandardMaterial — Part One

## Concept

### What is MeshStandardMaterial

`MeshStandardMaterial` is Three.js's implementation of **physically-based rendering** (PBR). It's called "standard" because PBR has become the standard rendering approach across software, engines, and libraries — from Three.js to Blender to Unreal Engine. This means the material will look realistic, and the same parameters produce similar results regardless of the technology you're using.

Unlike `MeshBasicMaterial` (which ignores lights entirely) or `MeshPhongMaterial` (which uses simpler lighting models), `MeshStandardMaterial` simulates how light actually interacts with surfaces in the real world.

### Requires lights

Unlike `MeshBasicMaterial`, `MeshStandardMaterial` **requires lights to be visible**. Without at least an `AmbientLight`, the object will appear black. In this app, two lights are used:

- `AmbientLight` — provides a base level of illumination across the entire scene
- `PointLight` — a single point light source that creates directional highlights and shadows

### Metalness and Roughness

The two key properties that control how the material looks:

- **`metalness`** (0–1) — how "metallic" the surface appears. At 0 it looks like a non-metal (plastic, wood). At 1 it looks like polished metal. In practice, most real-world surfaces are between 0 and 1.
- **`roughness`** (0–1) — how rough or smooth the surface is. At 0, the surface is perfectly smooth (mirror-like reflections). At 1, it's completely rough (diffuse, no specular highlights).

These two properties together define the material's appearance. For example:
- Metal with low roughness → shiny, mirror-like metal
- Metal with high roughness → brushed metal look
- Non-metal with low roughness → glossy plastic
- Non-metal with high roughness → matte plastic

### setAnimationLoop

This lesson uses `renderer.setAnimationLoop(tick)` instead of the more familiar `window.requestAnimationFrame(tick)`. The `setAnimationLoop` method is recommended for WebGPU rendering and handles the animation loop internally. When using it, you do **not** need to call `requestAnimationFrame` yourself at the end of your tick function — Three.js handles that for you.

### Debug UI with lil-gui

The material properties (`metalness`, `roughness`) are exposed through a `lil-gui` debug panel, making it easy to tweak values in real time and see how they affect the material's appearance. This is a common pattern in Three.js development — using a GUI to explore material parameters before settling on final values.

## Code

in repo - `apps/10_8_MeshStandardMaterial_part_one`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

// Material — PBR with physical parameters
const material = new THREE.MeshStandardMaterial();
material.metalness = 0.45;
material.roughness = 0.65;

// Debug GUI to tweak properties live
const gui = new GUI({ title: 'Debugging' });
gui.add(material, 'metalness').min(0).max(1).step(0.0001);
gui.add(material, 'roughness').min(0).max(1).step(0.0001);

// Meshes with the same material
const sphere = new THREE.Mesh(new THREE.SphereGeometry(0.5, 16, 16), material);
sphere.position.x = -1.5;

const torus = new THREE.Mesh(new THREE.TorusGeometry(0.3, 0.2, 16, 32), material);
torus.position.x = 1.5;

// Lights — required for MeshStandardMaterial
const ambientLight = new THREE.AmbientLight(0xffffff, 1);
const pointLight = new THREE.PointLight(0xffffff, 30);
pointLight.position.set(2, 3, 4);

const scene = new THREE.Scene();
scene.add(sphere, torus, ambientLight, pointLight);

const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setSize(innerWidth, innerHeight);
renderer.setPixelRatio(Math.min(devicePixelRatio, 2));

const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

// Animation loop — setAnimationLoop instead of requestAnimationFrame
const timer = new THREE.Timer();

renderer.setAnimationLoop((timestamp: number) => {
  timer.update(timestamp);
  controls.update();
  torus.rotation.y = timer.getElapsed() * 0.1;
  sphere.rotation.y = timer.getElapsed() * 0.1;
  renderer.render(scene, camera);
});
```

## Gotchas

- **Material appears black** — `MeshStandardMaterial` requires lights. If you forget to add `AmbientLight` or other lights, the object will render as black. This is a common first-time surprise coming from `MeshBasicMaterial`.
- **Metalness too high** — Setting `metalness` close to 1 without an environment map can make objects look unnaturally dark or flat. In the next lesson, environment maps will be introduced to give metallic surfaces something to reflect.
- **Forgetting `colorSpace`** — Textures loaded from files may need `texture.colorSpace = THREE.SRGBColorSpace` for correct color rendering, especially albedo/diffuse textures.
- **`setAnimationLoop` vs `requestAnimationFrame`** — When using `setAnimationLoop`, do NOT call `requestAnimationFrame` at the end of your tick function. Three.js handles the loop internally. Calling both will cause double-rendering.

## Revisit

- The next lesson (10.9) will introduce **environment maps**, which add realistic reflections and lighting to `MeshStandardMaterial` — this is especially important for metallic surfaces.
- Experiment with extreme values: `metalness: 1, roughness: 0` (perfect mirror metal) vs `metalness: 0, roughness: 1` (completely matte non-metal).
- Consider how `MeshStandardMaterial` compares to `MeshPhongMaterial` — the former is more physically accurate but slightly more expensive to compute.
