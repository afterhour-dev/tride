## Concept

[GSAP](https://gsap.com/) (GreenSock Animation Platform) is a professional-grade JavaScript animation library. Instead of manually updating object properties inside a render loop, you declare *tweens* — descriptions of what should change, over how long, and with what easing — and GSAP handles the interpolation between frames.

### How GSAP fits into a Three.js render loop

GSAP does **not** replace `requestAnimationFrame`. It runs on its own internal ticker (which itself uses `requestAnimationFrame` under the hood). The typical pattern is:

1. You create a `requestAnimationFrame` loop that calls `renderer.render(scene, camera)` every frame.
2. You create GSAP tweens that modify Three.js object properties (position, rotation, scale, color, etc.).
3. Each frame, the render loop picks up whatever values GSAP has set — no manual property updates needed.

This is the "fire-and-forget" approach: once a tween is created, you don't reference it again unless you need to control it (pause, reverse, kill).

### Core GSAP methods

| Method | Purpose |
|--------|---------|
| `gsap.to(target, vars)` | Animate **from** current values **to** the specified values |
| `gsap.fromTo(target, fromVars, toVars)` | Animate from explicit start values to explicit end values |
| `gsap.from(target, vars)` | Animate **from** the specified values **to** current values |

### Key tween properties

- **`duration`** — length of the animation in seconds
- **`ease`** — the acceleration curve (e.g. `'bounce.in'`, `'elastic.in'`, `'power2.out'`)
- **`repeat`** — number of repetitions (`-1` for infinite)
- **`yoyo`** — when `true`, reverses direction on each repeat (ping-pong effect)
- **`delay`** — seconds to wait before the tween starts

### Easing

Easing defines how a value changes over time — linear is constant speed, ease-in starts slow and accelerates, ease-out starts fast and decelerates. GSAP ships with many built-in eases. See [GSAP Easing Visualizer](https://gsap.com/docs/v3/Eases/) to explore them interactively.

### Three.js Timer

`THREE.Timer` is a simple utility for tracking elapsed time. In this app, `timer.update(timestamp)` is called each frame, but `timer.getElapsed()` is commented out — it's available if you need time-based logic outside of GSAP (e.g. procedural animation, physics).

### Why camera.lookAt is commented out

`camera.lookAt(mesh.position)` would make the camera track the animated mesh. Since GSAP is moving the mesh's position, enabling this would cause the camera to follow the mesh around — which changes the visual composition. Whether you want this depends on the effect you're after.

## Code

in repo - `apps/3_animation_gsap`

```ts
import * as THREE from 'three/webgpu';
import gsap from 'gsap';

// 1. Setup scene, geometry, material, mesh
const scene = new THREE.Scene();
const mesh = new THREE.Mesh(
  new THREE.BoxGeometry(0.5, 0.5, 0.5),
  new THREE.MeshBasicMaterial({ color: 0x4c9892, wireframe: true }),
);
scene.add(mesh);

// 2. Create tweens — GSAP handles the interpolation
gsap.to(mesh.position, {
  duration: 4,
  y: 1.5,
  ease: 'bounce.in',
});

gsap.to(mesh.rotation, {
  z: Math.PI * 2,
  duration: 15,
  ease: 'elastic.in',
  repeat: 2,
  yoyo: true,
});

gsap.fromTo(
  mesh.scale,
  { y: 0.5, delay: 2 },
  { y: 1.5, repeat: -1, yoyo: true, duration: 6 },
);

// 3. Render loop — just re-renders, GSAP does the rest
function tick() {
  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
}
window.requestAnimationFrame(tick);
```

## Gotchas

- **GSAP does not call `renderer.render()`** — you still need your own `requestAnimationFrame` loop. Without it, nothing appears on screen even though GSAP is updating properties.
- **Fire-and-forget tweens keep running** — a `gsap.to()` call returns a tween object, but if you never store or reference it, the animation still plays. This is fine for simple cases, but if you need to stop/modify a tween later, you must save the reference.
- **GSAP modifies the Three.js object directly** — it sets `mesh.position.y`, `mesh.rotation.z`, etc. No special integration or bridge is needed.
- **`yoyo: true` without `repeat` does nothing** — yoyo only matters when the animation repeats. A single play-through won't reverse.

- Try GSAP's `gsap.timeline()` for sequencing multiple animations in order
- Look into `gsap.killTweensOf(target)` to stop animations programmatically
