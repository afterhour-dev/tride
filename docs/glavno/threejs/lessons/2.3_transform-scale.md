# Transform Scale

## Concept

Scale controls how large or small a mesh appears in the scene. It is stored as a `Vector3` — the same type used for `position` — where each component (x, y, z) is a **multiplier** applied to the geometry's original dimensions.

A scale of `(1, 1, 1)` means the mesh is at its original size. A scale of `(2, 2, 2)` doubles it in every direction. A scale of `(0.5, 1, 1)` squashes it along the x-axis while leaving y and z unchanged.

Three main ways to set scale:

```ts
// Uniform scale — all three axes get the same value
mesh.scale.setScalar(0.5); // (0.5, 0.5, 0.5)

// Per-axis scale — pass x, y, z (z defaults to 1 if omitted)
mesh.scale.set(2, 1.5);    // (2, 1.5, 1)
mesh.scale.set(2, 1.5, 1); // same thing, explicit

// Direct property access
mesh.scale.z = 1.2; // only changes z
```

`setScalar()` is useful when you want uniform scaling. `set()` lets you control individual axes. Direct property access works when you only need to change one axis.

Scale is applied **after** the geometry is created — it does not modify the underlying vertex data, it multiplies at render time. This means you can animate scale freely without any geometry rebuild cost.

The camera in this app is slightly offset (`position.y = 0.5`, `position.x = 0.1`) to give a more three-dimensional view. Without this, the z-axis points directly at the camera and the box looks flat (2D).

## Code

in repo - `apps/2_transforms_scale`

```ts
import './style.css';
import * as THREE from 'three/webgpu';
import { getRequiredElement } from './util';

const canvas = getRequiredElement<HTMLCanvasElement>('canvas#tride');

const sizes = {
  width: 800,
  height: 600,
};

async function init() {
  const scene = new THREE.Scene();

  const boxGeometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
  const material = new THREE.MeshBasicMaterial({
    color: 0x4c9892,
    wireframe: true,
  });

  const mesh = new THREE.Mesh(boxGeometry, material);
  mesh.position.z = 1.5;
  mesh.position.x = -0.5;
  mesh.position.y = 0.6;

  // Scale — uniform, then per-axis
  mesh.scale.setScalar(0.5);
  mesh.scale.set(2, 1.5);
  mesh.scale.z = 1.2;

  scene.add(mesh);

  const camera = new THREE.PerspectiveCamera(75, sizes.width / sizes.height);
  camera.position.z = 3;
  camera.position.y = 0.5;
  camera.position.x = 0.1;
  scene.add(camera);

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();

  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.setColors('red', 'green', 'blue');
  scene.add(axesHelper);

  renderer.setSize(sizes.width, sizes.height);
  renderer.setClearColor(0x000000, 1);
  renderer.render(scene, camera);
}

await init();
```

## Gotchas

- **`set(x, y)` omits z as 1, not 0** — `mesh.scale.set(2, 1.5)` results in `(2, 1.5, 1)`, not `(2, 1.5, 0)`. A z-scale of 0 would flatten the mesh to nothing. If you need z = 0, pass it explicitly: `mesh.scale.set(2, 1.5, 0)`.

- **Scale values are multipliers, not absolute sizes** — a scale of `2` means "twice the original geometry size", not "2 world units". If you change the geometry later (e.g. from `BoxGeometry(0.5)` to `BoxGeometry(1)`), the same scale value produces a different visual size.

- **Non-uniform scale distorts lighting and normals** — when x, y, and z scale factors differ, normals are stretched unevenly. `MeshBasicMaterial` (used here) is unaffected because it ignores lighting, but `MeshStandardMaterial` and similar lit materials will look wrong under non-uniform scale. This is a fundamental limitation of the standard transform pipeline, not a Three.js bug.

- **WebGPU fallback gotcha** — `WebGPURenderer` falls back to WebGL2 when no GPU adapter is available. The fallback does not default to an opaque black clear color the way `WebGLRenderer` does. Always call `renderer.setClearColor(0x000000, 1)` to ensure consistent behavior across backends.

## Revisit

- How does scale interact with rotation order? Non-uniform scale + rotation can produce unexpected results — worth testing with `MeshStandardMaterial` to see the lighting artifacts.
- Try animating scale in the render loop (e.g. `mesh.scale.x = Math.sin(time)`) to see the visual effect.
- Compare `MeshBasicMaterial` (no lighting) vs `MeshStandardMaterial` (lit) under non-uniform scale to understand the normal distortion issue.
