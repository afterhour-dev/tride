# MeshStandardMaterial — Part Two

## Concept

### Environment Maps

In the [previous lesson](10.8_mesh-standard-material-part-one), `MeshStandardMaterial` was explored with manual lights (`AmbientLight` + `PointLight`). The material looked somewhat flat and metallic surfaces had nothing realistic to reflect.

An **environment map** (also called an environment texture or HDR map) solves this. It's a panoramic image of a real or imagined environment that wraps around the entire scene. When applied, every reflective surface in the scene "sees" the environment — as if the objects were actually sitting inside that place. This produces realistic reflections, ambient lighting, and color bleeding without manually placing dozens of lights.

Environment maps are especially important for metallic surfaces, because metal in the real world is highly reflective. Without an environment map, a `metalness` value close to 1 makes objects look unnaturally dark — there's nothing for them to reflect.

### Loading HDR Images with HDRLoader

HDR (High Dynamic Range) images store a much wider range of brightness values than standard JPEG or PNG files. This makes them ideal for environment maps because they can represent both bright sky areas and dark shadow areas simultaneously.

In this app, `HDRLoader` is used instead of the older `RGBELoader` (which is deprecated):

```ts
import { HDRLoader } from 'three/examples/jsm/Addons.js';

const hdrLoader = new HDRLoader();
const hdrTexture = await hdrLoader.loadAsync('/envmap/2k.hdr');
```

The HDR file used here comes from [Poly Haven](https://polyhaven.com/a/urban_alley_01) — a free, open-source library of HDR environment maps.

### Equirectangular Reflection Mapping

After loading the HDR texture, you need to tell Three.js how to interpret it. Most HDR environment maps are stored as **equirectangular** projections (the same projection used for world maps — a 2D rectangle wrapping around a sphere). Setting the mapping type tells Three.js to treat the texture as a surrounding sphere rather than a flat image:

```ts
hdrTexture.mapping = THREE.EquirectangularReflectionMapping;
```

### Environment vs Background

There are two separate assignments that control how the HDR map is used:

```ts
scene.environment = hdrTexture;  // provides lighting and reflections
scene.background = hdrTexture;   // makes it visible as the scene background
```

- **`scene.environment`** — uses the HDR map to calculate lighting and reflections for all PBR materials in the scene. Even if the background is set to a solid color, `scene.environment` still lights the objects.
- **`scene.background`** — displays the HDR map as the visible background of the scene. Without this, you'd see the default black background while objects still receive environment lighting.

You can use them independently. For example, `scene.environment` without `scene.background` gives you realistic lighting with a plain or transparent background.

### Initialization Order

There's a question about whether `scene.environment` and `scene.background` need to be assigned before or after `await renderer.init()`. In this app, the renderer is initialized first, and the environment map is loaded and assigned afterward — this works fine. In practice, the order of `scene.environment` / `scene.background` relative to `renderer.init()` doesn't cause errors. What matters is that the HDR texture has finished loading before you assign it.

### Lights Still Work Alongside Environment Maps

When an environment map provides lighting, you don't strictly need additional lights — but you can still add them. Ambient and point lights will add their contribution on top of the environment lighting. In this app, the additional lights are commented out to explore the environment map's lighting in isolation, but they could be uncommented to layer more light into the scene.

### Environment Maps Work with Other Materials Too

Environment maps aren't exclusive to `MeshStandardMaterial`. They also work with `MeshPhongMaterial` and `MeshLambertMaterial` because those materials support lighting calculations. However, the effect is most pronounced with `MeshStandardMaterial` (PBR) since it's designed for physically accurate reflections. With Lambert or Phong, the environment map provides ambient-style lighting rather than detailed specular reflections.

### Metalness and Roughness with Environment Maps

With an environment map in place, the `metalness` and `roughness` parameters become much more visually interesting:

- **High metalness + low roughness** → clear, mirror-like reflections of the environment
- **High metalness + high roughness** → blurred, diffuse reflections (brushed metal look)
- **Low metalness + low roughness** → glossy plastic-like surface with subtle environment reflections
- **Low metalness + high roughness** → matte surface, environment map mainly provides ambient lighting

The app uses `metalness: 0.7` and `roughness: 0.2` as starting defaults — a reasonable middle ground that shows off the environment map clearly.

## Code

in repo - `apps/10_9_MeshStandardMaterial_part_two`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls, HDRLoader } from 'three/examples/jsm/Addons.js';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

const scene = new THREE.Scene();

// Renderer
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();

// Environment map — loaded as HDR and set to equirectangular mapping
const hdrLoader = new HDRLoader();
const hdrTexture = await hdrLoader.loadAsync('/envmap/2k.hdr');
hdrTexture.mapping = THREE.EquirectangularReflectionMapping;

scene.environment = hdrTexture;  // lighting + reflections
scene.background = hdrTexture;   // visible background

// PBR material — metalness and roughness are key with env maps
const material = new THREE.MeshStandardMaterial();
material.metalness = 0.7;
material.roughness = 0.2;

// Multiple meshes share the same material
const sphere = new THREE.Mesh(new THREE.SphereGeometry(0.5, 16, 16), material);
sphere.position.x = -1.5;

const torus = new THREE.Mesh(new THREE.TorusGeometry(0.3, 0.2, 16, 32), material);
torus.position.x = 1.5;

scene.add(sphere, torus);

// Camera
const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);

// Controls
const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

// Animation
const timer = new THREE.Timer();
renderer.setAnimationLoop((timestamp: number) => {
  timer.update(timestamp);
  controls.update();
  sphere.rotation.y = timer.getElapsed() * 0.1;
  torus.rotation.y = timer.getElapsed() * 0.1;
  renderer.render(scene, camera);
});
```

## Gotchas

- **Metal objects look dark without environment map** — If you set high `metalness` but forget `scene.environment`, metallic objects will appear unnaturally dark or black. They have nothing to reflect.
- **HDRLoader vs RGBELoader** — `RGBELoader` is deprecated. Always use `HDRLoader` for `.hdr` files. Both load the same file format, but `HDRLoader` is the maintained path forward.
- **Forgetting `EquirectangularReflectionMapping`** — Without this mapping assignment, the HDR texture won't wrap correctly around the scene and reflections will look distorted or broken.
- **Environment vs Background confusion** — `scene.environment` = lighting/reflections, `scene.background` = visible backdrop. You can use one without the other. Setting only `scene.background` gives you a visible background but no environment-based lighting on objects.
- **Order of initialization** — The HDR texture must be fully loaded before assigning it to `scene.environment` or `scene.background`. Using `await hdrLoader.loadAsync()` ensures this. Assigning a half-loaded texture won't crash but will show incorrect results.
