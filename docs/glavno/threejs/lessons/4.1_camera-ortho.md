# 4.1 Camera Ortho

## Concept

An **OrthographicCamera** projects 3D scenes onto a 2D plane without any perspective distortion — objects don't get smaller as they move away from the camera. This is the opposite of a `PerspectiveCamera`, where distant objects shrink naturally.

Orthographic cameras are useful for:
- CAD and architectural visualization (true proportions at any distance)
- 2D games and UIs (flat rendering, pixel-perfect alignment)
- Mini-map overlays
- Isometric views

### How it differs from PerspectiveCamera

| | PerspectiveCamera | OrthographicCamera |
|---|---|---|
| Depth perception | Yes — objects shrink with distance | No — parallel lines stay parallel |
| FOV | Defined by field-of-view angle | Defined by frustum bounds |
| Use case | Realistic 3D | Flat/isometric views |

### OrthographicCamera parameters

The constructor takes six frustum bounds plus near/far clipping planes:

```ts
new THREE.OrthographicCamera(left, right, top, bottom, near, far)
```

- **left / right** — horizontal extent of the visible area (in world units)
- **top / bottom** — vertical extent of the visible area (in world units)
- **near** — distance to the near clipping plane (objects closer than this are not rendered)
- **far** — distance to the far clipping plane (objects farther than this are not rendered)

### The aspect ratio trick

If you pass `-1, 1, 1, -1` directly as left/right/top/bottom, the visible area becomes a square regardless of the canvas dimensions. To fix this, you multiply `left` and `right` by the aspect ratio:

```ts
const aspectRatio = sizes.width / sizes.height;

const camera = new THREE.OrthographicCamera(
  -1 * aspectRatio,  // left
   1 * aspectRatio,  // right
   1,                // top
  -1,                // bottom
   0.1,              // near
   100,              // far
);
```

This makes the frustum match the canvas proportions — objects won't appear squished or stretched.

### OrthographicCamera inheritance

`OrthographicCamera` extends `Camera`, which in turn extends `Object3D`. This means it inherits position, rotation, and scale — you can move and orient the camera just like any other scene object. The `camera.lookAt()` method works the same way as with a perspective camera.

## Code

in repo - `apps/4_camera_ortho`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

const sizes = { width: 800, height: 600 };

const scene = new THREE.Scene();

// Box mesh
const boxGeometry = new THREE.BoxGeometry(0.5, 0.5, 0.5);
const material = new THREE.MeshBasicMaterial({ color: 0x4c9892 });
const mesh = new THREE.Mesh(boxGeometry, material);
mesh.position.set(-0.5, 0, 0.5);
scene.add(mesh);

// Orthographic camera
const aspectRatio = sizes.width / sizes.height;
const camera = new THREE.OrthographicCamera(
  -1 * aspectRatio, 1 * aspectRatio,  // left, right
  1, -1,                               // top, bottom
  0.1, 100                             // near, far
);
camera.position.set(0.1, 0.5, 3);
scene.add(camera);

// Renderer
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setSize(sizes.width, sizes.height);

// Axes helper for reference
const axesHelper = new THREE.AxesHelper(5);
axesHelper.setColors('red', 'green', 'blue');
scene.add(axesHelper);

// Orbiting animation
const timer = new THREE.Timer();

function tick(timestamp: number) {
  timer.update(timestamp);
  const elapsed = timer.getElapsed();

  camera.position.x = Math.cos(elapsed * 0.2);
  camera.position.z = -Math.sin(elapsed * 0.2);
  camera.lookAt(mesh.position);

  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

## Gotchas

- **Aspect ratio ignored** — If you forget to multiply `left`/`right` by the aspect ratio, your scene will look squished on non-square canvases. This is the most common mistake with orthographic cameras.
- **Near/far clipping** — Objects closer than `near` or farther than `far` are invisible. If your objects seem to disappear when the camera moves, check these values.
- **No depth of field** — Unlike a perspective camera, there's no natural sense of depth. Use `AxesHelper` or wireframe mode to help visualize the 3D space.

## Revisit

- Compare `OrthographicCamera` vs `PerspectiveCamera` side by side on the same scene — this builds intuition for when each is appropriate
- Experiment with different `near`/`far` values to see clipping behavior
- Try creating an isometric view by positioning the camera at equal angles (e.g. `position.set(1, 1, 1)` and `lookAt(0, 0, 0)`)

## Outdated

> ⚠️ The approach is valid. This app uses `WebGPURenderer` (the modern renderer), so it's up to date. The orthographic camera concept itself is timeless — it's fundamental to how projections work in computer graphics.
