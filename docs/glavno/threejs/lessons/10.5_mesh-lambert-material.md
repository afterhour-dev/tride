# 10.5 MeshLambertMaterial

## Concept

`MeshLambertMaterial` is the **first material in the series that requires lights**. Unlike `MeshBasicMaterial` (which ignores lighting entirely), `MeshLambertMaterial` responds to light sources in your scene — making it the simplest material that actually simulates how light interacts with surfaces.

### Why lights matter

Without lights, `MeshLambertMaterial` objects appear black. The material calculates how much light reaches each surface point based on:
- The light's position, type, and intensity
- The surface's orientation relative to the light (the surface normal)
- The material's properties (color, emissive, etc.)

### How it works

MeshLambert uses the **Lambertian reflectance model** — a simple, physically-inspired model where:
- Light reflects equally in all directions (diffuse reflection only)
- No specular highlights (shiny spots) are produced
- The brightness depends on the angle between the light and the surface normal

This makes it:
- **Fast** — the most performant material that responds to lights
- **Simple** — easy to understand and debug
- **Limited** — no specular highlights means surfaces look matte/diffuse only

### Shared properties with MeshBasicMaterial

`MeshLambertMaterial` inherits many properties from `MeshBasicMaterial`:
- `color` — the base color of the material
- `map` — texture map
- `alphaMap` — transparency texture
- `transparent` / `opacity` — alpha blending
- `side` — which faces to render (front, back, double)
- `wireframe` — wireframe rendering

### Light-related properties (new)

Since this is the first material that uses lights, it introduces:
- Responds to `AmbientLight`, `PointLight`, `DirectionalLight`, etc.
- `emissive` — color that glows regardless of lighting
- `emissiveMap` — texture for emissive glow
- `emissiveIntensity` — strength of the emissive effect

> We'll dive deeper into lights and their properties in a dedicated group of lessons — for now, we just added two simple lights to make the material visible.

### The artifact problem

The Lambertian model isn't perfect. On rounded geometries (like spheres), you can see **visible faceting** — the individual triangles become apparent, especially when:
- You remove ambient light and only use a point light
- The geometry has low segment counts

This happens because Lambert calculates lighting per-vertex (per face corner), not per-pixel. For smoother results, you'd use `MeshStandardMaterial` or `MeshPhongMaterial` instead.

## Code

in repo - `apps/10_5_MeshLambertMaterial`

```ts
import * as THREE from 'three/webgpu';

// Lights are REQUIRED — without them, objects appear black
const ambientLight = new THREE.AmbientLight(0xffffff, 1);
scene.add(ambientLight);

const pointLight = new THREE.PointLight(0xffffff, 30);
pointLight.position.set(2, 3, 4);
scene.add(pointLight);

// MeshLambertMaterial — simplest material that uses lights
const material = new THREE.MeshLambertMaterial();

// Create meshes with various geometries
const boxMesh = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  material
);

const sphereMesh = new THREE.Mesh(
  new THREE.SphereGeometry(0.5, 16, 16),
  material
);

const torusMesh = new THREE.Mesh(
  new THREE.TorusGeometry(0.3, 0.2, 16, 32),
  material
);

scene.add(boxMesh, sphereMesh, torusMesh);
```

## Gotchas

- **Objects appear black without lights** — unlike `MeshBasicMaterial`, `MeshLambertMaterial` requires at least one light source in the scene. If your objects are black, check that you've added lights.
- **Faceting on rounded geometries** — the Lambertian model calculates lighting per-vertex, so low-poly spheres and toruses show visible triangle edges. Increase segment counts or use `MeshStandardMaterial` for smoother results.
- **No specular highlights** — Lambert only produces diffuse reflection. If you need shiny surfaces, you'll need `MeshPhongMaterial` or `MeshStandardMaterial` instead.
- **Performance vs. quality trade-off** — while `MeshLambertMaterial` is the most performant light-responsive material, the visual quality is limited. For production work, `MeshStandardMaterial` is usually preferred.
