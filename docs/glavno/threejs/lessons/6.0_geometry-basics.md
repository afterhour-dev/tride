## Concept

Three.js provides a set of **built-in geometries** — pre-made shapes you can use to quickly create meshes without manually defining every vertex and triangle. All of them inherit from [`BufferGeometry`](https://threejs.org/docs/#api/en/core/BufferGeometry), which is the base class for all geometry types in Three.js.

### BufferGeometry — the foundation

Every built-in geometry (BoxGeometry, SphereGeometry, PlaneGeometry, etc.) is a subclass of `BufferGeometry`. This means they all share the same core properties and methods:

- **`attributes`** — contains the vertex data (position, normal, uv, etc.) stored as `BufferAttribute` instances
- **`index`** — defines how vertices are connected into triangles (indexed geometry)
- **`groups`** — defines material groups for multi-material meshes

Useful methods on `BufferGeometry`:
- **`translate(x, y, z)`** — moves all vertices by the given offset (does **not** move the mesh, only the geometry data itself)
- **`rotateX(angle)`**, **`rotateY(angle)`**, **`rotateZ(angle)`** — rotates all vertices around the origin
- **`normalize()`** — rescales all vertices so the geometry fits inside a unit sphere
- **`computeBoundingBox()`** / **`computeBoundingSphere()`** — calculates bounding volumes for frustum culling and raycasting

> These methods operate on the **vertices directly**, not on the mesh's position/rotation. This is an important distinction — you're modifying the geometry data, not the object transform.

### BoxGeometry in detail

`BoxGeometry` is the most commonly used geometry for learning. Its constructor:

```ts
BoxGeometry(width, height, depth, widthSegments, heightSegments, depthSegments)
```

- **`width`** (default `1`) — size along the X axis
- **`height`** (default `1`) — size along the Y axis
- **`depth`** (default `1`) — size along the Z axis
- **`widthSegments`** (default `1`) — number of segments along the width
- **`heightSegments`** (default `1`) — number of segments along the height
- **`depthSegments`** (default `1`) — number of segments along the depth

### What are segments?

**Segments** are subdivisions of a geometry's surface. When you increase the segment count, you're adding more vertices and triangles to the mesh. This is important for:

1. **Deformation** — more segments allow smoother bending, displacement, or vertex animation
2. **Level of detail** — more segments = higher resolution, but more GPU work
3. **Wireframe visualization** — segments are visible when using `wireframe: true` on the material

For a `BoxGeometry` with `widthSegments=4, heightSegments=2, depthSegments=6`:
- Each face of the box is divided into a grid
- Each grid cell is split into **2 triangles**
- The wireframe material shows these subdivisions clearly

> ⚠️ Segments in Three.js are **not** the same as subdivisions in Blender. In Blender, "subdivision surface" is a modifier that smooths geometry by adding new vertices based on Catmull-Clark algorithms. In Three.js, segments are simple grid divisions — no smoothing, just more geometry density.

### Geometries for meshes and particles

Geometries can be used to create **meshes** (visible surfaces with materials) but also **particles** (point clouds). Particle systems use the geometry's position attribute to place points in 3D space. This lesson focuses on meshes only.

## Code

in repo - `apps/6_geometries`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

const scene = new THREE.Scene();

// BoxGeometry with segments: width=1, height=3, depth=3
// segments: 4 width, 2 height, 6 depth
const boxGeometry = new THREE.BoxGeometry(1, 3, 3, 4, 2, 6);

// Wireframe material to visualize the segments
const material = new THREE.MeshBasicMaterial({
  color: 0x4c9892,
  wireframe: true,
});

const boxMesh = new THREE.Mesh(boxGeometry, material);
boxMesh.position.x = -1.5;
boxMesh.position.z = 0.5;
scene.add(boxMesh);

// Camera
const camera = new THREE.PerspectiveCamera(
  75,
  window.innerWidth / window.innerHeight,
  0.1,
  100,
);
camera.position.z = 3;
camera.position.x = 1;
scene.add(camera);

// Controls
const orbitControls = new OrbitControls(camera, canvas);
orbitControls.enableDamping = true;

// Renderer (WebGPU)
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.setClearColor(0x000000, 1);

// Axes helper for orientation
const axesHelper = new THREE.AxesHelper(5);
axesHelper.setColors('red', 'green', 'blue');
scene.add(axesHelper);

// Render loop
function tick() {
  orbitControls.update();
  renderer.render(scene, camera);
  window.requestAnimationFrame(tick);
}
window.requestAnimationFrame(tick);

// Resize handler
window.addEventListener('resize', () => {
  camera.aspect = window.innerWidth / window.innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(window.innerWidth, window.innerHeight);
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
});
```

## Gotchas

- **Wireframe thickness** — there's no built-in way to control wireframe line thickness in Three.js. The wireframe lines are always 1px regardless of distance or screen size. If you need thicker wireframes, you'd need a custom shader or use `EdgesGeometry` + `LineBasicMaterial` instead.
- **Pixel ratio in resize handler** — don't forget to call `renderer.setPixelRatio()` inside the resize handler too. If the user moves the window between screens with different pixel ratios, not updating it will cause blurriness or performance issues.

## Revisit

- Try creating different built-in geometries (SphereGeometry, TorusGeometry, etc.) and experimenting with their segment parameters
- Look into `EdgesGeometry` as an alternative to wireframe for cleaner edge rendering
- Explore how changing segment counts affects vertex count — count vertices manually for small segment values to build intuition
- Research the difference between indexed and non-indexed geometries (`toNonIndexed()`)
