## Concept

When you use a built-in geometry like `THREE.BoxGeometry` or `THREE.SphereGeometry`, Three.js generates all the vertex data internally. But sometimes you need a shape that doesn't exist in the library — or you want full control over every vertex. That's where `BufferGeometry` comes in.

### Creating vertices with `Float32Array`

A triangle is defined by 3 vertices, each with 3 components (x, y, z). That's 9 numbers total. Three.js expects this data as a **`Float32Array`** — a [Typed Array](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Float32Array) that stores 32-bit floating-point numbers in a fixed-length, contiguous block of memory.

```ts
// Allocate space for 9 floats (3 vertices × 3 components)
const verticesPositionArray = new Float32Array(9);

// Vertex 1
verticesPositionArray[0] = 0;  // x
verticesPositionArray[1] = 0;  // y
verticesPositionArray[2] = 0;  // z

// Vertex 2
verticesPositionArray[3] = 0;
verticesPositionArray[4] = 2;
verticesPositionArray[5] = 0;

// Vertex 3
verticesPositionArray[6] = 0;
verticesPositionArray[7] = 0;
verticesPositionArray[8] = 2;
```

You can also initialize it inline:

```ts
const verticesPositionArray = new Float32Array([
  0, 0, 0,  // vertex 1
  0, 2, 0,  // vertex 2
  0, 0, 2,  // vertex 3
]);
```

**Why `Float32Array`?** GPUs work with 32-bit floats natively. A regular JavaScript array holds arbitrary types and has dynamic sizing — both things that slow down GPU data transfer. `Float32Array` packs the data in a flat, typed buffer that the GPU can consume directly, which is why Three.js requires it (or other Typed Arrays) for geometry data.

The single parameter (`9`) is the **number of elements**, not bytes. Each element is 32 bits (4 bytes), so this buffer is 36 bytes in memory.

### `BufferGeometry` and `BufferAttribute`

`BufferGeometry` is the Three.js class for custom geometry. It doesn't store vertex data directly — instead, you attach **attributes** to it, each wrapped in a `BufferAttribute`:

```ts
const bufferGeometry = new THREE.BufferGeometry();

bufferGeometry.setAttribute(
  'position',
  new THREE.BufferAttribute(verticesPositionArray, 3),
);
```

The second parameter to `BufferAttribute` (here `3`) is the **itemSize** — how many array elements make up a single vertex component. For positions, it's 3 (x, y, z). For colors, it could be 3 (r, g, b) or 4 (r, g, b, a). For UVs, it's 2 (u, v).

The attribute name `'position'` tells Three.js what this data represents. Other common attribute names: `'normal'`, `'uv'`, `'color'`. Without normals, lighting calculations won't work correctly — but since this example uses `MeshBasicMaterial` (which ignores light), no normals are needed.

### Mesh: geometry + material = renderable object

```ts
const mesh = new THREE.Mesh(bufferGeometry, material);
scene.add(mesh);
```

`Mesh` is the standard renderable object in Three.js. It takes two arguments:
- A `BufferGeometry` (the shape)
- A `Material` (how it looks)

Without a geometry, there's nothing to draw. Without a material, there's no visual appearance. Both are required.

```ts
const verticesPositionArray = new Float32Array([
  0, 0, 0,  // vertex 1
  0, 2, 0,  // vertex 2
  0, 0, 2,  // vertex 3
]);

const bufferGeometry = new THREE.BufferGeometry();
bufferGeometry.setAttribute(
  'position',
  new THREE.BufferAttribute(verticesPositionArray, 3),
);

const material = new THREE.MeshBasicMaterial({ color: 0x4c9892 });
const mesh = new THREE.Mesh(bufferGeometry, material);
scene.add(mesh);
```

## Gotchas

- **Confusing the `Float32Array` length with vertex count.** The parameter `9` is the total number of floats, not the number of vertices. Divide by the itemSize (3 for positions) to get the vertex count: `9 / 3 = 3 vertices`.
- **Forgetting to set an attribute.** If you create a `BufferGeometry` but never call `setAttribute('position', ...)`, Three.js has no idea what shape to render — the mesh will be invisible with no error.
- **Using `MeshBasicMaterial` without realizing it ignores lights.** This is fine for simple geometry experiments, but if you switch to `MeshStandardMaterial` later and see a black screen, you'll need to add lights and normals.
- **ItemSize mismatch.** If your array has 9 elements but you set `itemSize` to `2`, Three.js will try to read 4.5 vertices — it won't crash but you'll get a corrupted triangle or an incomplete shape.

## Revisit

- Add a **normal** attribute to the geometry — without it, switching to a lit material (like `MeshStandardMaterial`) will show a black triangle. Normals tell the GPU which direction each vertex faces.
- Try creating a **quad** (two triangles) by adding 6 vertices (or use indexed geometry with 4 vertices and an index array).
- Explore `BufferAttribute.fromArray()` and `bufferGeometry.setFromPoints()` as shorthand alternatives to manual array filling.
- Look into **indexed geometry** — using an index buffer to share vertices between triangles, which is more memory-efficient for complex shapes.
