## Concept

[lil-gui](https://lil-gui.georgealways.com/) is a lightweight GUI library for tweaking parameters in the browser. It creates a small floating panel in the corner of the screen where you can adjust values and see changes in real time — extremely useful for experimenting with 3D scenes.

### GUI Types

lil-gui provides several control types, each suited for different data:

- **Range** — a slider for numeric values. Created with `.min()`, `.max()`, `.step()` chained after `.add()`.
- **Checkbox** — a boolean toggle. Automatically created when the property is a `boolean`.
- **Color** — a color picker. Created with `.addColor()` instead of `.add()`.
- **Button** — a clickable button. Created by adding a function as the property value.
- **Text** — created automatically for string properties.
- **Select** — a dropdown. Created with `.add(object, 'property', [options])`.

### Chaining vs Direct Parameters

lil-gui supports two styles for setting range constraints:

```ts
// Direct parameter style (positional args)
gui.add(boxMesh.position, 'y', -3, 3, 0.01);

// Chaining style (more declarative, preferred)
gui
  .add(boxMesh.position, 'y')
  .min(-3)
  .max(3)
  .step(0.01)
  .name('boxMesh.position.y');
```

The chaining style is more readable and self-documenting — you can see what each parameter does at a glance.

### The debugObject Pattern

You can't tweak a plain variable with `gui.add()` — lil-gui needs an object property. The workaround is a `debugObject` that holds properties outside of Three.js:

```ts
const debugObject = {
  color: '#527eaa',
  spin: () => {},
  lookAtMesh: false,
  subdivisions: 2,
};
```

This pattern is essential for two reasons:
1. **Plain variables can't be tweaked** — `gui.add(myVariable, "???")` has no property name to bind to.
2. **Color management** — Three.js applies color management internally, so the color displayed in the GUI isn't the raw value Three.js uses. Storing the color in a separate object lets you control the value before Three.js modifies it.

### Color Handling

The `color` property on Three.js materials is a `THREE.Color` instance, not a string. Three.js applies [color management](https://threejs.org/docs/#api/en/constants/Colors) (sRGB encoding) internally, which means the hex value you see in the GUI isn't the same as what Three.js uses for rendering.

Two solutions to get the correct color value:

1. **Use `getHexString()`** in an `onChange` handler to retrieve the modified color and apply it back to the material:
   ```ts
   .onChange((colorVal: THREE.Color) => {
     material.color.set(colorVal);
   });
   ```

2. **Store the color in `debugObject`** and pass it to the material constructor — this avoids the mismatch entirely by keeping the raw value separate from Three.js's internal representation.

### Geometry Tweaking

Geometry is created once and reused because it's expensive to allocate. You can't just set `boxGeometry.widthSegments = 5` — the geometry must be destroyed and recreated.

**Why `onFinishChange` instead of `onChange`**: When dragging a range slider, `onChange` fires on every pixel of movement. If you're creating a new `BoxGeometry` on each event, you're allocating hundreds of geometries per second. `onFinishChange` fires only when the user releases the slider, making it safe for expensive operations like geometry recreation.

```ts
gui
  .add(debugObject, 'subdivisions')
  .min(1)
  .max(20)
  .step(1)
  .onFinishChange((subdivs: number) => {
    // Dispose old geometry first
    boxGeometry.dispose();

    // Create new geometry with updated subdivisions
    boxMesh.geometry = new THREE.BoxGeometry(1, 1, 1, subdivs, subdivs, subdivs);

    // Reassign variable to point to new geometry
    boxGeometry = boxMesh.geometry;
  });
```

### Button (Function) Controls

You can add a function as a GUI property to create a clickable button:

```ts
debugObject.spin = () => {
  gsap.to(boxMesh.rotation, {
    duration: 1.5,
    y: boxMesh.rotation.y + Math.PI * 2,
  });
};
gui.add(debugObject, 'spin');
```

### Checkbox Controls

Boolean properties automatically become checkboxes:

```ts
gui.add(boxMesh, 'visible').name('boxMesh visible');
gui.add(boxMesh.material, 'wireframe').name('material wireframe');
gui.add(debugObject, 'lookAtMesh');
```

The `.name()` method lets you set a custom label for any control.

## Code

in repo - `apps/7_debug_ui`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';
import gsap from 'gsap';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;
const gui = new GUI();

const debugObject = {
  color: '#527eaa',
  spin: () => {},
  lookAtMesh: false,
  subdivisions: 2,
};

async function init() {
  const scene = new THREE.Scene();

  let boxGeometry = new THREE.BoxGeometry(1, 1, 1, 2, 2, 2);
  const material = new THREE.MeshBasicMaterial({
    color: debugObject.color,
    wireframe: true,
  });
  const boxMesh = new THREE.Mesh(boxGeometry, material);
  scene.add(boxMesh);

  // Range control
  gui.add(boxMesh.position, 'y').min(-3).max(3).step(0.01).name('boxMesh.position.y');

  // Checkbox
  gui.add(boxMesh, 'visible').name('boxMesh visible');
  gui.add(boxMesh.material, 'wireframe').name('material wireframe');

  // Color
  gui.addColor(debugObject, 'color').onChange((colorVal: THREE.Color) => {
    material.color.set(colorVal);
  });

  // Button (function)
  debugObject.spin = () => {
    gsap.to(boxMesh.rotation, { duration: 1.5, y: boxMesh.rotation.y + Math.PI * 2 });
  };
  gui.add(debugObject, 'spin');

  // Geometry tweak (onFinishChange)
  gui.add(debugObject, 'subdivisions').min(1).max(20).step(1).onFinishChange((subdivs: number) => {
    boxGeometry.dispose();
    boxMesh.geometry = new THREE.BoxGeometry(1, 1, 1, subdivs, subdivs, subdivs);
    boxGeometry = boxMesh.geometry;
  });

  const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 100);
  camera.position.set(1, 1.5, 3);
  scene.add(camera);

  const orbitControls = new OrbitControls(camera, canvas);
  orbitControls.enableDamping = true;

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();
  renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));
  renderer.setSize(window.innerWidth, window.innerHeight);

  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.visible = false;
  scene.add(axesHelper);
  gui.add(axesHelper, 'visible').name('axesHelper visible');

  function tick() {
    orbitControls.update();
    if (debugObject.lookAtMesh) {
      camera.lookAt(boxMesh.position);
    } else {
      camera.lookAt(new THREE.Vector3(0, 0, 0));
    }
    renderer.render(scene, camera);
    window.requestAnimationFrame(tick);
  }

  tick();
}

await init();
```

## Gotchas

- **Color mismatch** — The hex value you see in the lil-gui color picker doesn't match what Three.js uses internally. Three.js applies color management (sRGB encoding) to optimize rendering. If you copy the hex from the GUI and paste it directly into code as a color, you'll get a different result. Use `onChange` with `material.color.set()` to apply the value correctly.

- **Disposing geometry** — Always call `.dispose()` on the old geometry before creating a new one. Forgetting this causes a [GPU memory leak](https://threejs.org/docs/#api/en/core/Object3D.dispose). Dispose *before* creating the new geometry (though order between dispose and create doesn't technically matter, doing it first is clearer).

- **Reassigning the variable** — After creating a new geometry and assigning it to `boxMesh.geometry`, you must also reassign your `let` variable (`boxGeometry = boxMesh.geometry`). Otherwise the variable still points to the old (disposed) geometry.

- **`onChange` vs `onFinishChange` for geometry** — `onChange` fires on every slider movement. Creating a new geometry on each pixel of drag is expensive and can freeze the browser. Use `onFinishChange` for any operation that allocates or destroys resources.

- **Plain variables can't be GUI-tweaked** — `gui.add(myVariable, "???")` doesn't work. You need an object with a named property. Wrap plain variables in an object (`const obj = { myVar: 256 }`) before adding them to the GUI.

## Revisit

- **`addFolder()`** — This lesson covers the basics of lil-gui controls. The `addFolder` method for organizing controls into collapsible groups is covered in a separate lesson.
- **Color management in Three.js** — The color handling quirk is a symptom of Three.js's [color management system](https://threejs.org/docs/#api/en/constants/Colors). Understanding how `THREE.Color`, sRGB, and linear color spaces work will help avoid similar surprises with other color-related APIs.
- **Geometry disposal patterns** — Practice the dispose-then-recreate pattern until it's second nature. It applies to geometries, materials, and textures.

## Outdated

The approach is valid. lil-gui is a lightweight, well-maintained library specifically designed for this use case. There are no major deprecations or alternatives that supersede it for simple debug panels.
