## Concept

A `THREE.Group` is an invisible container in the scene graph. It inherits from `THREE.Object3D`, so it has the same `position`, `rotation`, and `scale` properties as any mesh — but it doesn't render anything itself. Its purpose is to let you treat multiple meshes as a single unit.

When you call `group.add(meshOne, meshTwo)`, those meshes become children of the group. Any transformation you apply to the group (position, rotation, scale) is **added on top of** each child's own transform. This means if you move the group, every child moves with it — but each child can still have its own local offset inside the group.

This is useful when you want to:
- Move, rotate, or scale several objects together without duplicating transform logic
- Organize your scene into logical clusters (e.g. a "table" group containing legs + surface)
- Build complex objects from simpler parts

**Multi-group membership:** In Three.js, a mesh can only have one parent. If you try to `group2.add(meshOne)` when `meshOne` is already in `group`, it gets silently removed from the first group and moved to the second. There's no error — the mesh just disappears from where you expected it to be. This is a common source of confusion.

**Group methods:** Since `Group` extends `Object3D`, you can use the same methods on it as on any mesh:
- `group.add(obj1, obj2, ...)` — add children
- `group.remove(obj)` — remove a child
- `group.children` — array of direct children
- `group.position`, `group.rotation`, `group.scale` — transform the whole group
- `group.localToWorld(vec)` / `group.worldToLocal(vec)` — coordinate space conversions

There are no group-specific methods beyond what `Object3D` provides — it's a simple container, not a special node type.

## Code

in repo - `apps/2_transform_group`

```ts
const group = new THREE.Group();
scene.add(group);

// Create meshes — note the shared geometry but individual materials
const meshOne = new THREE.Mesh(boxGeometry, material);
const meshTwo = new THREE.Mesh(
  new THREE.BoxGeometry(0.5, 0.5, 0.5),
  new THREE.MeshBasicMaterial({ color: 0x433024 }),
);
const meshThree = new THREE.Mesh(
  boxGeometry,
  new THREE.MeshBasicMaterial({ color: '#853a34' }),
);

// Add meshes to the group
group.add(meshOne, meshTwo);

// Individual local offsets within the group
meshOne.position.x = -1.5;
meshThree.position.x = 1.5;

// Group-level transforms — applied on top of children's own transforms
group.rotation.x = (45 * Math.PI) / 180;
group.scale.set(0.5, 0.5);
group.position.y = 0.5;
group.position.x = -0.5;

// meshThree is NOT in the group — it stays at its own position
scene.add(meshThree);
```

## Gotchas

- **Silent re-parenting:** Calling `group2.add(mesh)` when `mesh` is already in `group1` removes it from `group1` without warning. If your transforms stop working as expected, check `mesh.parent` to see which group actually owns it.
- **Transform stacking:** Group transforms compose multiplicatively with child transforms. If your group is rotated 45° and a child is also rotated 45°, the child ends up at 90° in world space. It's easy to double-count rotations.
- **Not a spatial container:** A `Group` has no bounds or collision — it's purely a transform hierarchy. Don't confuse it with physics or spatial partitioning concepts.

## Revisit

- Try making a mesh belong to multiple groups simultaneously and observe what happens (it won't work — confirm the one-parent rule)
- Explore `group.children`, `group.getObjectById()`, and `group.traverse()` to understand group traversal
- Look into `group.matrixWorld` and how parent transforms propagate through the scene graph
