## Concept

The **checkbox** is the simplest control type in [lil-gui](https://lil-gui.github.io/). It binds a GUI toggle to a boolean property on any object — when you click the checkbox, the property flips between `true` and `false` instantly.

### Basic syntax

```ts
gui.add(object, 'booleanProperty').name('Label');
```

`lil-gui` reads the current value of `object.booleanProperty` and creates a checkbox. Clicking it writes `true`/`false` back to the same property. No callbacks needed — the binding is live.

### What you can control

Any boolean property on any object works:

- **Three.js built-ins**: `mesh.visible`, `material.wireframe`, `axesHelper.visible`
- **Custom objects**: create a plain JS object (`debugObject`) and add your own boolean flags

### Why use a debug object?

Instead of toggling properties directly, many developers use a **debug object** — a plain JS object whose sole purpose is to hold flags for the GUI:

```ts
const debugObject = {
  lookAtMesh: false,
};

gui.add(debugObject, 'lookAtMesh');
```

This pattern is useful when:

- The property you want to toggle doesn't exist on a Three.js object yet
- You need a boolean that drives behavior in the animation loop (like camera `lookAt`)
- You want to keep GUI logic separate from scene logic

### Checkbox in the animation loop

When a checkbox controls something that updates every frame (like camera orientation), read its value inside `requestAnimationFrame`:

```ts
function tick() {
  if (debugObject.lookAtMesh) {
    camera.lookAt(boxMesh.position);
  } else {
    camera.lookAt(new THREE.Vector3(0, 0, 0));
  }
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
```

This approach works, but an `if` statement runs every frame. For a simple boolean check, the performance cost is negligible — but it's worth knowing that more complex GUI-driven logic (like changing materials or geometries) may need smarter update strategies.

### Accessing nested properties

You can pass nested objects directly to `gui.add()`:

```ts
gui.add(boxMesh.material, 'wireframe').name('material wireframe');
```

`boxMesh.material` is an object, and `wireframe` is its boolean property. `lil-gui` handles the nesting — you don't need to flatten anything.

## Code

in repo - `apps/7_gui_checkbox`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;
const gui = new GUI();

const debugObject = { lookAtMesh: false };

const scene = new THREE.Scene();

const boxGeometry = new THREE.BoxGeometry(1, 1, 1, 2, 2, 2);
const material = new THREE.MeshBasicMaterial({ color: 0x4c9892, wireframe: true });
const boxMesh = new THREE.Mesh(boxGeometry, material);
boxMesh.position.x = -1.5;
boxMesh.position.z = 0.5;
scene.add(boxMesh);

// Checkbox: toggle mesh visibility
gui.add(boxMesh, 'visible').name('boxMesh visible');

// Checkbox: toggle wireframe on the material
gui.add(boxMesh.material, 'wireframe').name('material wireframe');

// Checkbox: custom debug flag for camera lookAt
gui.add(debugObject, 'lookAtMesh');

const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);
scene.add(camera);

const axesHelper = new THREE.AxesHelper(5);
axesHelper.visible = false;
scene.add(axesHelper);
gui.add(axesHelper, 'visible').name('axesHelper visible');

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.setSize(window.innerWidth, window.innerHeight);
renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

function tick() {
  if (debugObject.lookAtMesh) {
    camera.lookAt(boxMesh.position);
  } else {
    camera.lookAt(new THREE.Vector3(0, 0, 0));
  }
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

## Gotchas

- **`gui.add()` needs the object, not the value** — passing `gui.add(true)` won't work. Always pass the object that owns the property, then the property name as a string.
- **Boolean binding is live** — changing `boxMesh.visible = false` in code will immediately update the checkbox state. This is convenient but can cause confusion if you toggle things from multiple places.
- **`debugObject` pattern is common** — don't feel like you need to attach every GUI control to a real Three.js property. A plain object is perfectly fine for custom toggles.
- **The `if` in the tick loop is fine for booleans** — but if you're changing materials, geometries, or doing heavier work based on a checkbox, consider caching the value and only acting when it changes.

## Revisit

- The `debugObject` pattern is worth internalizing — it's the standard way to bridge GUI controls and animation logic in Three.js projects
- If you need a dropdown instead of a checkbox, lil-gui has a `select` type — worth exploring when you have more than two options
- Consider what happens when you combine multiple checkboxes (e.g., visible + wireframe + lookAt) — the interactions can get interesting
