## Concept

Real-time 3D shadows have always been a challenge. Unlike raytracing — which simulates every light ray's path to produce pixel-perfect shadows — real-time rendering must use tricks to achieve reasonable results at interactive frame rates. Three.js has a built-in shadow system that is convenient but not perfect.

### Core Shadows vs Drop Shadows

When light hits an object, two types of shadows appear:

- **Core shadows** — the dark area on the object itself where light doesn't reach (e.g. the dark side of a sphere facing away from the light).
- **Drop shadows** — the silhouette projection of an object onto a surface behind or below it (e.g. the shadow of a sphere on the floor).

The code in this lesson focuses on getting **drop shadows** working — we want to see the sphere's shadow silhouette on the floor plane.

### How Three.js Shadow Maps Work

Three.js uses **shadow maps** under the hood. Here's the process:

1. When you render a frame, Three.js does an additional render pass **for each light that has shadows enabled**.
2. Each such pass simulates what the light "sees" — as if the light were a camera looking at the scene.
3. During these light renders, Three.js replaces every mesh's material with a `MeshDepthMaterial`, effectively rendering a depth map from the light's perspective.
4. The depth information is stored as a texture called a **shadow map**.
5. Back in the main render pass, every material that is set to receive shadows uses the shadow map to project the shadow onto its geometry.

This is not true raytracing — the shadow map is a snapshot of depth from one angle, so it has limitations like resolution boundaries (jagged edges), self-shadowing artifacts, and it only captures shadows the light directly "sees".

### Which Lights Support Shadows

Only three light types support shadow casting:

- `PointLight`
- `DirectionalLight`
- `SpotLight`

`AmbientLight`, `HemisphereLight`, and `RectAreaLight` do **not** cast shadows — they provide ambient fill or area illumination but lack the directional focus needed for shadow mapping.

### Activating Shadows in Three.js

Shadow setup requires three layers of configuration:

**1. Renderer** — enable the shadow system globally:

```ts
renderer.shadowMap.enabled = true;
```

**2. Per-object** — each mesh decides whether it casts and/or receives shadows:

```ts
floorMesh.receiveShadow = true;   // floor receives the sphere's shadow
sphereMesh.castShadow = true;     // sphere casts a shadow
```

**3. Per-light** — each shadow-capable light must have shadows enabled:

```ts
directionalLight.castShadow = true;
```

This granularity gives you control: a floor only receives shadows, a sphere casts and may receive, and each light decides whether to participate in the shadow map pipeline.

## Code

in repo - `apps/13_shadows`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

// Renderer
const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();
renderer.shadowMap.enabled = true; // Enable shadow system

// Scene
const scene = new THREE.Scene();

// Lights
const ambientLight = new THREE.AmbientLight(0xffffff, 1);
scene.add(ambientLight);

const directionalLight = new THREE.DirectionalLight(0xffffff, 1.5);
directionalLight.position.set(2, 2, -1);
directionalLight.castShadow = true; // Light casts shadows
scene.add(directionalLight);

// Objects
const material = new THREE.MeshStandardMaterial();
material.roughness = 0.7;

const sphere = new THREE.Mesh(
  new THREE.SphereGeometry(0.5, 32, 32),
  material,
);
sphere.castShadow = true; // Sphere casts a shadow

const floor = new THREE.Mesh(new THREE.PlaneGeometry(5, 5), material);
floor.receiveShadow = true; // Floor receives shadows
floor.rotation.x = -Math.PI / 2;
floor.position.y = -0.5;

scene.add(sphere, floor);

// Camera
const camera = new THREE.PerspectiveCamera(75, width / height, 0.1, 100);
camera.position.set(2, 1, 1);

// Controls
const controls = new OrbitControls(camera, canvas);
controls.enableDamping = true;

// Animation loop
renderer.setAnimationLoop(() => {
  controls.update();
  renderer.render(scene, camera);
});
```

## Gotchas

- **`renderer.shadowMap.enabled = true` must come after `await renderer.init()`** when using `WebGPURenderer`. Setting it before init will have no effect because the renderer hasn't been initialized yet.
- **A light's shadow direction is not independently rotatable.** The `DirectionalLight.lookAt()` method exists but doesn't always behave as expected for shadow orientation — the shadow map is tied to the light's position and target. The `debugObject.directLookAtCenter` button demonstrates this: calling `lookAt(new THREE.Vector3())` doesn't rotate the shadow direction the way you might intuitively expect.
- **The `ArrowHelper` for the light direction is computed once.** If you create it with the light's direction at a single point in time and then move the light, the arrow stays where it was. You'd need to update or recreate it each frame for a dynamic arrow.
- **`material.needsUpdate = true` is required when toggling `wireframe` on `MeshStandardMaterial` in WebGPU** — or the material won't recompile and the change won't take effect visually.
- **Not all materials receive shadows by default.** While most built-in materials do, custom `ShaderMaterial` setups need explicit handling for shadow reception.
- **Shadows have a resolution limit.** The default shadow map resolution may look blocky or jagged — optimizing shadow map size, filtering, and bias is where the real work lies beyond this intro.

## Revisit

- The `directionalLight.lookAt()` behavior needs more investigation — currently it does not affect the shadow projection direction as expected. Understanding how Three.js maps the directional light's frustum for shadow casting would clarify this.
- Shadow map optimization (resolution, PCF soft shadows, bias tuning) is not covered here — this is just the introduction.

approach is valid
