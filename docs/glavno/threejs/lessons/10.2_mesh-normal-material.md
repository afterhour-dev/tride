# 10.2 mesh-normal-material


![[meshnormalmaterial.png]]
## Concept

`MeshNormalMaterial` is a Three.js material that colors each face of a mesh based on the **orientation of its surface normals** relative to the camera. Instead of using colors, textures, or lighting calculations, it maps the direction each face is pointing to a color value.

### What are normals?

Normals are vectors (directions) stored at each vertex of a geometry. They point outward from the surface and encode which way that part of the face is "facing." Normals are essential for:

- **Lighting** — calculating how much light hits a surface based on the angle between the light direction and the surface normal
- **Reflections and refractions** — determining how the environment should reflect or refract on the surface
- **Debugging** — visualizing whether normals are pointing the right direction

### How MeshNormalMaterial colors faces

The material maps the normal's X, Y, Z components to RGB color channels. Since normals point in different directions across a curved surface, you get a rainbow-like gradient effect. Faces pointing toward the camera appear differently than faces pointing away.

The purple, blue, and green hues you see are a direct visualization of the normal orientation — similar to what you'd see in a normal map texture used in PBR materials.

### Debugging with MeshNormalMaterial

One of the most common uses is **debugging normals**. If your geometry looks wrong or lighting is off, switching to `MeshNormalMaterial` quickly shows you whether normals are flipped, duplicated incorrectly, or missing.

### Other uses

Beyond debugging, the material can be used for:
- **Stylized effects** — the colorful gradient can look great as-is
- **Post-processing inputs** — normal data can feed into custom shaders for effects like edge detection or ambient occlusion

### Flat shading

The `flatShading` property (set to `true` in the app) makes each face a single solid color rather than smoothly interpolating across triangles. This gives a faceted, low-poly look and makes it easier to see individual faces and their orientations.

## Code

in repo — `apps/10_2_MeshNormalMaterial`

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';

const scene = new THREE.Scene();

// Create geometries
const boxGeometry = new THREE.BoxGeometry(1, 1, 1);
const sphereGeometry = new THREE.SphereGeometry(0.5, 16, 16);
const torusGeometry = new THREE.TorusGeometry(0.3, 0.2, 16, 32);

// MeshNormalMaterial — colors based on surface normal orientation
const material = new THREE.MeshNormalMaterial();
material.flatShading = true; // Faceted look — one color per face

// Create meshes
const boxMesh = new THREE.Mesh(boxGeometry, material);
boxMesh.position.x = 1.5 * 8;
boxMesh.position.z = 3;

const sphereMesh = new THREE.Mesh(sphereGeometry, material);
sphereMesh.position.x = -1.5;

const torusMesh = new THREE.Mesh(torusGeometry, material);
torusMesh.position.x = 1.5;

scene.add(boxMesh, sphereMesh, torusMesh);

// Camera and renderer
const camera = new THREE.PerspectiveCamera(75, window.innerWidth / window.innerHeight, 0.1, 100);
camera.position.set(1, 1.5, 3);

const renderer = new THREE.WebGPURenderer({ canvas });
await renderer.init();

// Render loop
function tick() {
  boxMesh.rotation.y += 0.01;
  sphereMesh.rotation.y += 0.01;
  torusMesh.rotation.y += 0.01;
  renderer.render(scene, camera);
  requestAnimationFrame(tick);
}
requestAnimationFrame(tick);
```

## Gotchas

- **No color or lighting** — MeshNormalMaterial ignores lights completely. It won't respond to directional lights, point lights, or ambient light. This is by design — the color comes purely from normal orientation.
- **`flatShading: true` vs `false`** — With flat shading off (default), colors interpolate smoothly across faces. With it on, each triangle is a solid color. The visual difference is significant — flat shading makes the faceted structure obvious.
- **Normals can be wrong** — If your geometry was imported from a model or generated procedurally, normals might be flipped or missing. MeshNormalMaterial is the fastest way to spot this.
