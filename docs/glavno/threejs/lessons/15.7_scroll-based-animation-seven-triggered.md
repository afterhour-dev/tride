## Concept

This is the last lesson in the scroll-based-animation series, a direct continuation of [[15.6_scroll-based-animation-particles]]. By now we have a scene where the camera scrolls down a vertical stack of three toon-shaded meshes (a torus, a cone, a torus knot), each spaced `objectsDistance` apart along −Y, while a mouse parallax smoothly offsets a wrapping `cameraGroup`. Particles float in the background. The scene already scrolls and feels deep.

**The goal of this lesson is to make the objects react to *where you are* in the scroll** — to trigger a little spin on a mesh exactly when you arrive at its corresponding section, in addition to the permanent rotation that's always running.

So we have two kinds of rotation fighting for the same property:

1. A **permanent** continuous rotation applied every frame inside `tick()`.
2. A **triggered** one-shot spin applied by [GSAP](https://gsap.com/) when you reach a new section.

The whole lesson is really about two things: **knowing when you changed sections**, and **making the permanent + triggered rotations coexist without one destroying the other**.

### 1 — Knowing when we reach a section, using only `scrollY`

`// EXPLAIN:` there are plenty of ways to detect which section you're in (IntersectionObserver, a library, etc.), but here we use raw scroll math because our HTML sections are each exactly `100vh`.

```ts
let scrollY = window.scrollY;
let currentSection = 0;

window.addEventListener('scroll', () => {
    scrollY = window.scrollY;

    // scrollY / viewport-height  ->  0..2  (three sections)
    const newSection = Math.round(scrollY / sizes.height);
    // Math.round turns that into exactly 0, 1, or 2

    if (currentSection !== newSection) {
        currentSection = newSection;
        // <-- trigger the spin here
    }
});
```

Let's unpack that:

- When `scrollY` is between `0` and `0.5 * height`, `scrollY / height` is between `0` and `0.5`, which rounds to `0` → first section.
- Between `0.5 * height` and `1.5 * height` it rounds to `1` → second section.
- Between `1.5 * height` and `2.5 * height` it rounds to `2` → third section.

The `Math.round` maps a continuous scroll position onto discrete section indices. The `if (currentSection !== newSection)` guard ensures we only react on the *transition* between sections, not on every single scroll event (which fires dozens of times per second). We trigger only on the change — that's what "triggered animation" means.

### 2. The triggered spin with GSAP

```js
gsap.to(selectionMeshes[currentSection].rotation, {
    duration: 1.5,
    ease: 'power2.inOut',
    x: '+=6',
    y: '+=3',
    z: '+=1.5',
});
```

`gsap.to` tweens the rotation object toward the given values over `1.5` seconds with a `power2.inOut` ease — starting slow, speeding up, finishing slow. The `x: '+=6'` (relative suffix) means "add 6 full rotations *on top of the current value*", not "set x to exactly 6". That relative form is the key: it composes with whatever rotation is already there.

### 3. The core gotcha: permanent rotation vs GSAP

This is the whole reason the lesson exists. `// EXPLAIN:` a naive permanent rotation writes the rotation *directly* every frame:

```js
// BAD: this overwrites GSAP every frame
mesh.rotation.x = elapsedTime * 0.1;
mesh.rotation.y = elapsedTime * 0.12;
```

The `=` assignment clobbers whatever GSAP just set, so the triggered spin is instantly erased on the next frame — you'd never see it.

We fix it by replacing assignment with **increment using delta time**:

```js
// GOOD: keep permanent spin, but ADD to it every frame so it stacks with GSAP
mesh.rotation.x += delta * 0.1;
mesh.rotation.y += delta * 0.12;
```

`+=` is the whole story. Because both the permanent rotation (in `tick`) and the triggered rotation (GSAP) use relative addition, the numbers compose. There's no live fight — GSAP handles its temporary burst, and the permanent `+=` keeps slowly rotating on top.

`// EXPLAIN:` detail — *why delta time, not elapsed time?* If we increment by `elapsedTime * 0.1`, the added amount grows to the total number of seconds since start each frame, so the increment magnitude becomes enormous and the mesh would whirl out of control. With `delta` (the fraction of a second since the last frame, typically ~0.016), each frame adds a small fixed angular step, so the cumulative rotation stays smooth and bounded. Incrementing requires per-frame deltas; assignment can use elapsed time because it sets an absolute value.

## Code

in repo - `apps/15_7_scroll_based_animation_seven`

```ts
// Scene, renderer (WebGL so ParticlesMaterial works), cameraGroup, etc. — as in 15.6

let scrollY = window.scrollY;
let currentSection = 0;

window.addEventListener('scroll', () => {
    scrollY = window.scrollY;

    // sections are exactly 100vh, so scrollY/height is 0..2
    const newSection = Math.round(scrollY / sizes.height);
    if (currentSection !== newSection) {
        currentSection = newSection;

        // triggered spin (relative += means "add 6 more")
        gsap.to(selectionMeshes[currentSection].rotation, {
            duration: 1.5,
            ease: 'power2.inOut',
            x: '+=6',
            y: '+=3',
            z: '+=1.5',
        });
    }
});

function tick(timestamp: number) {
    timer.update(timestamp);
    const delay = timer.getDelta();

    camera.position.y = -(scrollY * debugObject.objectsDistance) / sizes.height;
    // ... parallax easing on cameraGroup ...

    for (const mesh of selectionMeshes) {
        // increments (+=), NOT assignment (=), so the GSAP spin survives
        mesh.rotation.x += delay * 0.1;
        mesh.rotation.y += delay * 0.12;
    }

    renderer.render(scene, camera);
}
```

## Gotchas

- **Assigning with `=` instead of incrementing `+=`.** If the permanent rotation does `mesh.rotation.x = elapsedTime * 0.1`, it overwrites GSAP's value every frame and the triggered spin never appears. The whole lesson is the `+=` vs `=` distinction.
- **Using `elapsedTime` with increment.** If you switch to `+=` but keep multiplying by `elapsedTime` instead of `delta`, the increment magnitude grows with the total running time and the mesh spins out of control. `// GOTCHA:` increment needs `delta`; assignment needs `elapsed`.
- **Forgetting to guard the scroll handler.** `scroll` fires many times a second. Without `if (currentSection !== newSection)` you'd re-trigger the tween repeatedly mid-section. The guard makes it fire only on section transitions.
- **`Math.round` vs section boundaries.** Because sections are exactly `100vh`, integer-rounding `scrollY / sizes.height` works cleanly. If your sections had different or fractional heights, this trick breaks — you'd need the bounding-box / offset approach.
- **GSAP must increment relatively (`'+=6'`), not absolutely (`6`).** Absolute would reset rotation to a fixed value and immediately get overridden anyway; the relative suffix is what composes with the running rotation.

## Revisit

- **Why delta time is required for incremental rotation** — derive that incrementing by `elapsedTime` gives unbounded growth while `delta` keeps it stable. Practice explaining it step-by-step.
- **Section detection beyond round-to-index.** This lesson hard-codes the `100vh` assumption. Revisit alternatives (`Element.getBoundingClientRect()`, IntersectionObserver, or a scroll library) for arbitrary layout heights.
- **Improvements the README noted as not done here:** animate other properties (material color, scale), ease/animate the HTML text itself, refine the particles, or add more GUI tweaks. Those are natural follow-ups.
- **GSAP `power2.inOut` and other easing curves** — revisit from a deeper animation-easing perspective.

## Outdated

approach is valid

The scroll + GSAP triggered-animation technique is still current and widely used. **Note:** this app runs on the WebGL renderer because the series uses built-in `PointsMaterial` for particles (WebGPU points support wasn't available in the Three.js version used). The GSAP + scroll trigger idea itself is renderer-agnostic and remains a real approach. If you want to move the particle scene to WebGPU, custom ShaderMaterial points would be the modern path — but that doesn't change the scroll/trigger concept documented here.

> 💡 More up to date alternative: [GSAP ScrollTrigger](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) 🤖 suggested — this lesson detects sections manually with `scrollY` math; ScrollTrigger is the standard modern plug-in way to trigger animations on scroll with less hand-rolled code.
