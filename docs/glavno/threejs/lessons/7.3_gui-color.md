# GUI Color & Color Management Quirk

## Concept

The `color` property on a Three.js material is a `THREE.Color` instance — not a string, not a number. This matters because lil-gui's `.addColor()` interacts with it in a way that can surprise you.

### The Problem

When you tweak a color in lil-gui, the hex value displayed in the color picker is the **displayed** (sRGB) value. But Three.js internally stores colors in **linear** space for rendering. So if you copy the hex code from the GUI and paste it directly into your code as a material color, you get a different result — Three.js will convert that hex again, double-encoding it.

### The debugObject Pattern

Plain variables can't be tweaked by lil-gui (it needs an object property to bind to), so we store the color in a `debugObject`:

```ts
const debugObject = {
  color: '#527eaa',
};
```

Then initialize the material from that object:

```ts
const material = new THREE.MeshBasicMaterial({
  color: debugObject.color,
});
```

This keeps the raw color value outside of Three.js's internal pipeline.

### Two Solutions for the Color Mismatch

**Solution 1 — `onChange` handler:**

Bind the GUI to `debugObject.color` instead of `material.color`, and in the `onChange` handler, apply the color back to the material using `.set()`:

```ts
gui
  .addColor(debugObject, 'color')
  .onChange((colorVal: THREE.Color) => {
    material.color.set(colorVal);
  });
```

This works because `.set()` on a `THREE.Color` accepts a `THREE.Color` instance directly — no hex string copying needed.

**Solution 2 — `getHexString()`:**

If you want to hardcode a color from the GUI into your code, use `getHexString()` to get the linear-space hex value:

```ts
.onChange((colorVal: THREE.Color) => {
  console.log(colorVal.getHexString());
  // copy the output and use it as: color: 0x...
});
```

This is more manual but useful when you want to commit a specific color to code.

### Why Three.js Does This

Three.js applies [color management](https://threejs.org/docs/#api/en/constants/Colors) (sRGB encoding) to optimize rendering. Colors are stored and processed in linear space internally, then converted to sRGB for display. The color value you see in the tweak panel is the sRGB representation — not what Three.js uses internally. This is by design, not a bug, but it means you can't just copy-paste hex values between GUI and code.

```ts
import * as THREE from 'three/webgpu';
import { OrbitControls } from 'three/examples/jsm/Addons.js';
import GUI from 'lil-gui';

  color: '',

async function init() {
  const scene = new THREE.Scene();

  debugObject.color = '#527eaa';

  const boxGeometry = new THREE.BoxGeometry(1, 1, 1, 2, 2, 2);
  const material = new THREE.MeshBasicMaterial({
    color: debugObject.color,
  });

  const boxMesh = new THREE.Mesh(boxGeometry, material);
  boxMesh.position.x = -1.5;
  boxMesh.position.z = 0.5;
  scene.add(boxMesh);

  // Bind to debugObject, not material — avoids color mismatch
  gui
    .addColor(debugObject, 'color')
    .onChange((colorVal: THREE.Color) => {
      material.color.set(colorVal);
    });

  gui.add(boxMesh.material, 'wireframe').name('material wireframe');

  // ... camera, controls, renderer, resize, tick loop ...
}
```

## Gotchas

- **Copying hex from GUI gives wrong color** — The hex value in lil-gui's color picker is the sRGB display value. Pasting it directly into code as a color will be double-encoded by Three.js. Always use `.onChange()` with `material.color.set()` or `getHexString()`.

- **Binding `addColor` directly to `material.color`** — If you do `gui.addColor(material, 'color')`, lil-gui modifies the `THREE.Color` instance directly, which can lead to unexpected results because the color management pipeline interferes. Use a separate `debugObject` and apply changes in `onChange`.

- **`colorVal` in `onChange` is a `THREE.Color` instance** — Don't treat it as a string. You can call `.getHexString()`, `.getStyle()`, or pass it to `.set()` on another color. It's not a hex string you can compare with `===`.

## Revisit

- **Three.js color management** — This quirk is a symptom of Three.js's [color management system](https://threejs.org/docs/#api/en/constants/Colors). Understanding how `THREE.Color`, sRGB, and linear color spaces work will help avoid similar surprises with textures, lighting, and post-processing.
- **`getHexString()` vs `.getStyle()`** — `getHexString()` returns the hex without `#` (e.g. `"527eaa"`), while `.getStyle()` returns the CSS-style string (e.g. `"#527eaa"`). Know which one you need.
- **Color in materials vs geometry attributes** — This lesson covers material colors. Vertex colors (stored in buffer geometry attributes) have their own quirks with color management.

## Outdated

The approach is valid. lil-gui's `addColor` is the standard way to add color pickers to debug panels. Three.js color management has been stable since r152 and is unlikely to change.
