# Directional Light

Exploring `DirectionalLight` — the three.js light type that simulates a far-away, sun-like source whose rays travel in parallel across the whole scene.

## Concept

A `DirectionalLight` behaves like the **sun**: its rays arrive across the scene as a set of **parallel lines**, all traveling in the same direction. Because the real sun is so far away, the light striking your scene barely diverges — **every surface pointing toward the sun gets hit by rays coming from essentially the same angle**. That's exactly what `DirectionalLight` models.

### Why parallel rays matter

Because the rays are parallel, the light direction is **constant everywhere in the scene** — it does not fan out from a single point the way a `PointLight` does. This means:

- A whole scene (many objects) all receive light from the **same** direction.
- Which surfaces are lit depends only on their orientation relative to that direction, not on their distance from any "light bulb".
- One side of every object is bright, the opposite side falls into darkness — which is exactly what makes the sun's directional quality readable.

### Color and intensity

Like `AmbientLight`, `DirectionalLight` accepts two arguments at construction:

```ts
const directionalLight = new THREE.DirectionalLight(0x00fffc, 0.3);
```

- **`color`** — `0x00fffc` here, a cyan/teal light.
- **`intensity`** — `0.3`, the brightness.

You can also set `.color` and `.intensity` **after** instantiation, or skip both arguments and assign later — which is handy when you expose them to a lil-gui panel. In the GUI the intensity is limited to a `0–1` range with `0.001` steps so bright/cutoff behavior can be observed live.

### The position question: where does the light come from?

The trick is that a directional light **does have a position**, but the position only matters through the **direction** it implies. The light emits parallel rays pointing *from* `light.position` *toward* `light.target` (which defaults to the origin `(0, 0, 0)`).

In this app the **default position is `(0, 1, 0)`** — so by default the light shines straight down from directly above. That's why, when ambient intensity is lowered to `0`, only the **top/facing-upward** surfaces of the sphere are lit and the bottom halves fall into shadow. The README even notes this was discovered by adding `position.x/y/z` to the GUI and watching them — a default of `(0, 1, 0)` means "light from above".

To make the light come from a different direction, reposition it — the README example moves it to the **right** by lowering `y` and raising `x`:

```ts
directionalLight.position.set(1, 0.25, 0);
```

Now rays travel roughly leftward, lighting the right-facing sides of the spheres and boxing while leaving left-facing sides dark.

### Why distance doesn't matter (for now)

Because `DirectionalLight` rays are parallel and the light has **no decay/attenuation over distance**, moving the light closer or farther does **not** change how bright the scene is — only its *direction* changes the result. This is unlike point/spot lights, which brighten as you bring a surface nearer. The README notes this distance-insensitivity and flags that it will matter once **shadows** are the subject: the direction (position) determines where shadows fall, and shadow casting uses an orthographic shadow camera where distance does influence the shadow frustum.

### Visualizing the light's direction with helpers

Since an invisible directional light is hard to reason about, the app layers three helpers:

- **`AxesHelper(5)`** — shows the world `x/y/z` axes, so you can read off *which* world direction the light is traveling.
- **`DirectionalLightHelper(light, 5)`** — draws a small plane at the light's position plus a line pointing toward its target, making the "source" and its direction visible.
- **`ArrowHelper(normalized direction, origin, length)`** — an arrow from the scene origin pointing along the (normalized) light position, making "light comes from here" obvious at a glance.

All three ship with a `visible` toggle in the GUI so you can switch them on while experimenting.

### MeshStandardMaterial needs light

As in the previous lesson, the meshes use `MeshStandardMaterial` (`roughness = 0.4`), a physically-based material that **requires** light sources to be visible. Without any lights the surfaces render black. Combining a low `AmbientLight` (for fill) with the `DirectionalLight` (for direction and depth) is what makes the objects read as three-dimensional.

## Code

in repo - `apps/12_2_directional_light`

```ts
import * as THREE from 'three/webgpu';

const canvas = document.querySelector<HTMLCanvasElement>('canvas#tride')!;

async function init() {
  const scene = new THREE.Scene();

  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init();

  // Ambient light — uniform fill so dark sides aren't pure black
  const ambientLight = new THREE.AmbientLight(0xffffff, 0.5);
  scene.add(ambientLight);

  // Directional light — sun-like, parallel rays.
  // Default position is (0, 1, 0): straight down from above.
  const directionalLight = new THREE.DirectionalLight(0x00fffc, 0.3);
  directionalLight.position.set(1, 0.25, 0); // shine from the right
  scene.add(directionalLight);

  // Helpers let you reason about the light's direction
  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.setColors('red', 'green', 'blue');
  scene.add(axesHelper);

  const directionalLightHelper = new THREE.DirectionalLightHelper(directionalLight, 5);
  scene.add(directionalLightHelper);

  const arrowHelper = new THREE.ArrowHelper(
    directionalLight.position.clone().normalize(), // direction
    new THREE.Vector3(0, 0, 0), // origin
    1, // length
    0xffffff,
  );
  scene.add(arrowHelper);

  // Surfaces — MeshStandardMaterial needs lights to be visible
  const material = new THREE.MeshStandardMaterial();
  material.roughness = 0.4;

  const box = new THREE.Mesh(new THREE.BoxGeometry(0.75, 0.75, 0.75), material);
  const torus = new THREE.Mesh(new THREE.TorusGeometry(0.3, 0.2, 32, 64), material);
  torus.position.x = 1.5;
  const sphere = new THREE.Mesh(new THREE.SphereGeometry(0.5, 32, 32), material);
  sphere.position.x = -1.5;
  const floor = new THREE.Mesh(new THREE.PlaneGeometry(5, 5), material);
  floor.rotation.x = -Math.PI / 2;
  floor.position.y = -0.65;

  scene.add(box, torus, sphere, floor);

  // Camera
  const camera = new THREE.PerspectiveCamera(75, innerWidth / innerHeight, 0.1, 100);
  camera.position.set(2, 1, 1);
  scene.add(camera);

  // Render loop
  renderer.setPixelRatio(Math.min(devicePixelRatio, 2));
  renderer.setSize(innerWidth, innerHeight);
  renderer.setAnimationLoop(() => {
    renderer.render(scene, camera);
  });
}

await init();
```

## Gotchas

- **Distance does nothing to a directional light's brightness.** There is no attenuation over distance, unlike point/spot lights. If you move the light farther away expecting it to dim, nothing happens — only the *direction* changes. This bites people coming from point lights. Distance matters only later, when shadows are involved.

- **The default position is `(0, 1, 0)`**, meaning "light from straight above." If you forget to set a position, top surfaces are lit and anything facing down or sideways falls into shadow. You can't easily tell where it comes from without a helper.

- **The light's position is just a direction, not an actual light source you can see.** `DirectionalLight` draws nothing in the scene; only the meshes reveal its effect. That's why the helpers (axes, directional helper, arrow) are worth toggling on while experimenting.

- **Direction is *from* position *toward* target (default origin).** To light an object from its right side, put the light to the *right* (positive x) and toward it — here lowering `y` keeps it from being a from-above light.

- **`MeshStandardMaterial` renders black without lights, and `AmbientLight` alone is flat.** With ambient intensity at `0`, the directional light alone leaves the back-facing halves of objects completely black — the contrast is intentional, and a low ambient fill keeps the dark side visible.

- **`await renderer.init()` is mandatory for WebGPU.** The `WebGPURenderer` must finish async initialization before rendering, or you get a blank canvas.

## Revisit

- **Shadows** — come back to how `DirectionalLight` casts shadows. Its shadow camera is **orthographic** (parallel rays → an ortho frustum), and *there* the position/distance does influence the shadow volume. This is the lesson where the README hinted the "distance matters" note pays off.

- Lower the ambient intensity to `0` on purpose and rotate the camera around each shape to really internalize *which* face is lit for a given light position. This makes the parallel-ray mental model concrete.

- Try the same scene with a `PointLight` and observe the difference: rays diverge from one point, corners of the box get unequal light, and a surface's brightness now depends on its distance from the light. This contrast clarifies what "parallel" buys you.

- Look into **`target`** — a directional light's direction can be steered by moving `light.target` to a specific object instead of relying on the default origin. Useful for follow-style lighting.

- Consider `HemisphereLight` for a more natural sky/ground ambient fill, paired with the directional sun.
