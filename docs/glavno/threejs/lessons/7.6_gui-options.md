# GUI Options

## Concept

[lil-gui](https://lil-guiCumhurbaşkan.org/) supports several control types: sliders, checkboxes, color pickers, and — this lesson's focus — **dropdown selects** (called "options" in lil-gui).

### The options object

When you call `gui.add(object, property, options)`, lil-gui detects the third argument and renders a **dropdown select** instead of a slider:

```ts
gui.add(debugObject, 'speed', {
  slow: 2,
  fast: 6,
});
```

The object keys become the **display labels** (`"slow"`, `"fast"`). The values become what the property is set to when that option is selected. So selecting "slow" sets `debugObject.speed = 2`, and "fast" sets it to 6.

This is different from `gui.add(object, property, min, max)` which creates a slider range. The options form is best when you have a small, fixed set of named presets rather than a continuous range.

### Button controls

Passing a **function** as the property creates a button:

```ts
gui.add(debugObject, 'spin');
```

Clicking it calls `debugObject.spin()`. In this app, `spin` uses gsap to rotate the box by `Math.PI * debugObject.speed` — so the speed dropdown controls how far the button rotates the box.

### Checkbox controls

Passing a **boolean** property creates a checkbox:

```ts
gui.add(axesHelper, 'visible').name('axesHelper visible');
```

Toggling it sets `axesHelper.visible` to `true` or `false`, which Three.js picks up on the next render.

### Tying controls together

The spin button and speed dropdown work together because they share the same `debugObject`:

```ts
const debugObject = {
  spin: () => {},          // button — will be overwritten
  speed: 2,                // dropdown — controls rotation amount
};

debugObject.spin = mojaFunkcije;  // assign the actual function
gui.add(debugObject, 'spin');     // button
gui.add(debugObject, 'speed', { slow: 2, fast: 6 }); // dropdown
```

The `mojaFunkcije` function reads `debugObject.speed` at call time, so changing the dropdown affects the next spin.

```ts
const gui = new GUI();

const debugObject = {
  spin: () => {},
  speed: 2,
};

// Button — calls debugObject.spin() on click
debugObject.spin = () => {
  gsap.to(boxMesh.rotation, {
    duration: 1.5,
    y: boxMesh.rotation.y + Math.PI * debugObject.speed,
  });
};
gui.add(debugObject, 'spin');

// Dropdown — selects from named presets
gui.add(debugObject, 'speed', {
  slow: 2,
  fast: 6,
});

// Checkbox — toggles boolean property
gui.add(axesHelper, 'visible').name('axesHelper visible');
```

## Gotchas

- **Options vs range** — `gui.add(obj, 'prop', { a: 1, b: 2 })` creates a dropdown. `gui.add(obj, 'prop', 0, 10)` creates a slider. The third argument's type determines the control type. Mixing them up is a common mistake.

- **Labels are object keys** — The display labels in the dropdown are the keys of the options object, not the values. `{ slow: 2, fast: 6 }` shows "slow" and "fast" as options, not "2" and "6".

- **Property type matters** — The initial type of the property determines the control. If `debugObject.speed` starts as `2` (a number), you get a dropdown with options. If it started as `true` (a boolean), you'd get a checkbox instead.

- **Button functions** — When you pass a function as the property value, lil-gui renders a button. The function reference is called on click — it does not get the selected value passed to it.

## Revisit

- The `debugObject` pattern (a plain object whose properties control the scene) is a common Three.js convention for debug UIs. It keeps GUI setup separate from scene logic.
- Practice adding more option presets — try a third option like `{ slow: 2, medium: 4, fast: 6 }` to see how the dropdown adapts.
- Consider using `gui.add(object, property).name('Custom Label')` to give controls friendlier names when the property name isn't descriptive.
