## Concept

This is a Vite + Three.js starter template that uses **WebGPU** as its rendering backend instead of the older WebGL. It's the foundation for future projects in this monorepo.

### WebGPU vs WebGL

WebGL is the older graphics API for the browser — it's based on OpenGL ES and has been the standard for 3D on the web for over a decade. WebGPU is its successor, designed from the ground up to map better to modern GPU hardware (Vulkan, Metal, DX12). Three.js supports both through different renderer classes:

- `WebGLRenderer` — the classic path, works everywhere
- `WebGPURenderer` — the new path, auto-falls back to WebGL2 when WebGPU isn't available

The import path changes too. Instead of `import * as THREE from 'three'`, you import from the WebGPU-specific entry point:

```ts
import * as THREE from 'three/webgpu';
```

This gives you the WebGPU-enabled build of Three.js, including the new TSL (Three Shading Language) and compute shader support.

### Async initialization

WebGL context creation is synchronous — you call `new WebGLRenderer()` and it's ready. WebGPU is different. Before the renderer can draw anything, it needs to negotiate a **GPU adapter** and **device** with the browser. This is an asynchronous operation.

Three.js gives you two options:

1. **Call `await renderer.init()` once**, then render normally with `renderer.render(scene, camera)` every frame.
2. **Skip `init()` and call `await renderer.renderAsync(scene, camera)`** each frame — it lazily initializes on the first call.

This app uses option 1 — a single `await renderer.init()` inside the async `init()` function, then a synchronous `renderer.render()` call. This is the cleaner pattern because you only pay the async cost once.

### Why `setClearColor` is required

With `WebGLRenderer`, the canvas defaults to an opaque black background out of the box. `WebGPURenderer` (especially when it falls back to WebGL2) does not — you need to explicitly set it:

```ts
renderer.setClearColor(0x000000, 1);
```

Without this, the background may appear transparent or have unexpected colors depending on the browser and GPU backend. This is a known gotcha documented in the app's [WebGPU dev setup notes](../../../apps/0_vite_webgpu_starter/Webgpu%20dev%20setup.md).

### Top-level await

The app uses top-level `await` in `main.ts`:

```ts
await init();
```

This works with Vite out of the box — Vite handles top-level await in ES modules natively, so `vite-plugin-top-level-await` is **not needed**. The plugin is only required for bundlers that don't support top-level await in module scope (like older webpack setups).

### ShaderMaterial / onBeforeCompile incompatibility

`ShaderMaterial`, `RawShaderMaterial`, and the `onBeforeCompile()` hook are **not supported** under `WebGPURenderer`. These are WebGL-era patterns for injecting custom GLSL shader code into Three.js materials. WebGPU uses a different shading model — **TSL (Three Shading Language)** — which compiles to WGSL instead of GLSL. If you need custom shading with WebGPU, you'll use TSL or write raw WGSL compute/fragment shaders, not the old GLSL material hacks.

## Code

in repo - `apps/0_vite_webgpu_starter`

```ts
import * as THREE from 'three/webgpu';

const canvasEl: HTMLCanvasElement | null =
  document.querySelector('canvas#tride');

if (!canvasEl) throw new Error('Canvas element is missing!');

const canvas = canvasEl;

const sizes = {
  width: 800,
  height: 600,
};

async function init() {
  // Scene
  const scene = new THREE.Scene();

  // Geometry + Material → Mesh
  const boxGeometry = new THREE.BoxGeometry(1, 1, 1);
  const material = new THREE.MeshBasicMaterial({
    color: 0x4c9892,
  });

  const mesh = new THREE.Mesh(boxGeometry, material);
  scene.add(mesh);

  // Camera
  const camera = new THREE.PerspectiveCamera(
    75,
    sizes.width / sizes.height,
  );
  camera.position.z = 3;
  camera.position.x = 0.5;
  scene.add(camera);

  // Renderer — WebGPU
  const renderer = new THREE.WebGPURenderer({ canvas });
  await renderer.init(); // the important async step

  // Helpers
  const axesHelper = new THREE.AxesHelper(5);
  axesHelper.setColors('red', 'green', 'blue');
  scene.add(axesHelper);

  renderer.setSize(sizes.width, sizes.height);
  renderer.setClearColor(0x000000, 1); // required for WebGPU fallback
  renderer.render(scene, camera);
}

await init();
```

## Gotchas

- **`setClearColor` is mandatory with WebGPU** — `WebGPURenderer`'s WebGL2 fallback doesn't default to an opaque black clear color the way plain `WebGLRenderer` does. If you skip it, you get a transparent or unexpected background.

- **`requestAdapter()` may return `null` on Linux** — Chrome ships a driver/hardware blocklist for WebGPU on Linux. If `navigator.gpu.requestAdapter()` returns null, you need to enable `Force enable WebGPU interop` and `Unsafe WebGPU Support` in `chrome://flags`, then relaunch Chrome. This is a local dev override only — real users won't have these flags set.

- **WebGPU requires a secure context** — the page must be served over `https://` or from `localhost`. A LAN IP like `192.168.x.x` won't work.

- **Privacy/fingerprint extensions** can shim `navigator.gpu` to always return null. Test in Incognito with extensions disabled if adapters aren't showing up.

- **Canvas element assignment quirk** — the `document.querySelector()` returns `Element | null`, which TypeScript doesn't narrow to `HTMLCanvasElement`. The extra assignment (`const canvas = canvasEl`) after the null check is a pragmatic workaround, not the cleanest pattern, but it works for a starter.

```ts
// use this instead in your next examples
// if you are bothered having two canvas constants
function getRequiredElement<T extends Element>(selector: string): T {
	const el = document.querySelector<T>(selector);
	if (!el) throw new Error(`Required element not found: ${selector}`);
	return el;
}

const canvas = getRequiredElement<HTMLCanvasElement>('canvas#tride');
```

## Outdated

approach is valid

WebGPU is the current standard for modern browser graphics. Three.js's `WebGPURenderer` with auto-fallback to WebGL2 is the recommended path forward. The patterns in this starter are up to date.
